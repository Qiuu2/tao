## 二、查出来并修掉的问题

### 2.1 ❗ 8 个删除接口从界面上根本调不通

**症状**：删除按钮点下去没反应，控制台里是 `40001 请求参数格式错误: EOF`。

**根因**：`http.delete(url, params)` 的第二个参数是 **query string**（`axios.delete(url, { params })`），
而后端这些接口读的是 **JSON body**。写成 `http.delete(url, { ids })` 发出去的请求没有 body，
后端 `DecodeJSON` 直接 EOF。

**受影响**：终端分区、节假日、遥控任务、终端功放 / 采播管理 / 文字语音 / led播放
（四类 typed 任务共用一个接口）、LED 设备、启用管理、噪声设备、声场分区。

**修法**：一律改成 `http.delete(url, {}, { data: { ids } })`。
`src/api/modules/basecfg.ts` 里把这条钉成注释。其余 18 个 delete 调用点逐个核过，写法本来就是对的。

> 这类错误不会在编译期暴露、TS 类型也拦不住 —— 两种写法签名完全一样。
> 新增 DELETE 接口时照着 basecfg.ts 那条注释写。

### 2.2 搜索失效与缺搜索

| 页面 | 问题 | 修法 |
|---|---|---|
| 文件管理 | 前端只发 `keyword` 不发 `searchKey`，后端 `switch` 两个 case 都不命中，搜索框毫无作用 | 后端补默认口径（不带 `searchKey` 时按媒体名称）；另新增 `typeid` 一路筛选 |
| 报警映射 | 同型问题 | 后端补默认分支：报警主机名 / 映射分区名 / 映射名一起模糊匹配 |
| 终端分区 | 后端支持 `keyword`，界面上没有搜索框（旧版 streammanager 有「搜索条件 → 分区名称」） | 补搜索框 |
| 报警分区 | 同上 | 补搜索框 |
| 遥控任务 | 同上（旧版 task_mapping 有「搜索条件 → 映射名称」） | 补搜索框 |
| 作息方案 | 同上 | 补搜索框 |

文件管理的搜索旧版是「选择类型…」下拉二选一（媒体名称 / 媒体类型），
新版做成两个并列的搜索框，两路条件可以同时生效 —— 比旧版那个二选一好用，是有意的差异。

### 2.3 列名与列缺失（逐条对旧版模板）

|---|---|---|
| 终端管理 | `TerminalManager/terminalmanager_form.html` 表头第 3 列是「所属分区」 | 补回这一列。早先按参考图拿掉过，理由是左边有分区树；但选「全部终端」时树上看不出每行归属，这一列是唯一出处。不想要可以在列设置里关掉（现在关掉会被记住） |

### 2.4 任务日志目录不存在时整页 500

后台 C 服务是**写第一条日志时**才建 `datelog/` 目录的，刚装好还没跑过任务的机器上它不存在，
列表接口 `stat` 失败直接 500，整个「任务日志」页打不开。

改成：目录不存在当空列表处理，页面上说明目录路径与原因（可能是还没跑过任务，也可能是
`config.yaml` 的 `logs.task_dir` 配错了）；删除、读取这类要求目录真实存在的操作仍然报错。

### 2.5 服务器状态显示成裸的 0

旧版 `servermanager_form.html` 用两张图表示：`workstate=0` → stop.gif（服务器终止）、
`=1` → start.gif（服务器运行）。新版直接把数字摆出来了。改成同义的文字标签，措辞用旧版原文。

### 2.6 列设置不保存（用户要求）

「列设置」抽屉里的「显示 / 排序」两个开关原来只活在内存里，刷新就回默认，
每次登录都要重新关一遍不想看的列。

现在按路由分键存进 localStorage（`htweb:cols:<path>`，见 `web/src/utils/tablePrefs.ts`），
下次进同一页直接套用。只存**与默认不同**的项 —— 后端加列、改列名都不会被一条旧记录带偏；
记录里没有的列按代码默认走，代码里已删的列在套用时忽略。一页多张表时由调用方传 `tableKey` 区分。

> 布局设置（主题 / 布局模式 / 侧边栏 / 页脚…）本来就走 pinia 的 `geeker-global` 落 localStorage，
> 退出登录也不清，这一轮一并验证过：改完设置 → 清 token → 重新登录，设置仍在。

### 2.7 顺带

- 清掉报警分区 / 报警映射里两个未使用的符号（`CirclePlus`、`typeSwitchCount`）。
- 补齐 10 个文件的 prettier 格式漂移。现在 `eslint src` 与 `vue-tsc --noEmit` 全站零告警。

## 三、与 ok112 有意不同的地方

这些不是漏做，是想清楚之后决定不照抄的。

| # | 地方 | 旧版 | 新版 | 为什么 |
|---|---|---|---|---|
| 1 | 作息方案的「备份方案 / 还原方案」 | 页面上两个按钮，点下去其实调 `backup_restore_form.php`，**备份的是整个数据库加媒体文件**，跟「方案」没关系 | 不在作息方案页放这两个按钮 | 新版有独立的「基础配置 → 备份还原」页，做的就是整库 + 媒体的备份包。在作息方案页再放一遍只会让人以为是「只备份这个方案」 |

| 5 | 文件广播的「终端属性」列 | 一列，内容是一个「浏览」链接 | 做成操作列里的「终端(N)」 | 同一个入口，还顺带把数量显示出来了 |

## 六、怎么复跑这一轮测试

脚本都在会话的临时目录里（`scratchpad/audit/`），不入库。要复跑的话按这个顺序：

1. 起 MariaDB 与 htweb，前端 `pnpm build` 后把 `dist` 指给 `server.static_dir`。
2. 全站扫描：逐页 `goto`，收集 `pageerror` / `console.error` / 非 200 的 `/api` 响应。
3. 增删改往返：按 §1.2 的清单在界面上走一遍，每步核对数据库。
4. 收尾：核对 `task` / `media` / `serverplaystream` / `alarmarea` / `holidaytime` /
   `sounddevice` / `soundgroupinfo` / `book_admin` / `shortcutkeytask` / `enabletask`
   里没有 `E2E` 开头的残留。

写测试脚本时的两个坑，值得记下来：

- **别用 `.el-table__row` 全局计数**。删除的影响面对话框关掉之后 DOM 还在，
  它里面的行会被一起数进去，看起来像「删了还在」。要限定到 `.table-box .el-table__row:visible`。
- **对话框里的控件形态各不相同**：遥控任务的「映射任务」是 `el-tree` 不是表格；
  作息方案的「添加方案」没有提交按钮，保存动作是方案任务表**行内**的「添加」
  （与旧版一样：方案是靠一条条加打铃条目建出来的）。
