## 二、查出来并修掉的问题

### 2.1 ❗ 8 个删除接口从界面上根本调不通

**症状**：删除按钮点下去没反应，控制台里是 `40001 请求参数格式错误: EOF`。

**根因**：`http.delete(url, params)` 的第二个参数是 **query string**（`axios.delete(url, { params })`），
而后端这些接口读的是 **JSON body**。写成 `http.delete(url, { ids })` 发出去的请求没有 body，
后端 `DecodeJSON` 直接 EOF。

**受影响**：终端分区、节假日、遥控任务、终端功放 / 采播管理 / 文字语音 / led播放
（四类 typed 任务共用一个接口）、LED 设备、启用管理、噪声设备、声场分区。

**修法**：一律改成 `http.delete(url, {}, { data: { ids } })`。
`src/api/modules/basecfg.ts` 里把这条钉成注释。其余 18 个 delete 调用点逐个核过，写法本来就是对的。

> 这类错误不会在编译期暴露、TS 类型也拦不住 —— 两种写法签名完全一样。
> 新增 DELETE 接口时照着 basecfg.ts 那条注释写。

另外实测发现一个真问题：**「用户登出」记的操作人是 `-`**。中间件是在 handler
返回之后才拿 token 去会话表反查用户名的，而 `handleLogout` 已经把会话作废了 ——

核对脚本很简单，加接口时可以再跑一次：

```python
routes  = re.findall(r'mux\.HandleFunc\("((?:POST|PUT|DELETE) [^"]+)"', main_go)
labeled = set(re.findall(r'"((?:POST|PUT|DELETE) [^"]+)":', audit_mw_go))
missing = [r for r in routes if r not in labeled and r not in self_logged]
```

### 2.10 日志保留期：默认 1 个月，按天滚动

日志原来只能手动清，不清就一直涨。现在：

- **保留期**默认 1 个月，可选 3 个月 / 半年 / 1 年。按**自然月**算
  （减 N 个月，不是减 N×30 天）—— 界面上写「1 个月」，2 月和 8 月不该一样长。
- **界面上是一个下拉加一个「确定」**：选完点确定，设置存下来，超期的当场滚掉。
  切下拉本身不发请求、也不删任何东西，旁边那行「点确定即清掉 X 之前的」
  跟着下拉走 —— 人在按下去之前就看得到自己要删掉哪一天之前的东西。
- **按天滚动**：服务里另有一个每天跑一次的定时任务，把落在保留窗口外的整天清掉。
  稳态下每天掉一天，日志量维持在固定天数上，不会某天突然删掉一大批。
  进程起来一分钟后先跑一次（机器关几天再开机，落下的那几天要补上），之后每 24 小时一次。
- ~~覆盖两边：**操作日志**按 `log.time` 删，**任务日志**按文件名里的日期删~~
  ~~（`logYYYY-MM-DD.html`，目录里别的文件一律不碰）。~~
  ~~**今天的任务日志文件永远不删**（BR-252）。~~
  **已改**：任务日志整块撤销后，滚动清理**只清 `log` 表**。
  界面上看不见的东西不该在后台被悄悄删掉，所以撤页面的同时把删文件那一半也撤了 ——
  `datelog/` 下那些文件归后台 C 服务自己管。
- **删之前先写一行审计**，写明这次滚掉了多少条，并且删除时排除掉刚写的那一行 ——
  否则「日志少了一截」这件事本身没有痕迹。定时任务写的那一行操作人是「系统」，
  点「确定」触发的写的是操作人本人。一次「确定」会留两行：先「修改日志保留期」、
  后「日志滚动清理（保留 X，清掉 Y 之前的 N 条）」。
- 存设置与清理是**同一个动作**（`PUT /api/logs/retention` 一次做完）。
  分成两步会出现「设置存下来了但清理没跑」的中间态，用户看不出来。
  清理失败不回滚设置 —— 设置已经落盘、明天的定时滚动会接着做，
  把设置退回去反而更费解；失败原因原样带回界面。

设置存 `logs.settings_file` 指的 JSON 文件（默认 `<备份目录上级>/logsettings.json`），
不进数据库 —— 零 DDL 红线，且现有空表都可能被 C 服务扫描，塞进去有触发误广播的风险。
读不到、内容坏了、取值不认识，一律退回默认的 1 个月：这一项决定「删多少」，
拿不准就该往「留得更多」的方向退。

接口：`GET /api/logs/retention` 读、`PUT /api/logs/retention` 存并立刻滚一次，
都收紧到超级管理员。改保留期这个动作本身也记审计（「修改日志保留期」）。

**改了什么**

| 页面 | 改动 |
|---|---|
| 文件广播 添加 / 修改 | led字幕 一段保留（LED任务名称 / Led速度 / 字幕内容），删掉下面的「led设备列表」勾选区 |
| 文字语音 添加 / 修改 | 新增一段 led字幕：「led播放」勾选项 + Led速度 + 字幕内容。**不带**设备列表 |

| 用户组 功能权限 | 任务管理组里新增「led播放」一项 |

「LED 设备」本身没有动：led播放 页工具栏上那个登记 LED 屏的弹窗照旧。

**文字语音的 led 是怎么落库的**

后端本来就支持（`typedtask/ledsub.go` 的 `syncLEDSub`），只是界面上一直没有入口。
勾上「led播放」提交后，另建一条 `tasktype=30`、`sec_task_id` 指回本任务的子任务，
除任务类型外整行照抄主任务，终端清单也跟主任务一致 —— 与文件广播那一项同构，
也与现网既有的 70033 / 70035 那一组数据同构。勾掉再保存，服务端把已有子任务删掉。

**⚠ ledoftask 不会被这次改动抹掉**

三张表单不再提交 `devices`，但 `ledoftask`（哪条任务上哪几块屏）是后台服务真正
读的表。子任务与 LED 任务在保存时都是「整条拆掉重建」，如果把「没传」当成
「用户清空了」，改一次任务就会让正在上屏的内容悄悄消失。所以定了这个约定：

    devices 缺省（JSON 里没这个键）  = 保持库里原样
    devices 显式传空数组 []          = 真的清空

界面走前者。实现在 `task/ledsub.go` 与 `typedtask/led.go` 的 `keepLEDBinds()`，
在拆之前把已有绑定读回入参。实测：不带 devices 改一次，绑定行照旧；传 `[]`，清空。

**led 权限用的是哪一列**

`usergroup` 只有 13 列且表结构不动（R1 红线），13 列里唯一没在新版驱动任何功能的
就是 `telephonepriv`（旧版的「电话管理」，新版没有电话广播这一页）。

## 六、怎么复跑这一轮测试

脚本都在会话的临时目录里（`scratchpad/audit/`），不入库。要复跑的话按这个顺序：

1. 起 MariaDB 与 htweb，前端 `pnpm build` 后把 `dist` 指给 `server.static_dir`。
2. 全站扫描：逐页 `goto`，收集 `pageerror` / `console.error` / 非 200 的 `/api` 响应。
3. 增删改往返：按 §1.2 的清单在界面上走一遍，每步核对数据库。
4. 收尾：核对 `task` / `media` / `serverplaystream` / `alarmarea` / `holidaytime` /
   `sounddevice` / `soundgroupinfo` / `book_admin` / `shortcutkeytask` / `enabletask`
   里没有 `E2E` 开头的残留。

写测试脚本时的两个坑，值得记下来：

- **别用 `.el-table__row` 全局计数**。删除的影响面对话框关掉之后 DOM 还在，
  它里面的行会被一起数进去，看起来像「删了还在」。要限定到 `.table-box .el-table__row:visible`。
- **对话框里的控件形态各不相同**：遥控任务的「映射任务」是 `el-tree` 不是表格；
  作息方案的「添加方案」没有提交按钮，保存动作是方案任务表**行内**的「添加」
  （与旧版一样：方案是靠一条条加打铃条目建出来的）。
