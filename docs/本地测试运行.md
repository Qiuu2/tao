# 把新 web 拉到本地跑起来

这份是**本地测试**的步骤，和 `deploy/README.md` 不是一回事：
那份是往真服务器上装（systemd、免密 sudo、Apache 托管），
这份只求在自己机器上把界面点起来、对着数据库看效果。

下面每一步都在一台 Ubuntu 24.04 上从头跑过：拉依赖、建库、导数据、编译后端、
打前端、起服务、登录、翻页面 —— 不是照着记忆写的。

---

## 0. 先说清楚：本地能测什么、不能测什么

新 web 只是「管理界面 + 数据库」这一层。真正让终端出声的是现场那台服务器上的
**后台 C 服务**和一屋子硬件终端，本地没有。所以：

| 能测 | 不能测 |
|---|---|
| 所有页面的增删改查，数据真进真出数据库 | 终端在线/离线状态（库里存的是什么就显示什么） |
| 用户 / 用户组 / 功能权限（含这次新加的 led播放 权限） | 「执行 / 停止 / 暂停」点了不会真的响 —— 通知是一个 UDP 报文，发给不存在的端口，只写日志 |
| 任务、作息方案、LED 字幕的完整往返与级联删除 | 录音、对讲、线路检测这些要终端应答的动作 |
| 列表、搜索、分页、列设置、日志与日志保留期 | 时间设置里的「设置服务器时间」、服务器信息里的「版本设置」（要免密 sudo，本地按钮会置灰） |
| 媒体上传（装了 ffmpeg 的话） | 注册服务（要 `registerserver` 这个命令，本地没有，页面会如实报错而不是假装成功） |

这不是缺陷，是这套系统本来的分工。

⚠ **Windows 上不能直接编译后端**：`internal/dashboard/perf.go` 用了
`syscall.Statfs`（取磁盘占用），这是 Unix 专有的。实测：

    GOOS=linux   ✓        GOOS=darwin  ✓        GOOS=windows  ✗ 编译不过

Windows 用户请用 **WSL2**（Ubuntu 就行），下面的命令在 WSL 里原样可用。

## 1. 装依赖

| 东西 | 版本 | 干嘛的 |
|---|---|---|
| Go | ≥ 1.24（`server/go.mod` 写的就是 1.24） | 编译后端 |
| Node | ≥ 18（模板要求 ≥16.18，实际用 20/22 都行） | 打前端 |
| MariaDB 10.x 或 MySQL 5.6+ | | 数据库 |
| ffmpeg | 可选 | 只有「文件管理 → 上传媒体」要它（要把上传的音频统一转成 128kbps） |

```bash
# Ubuntu / WSL2
sudo apt update
sudo apt install -y golang-go nodejs npm mariadb-server ffmpeg git
sudo npm i -g pnpm      # 前端锁文件是 pnpm 的
# Go 版本低于 1.24 的话去 https://go.dev/dl/ 装官方包，apt 里的常常偏旧
go version
```

macOS：`brew install go node mariadb ffmpeg`。

## 3. 建库

```bash
sudo service mariadb start          # WSL 下用 service，不是 systemctl

# 建库 + 导数据（二选一）
sudo mysql -e "CREATE DATABASE audioserver DEFAULT CHARACTER SET utf8;"
sudo mysql audioserver < audioserver-demo.sql     # 带样例数据（推荐）
# sudo mysql audioserver < audioserver.sql        # 或者：空系统

# 建一个**只有 DML、没有任何 DDL 权限**的账号
sudo mysql -e "
CREATE USER 'htweb'@'127.0.0.1' IDENTIFIED BY '换成你自己的口令';
GRANT SELECT, INSERT, UPDATE, DELETE ON \`audioserver\`.* TO 'htweb'@'127.0.0.1';
FLUSH PRIVILEGES;"
```

⚠ 别图省事用 root 连。「零 DDL」是这套系统能和旧库共存的前提（R1 红线）：
账号本身没有 DDL 权限，等于给「哪天不小心改了表结构」加了最后一道锁。

导完可以核一下：

```bash
sudo mysql audioserver -e "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='audioserver';"
# 应该是 89
```

## 4. 写 config.yaml

在仓库外面找个地方放运行目录（别放进 git 仓库里，配置里有口令）：

```bash
mkdir -p ~/htweb-local/{html,media,datelog,backups}
cd ~/htweb-local
```

`~/htweb-local/config.yaml`：

```yaml
server:
  listen: ":8080"
  static_dir: "/home/你的用户名/htweb-local/html"   # 前端 dist 放这里

database:
  host: "127.0.0.1"
  port: 3306
  user: "htweb"
  pass: "第 3 步设的口令"
  name: "audioserver"
  max_open: 8
  max_idle: 8

media:
  root: "/home/你的用户名/htweb-local/media"
  max_upload_mb: 300
  ffmpeg: "/usr/bin/ffmpeg"

notify:
  host: "127.0.0.1"
  port: 0
  # 本地没有后台 C 服务，关掉就只写日志不发包。
  # 开着也不会出错（UDP 发失败只记一行日志，不影响业务），只是日志吵。
  enabled: false

auth:
  # 随手生成一串：head -c 32 /dev/urandom | base64 | tr -d '=+/'
  secret: "换成一串随机值"
  ttl: 8h
  # 本地测试建议关掉验证码，省得每次登录还要认图
  captcha_enabled: false

backup:
  dir: "/home/你的用户名/htweb-local/backups"
```

`register` 和 `legacy` 两节本地可以整段不写 —— 不写就是「没有这个能力」，
页面会如实说明，不会假装成功。

## 5. 编译并跑起来

```bash
cd ~/tao/server
go build -o ~/htweb-local/htweb ./cmd/htweb

cd ~/tao/web
# 锁文件是 pnpm 的（web/pnpm-lock.yaml），用 pnpm 装才和这边装的版本一致
npm i -g pnpm && pnpm install
pnpm build:pro         # 产物在 web/dist
cp -r dist/* ~/htweb-local/html/

cd ~/htweb-local
./htweb -config config.yaml
```

起来会打印这几行，对上就说明配置生效了：

```
配置生效: db=htweb@127.0.0.1:3306/audioserver (密码长度 N) listen=:8080 static=… media=…
数据库连接成功，首连耗时 1ms
htweb 启动，监听 :8080
```

浏览器开 **http://127.0.0.1:8080**，登录 **admin / 123456**。

（`audioserver-demo.sql` 里另外三个账号：`operator`、`viewer`、`night`，
口令都是 123456，用来试不同用户组的权限差别 —— 比如「只读查看」组看不到 led播放。）

## 6. 要改前端代码的话：开 vite 热更新

上面那种是「打包后交给后端托管」，和线上一致，但改一行要重打一次包。
边改边看用这个：

```bash
cd ~/tao/web
# 把代理指到本地后端。仓库里默认写的是现场那台机器的地址
sed -i 's#http://192.168.2.159:8080#http://127.0.0.1:8080#' .env.development
pnpm dev
```

前端在 **http://127.0.0.1:8848**，`/api` 的请求由 vite 代理转给 8080 的后端。
后端那边照常跑着（static_dir 这时用不上）。

⚠ 改完记得别把 `.env.development` 的这处改动提交上去 —— 那是现场地址。

## 7. 常见问题

**登录报「用户名或密码错误」**
库导错了或者没导。`sudo mysql audioserver -e "SELECT username FROM book_admin;"`
看有没有 admin。口令 123456 的 md5 是 `e10adc3949ba59abbe56e057f20f883e`。

**起不来，说「数据库连接失败」**
先手工连一次：`mysql -h127.0.0.1 -uhtweb -p audioserver`。
连不上多半是账号建成了 `'htweb'@'%'` 而 MariaDB 又优先匹配了别的行，
或者 MariaDB 只监听了 socket 没监听 TCP（看 `/etc/mysql/` 下有没有 `skip-networking`）。

**`bind: address already in use`**
8080 被占了。改 `server.listen`，或者
`ss -lptn 'sport = :8080'` 找出占端口的进程。

**页面白屏 / 404**
`static_dir` 指的目录里要有 `index.html`。第 5 步的 `cp -r dist/*` 别漏。

**「设置服务器时间」「版本设置」按钮是灰的**
正常。这两个功能要一条受限的免密 sudo 规则（`deploy/install-sudoers.sh` 装的），
本地没装就探不通。按产品要求页面上不显示原因，想看原因去接口：
`GET /api/time` 的 `clockBlockReason`、`GET /api/server/version` 的 `reason`。

**日志页只有操作日志，没有「任务日志」标签**
是的，那一页撤掉了。后台 C 服务写在 `datelog/` 下的 `logYYYY-MM-DD.html`
新版一概不读也不删，`logs.task_dir` 这个配置项也没有了 ——
老的 `config.yaml` 里留着不影响启动，多余的键会被忽略。

**首页紧急广播「点了没反应」**
这四个按钮发的是**厂商 SDK 的二进制 UDP 包**（33 字节，`cmdid=194`），
不是 HTTP。UDP 没有回执，所以界面永远只会说「已下发」，不会因为没播出来而报错。
唯一的判据是服务端日志：

```bash
grep sdkudp htweb.log | tail
```

- 有 `sdkudp -> 地址:8885 : 紧急广播 … [报文]` → 包发出去了，问题在接收端
  （那台机器的 8885 上没有后台广播服务在听）
- 有 `sdkudp(已禁用，仅记录)` → `sdk.enabled` 是 false
- 一行都没有 → 请求没到这个接口。**最常见的是打开的其实是 `preview.html`**，
  那是静态预览，没有后端，写操作一律不生效

发到哪台机器**默认跟着浏览器地址栏走**：从 `http://192.168.1.50:8080` 打开，
包就发到 `192.168.1.50:8885`。本地想看到包，先占住端口再点：

```bash
python3 -c "
import socket
s=socket.socket(socket.AF_INET,socket.SOCK_DGRAM); s.bind(('0.0.0.0',8885))
print('listening 8885')
while True:
    d,a=s.recvfrom(2048); print(a,len(d),d.hex(' '))"
```

**上传媒体失败**
没装 ffmpeg，或者 `media.ffmpeg` 路径不对（`which ffmpeg` 看一眼）。

## 7.5 想把 AI 助手也跑起来

助手默认是关的（`config.yaml` 里 `assistant.enabled`）。关着的时候
前端连悬浮球都不出现，别的功能一切照旧 —— **不装模型也能把整站跑起来**。

要试助手就分三步：

### ① 建 6 张表

```bash
sudo mysql audioserver < ~/tao/db/assistant_tables.sql
```

htweb 的运行账号有意不给 DDL，所以要用 root 跑这一句。

### ② 起旁挂的 NLU 服务

```bash
cd ~/tao/nlu
pip install torch transformers rapidfuzz
python3 server.py --model /path/to/joint_rbt3 --port 5013
```

`--model` 指到训练好的 joint_rbt3 权重目录（在原 ai-speaker 那套里）。
torch 大概 2G，装一次就好。

**没有模型也能试**：写个几十行的桩按关键词返回固定意图就够验后端链路了 ——
这一轮开发全程用的就是桩，验的是 Go 这一侧的消歧、鉴权、执行、回话。
桩要实现三个接口：`GET /healthz`、`POST /infer`（返回
`{intent, confidence, slots, tokens, tags}`）、`POST /match`
（名称模糊匹配，直接调 `nlu/matcher.py` 就行）。

### ③ 打开开关

`config.yaml` 里：

```yaml
assistant:
  enabled: true
  nlu_url: "http://127.0.0.1:5013"
  nlu_timeout: 5s
  session_ttl: 30m
  undo_ttl: 10m
  history_limit: 1000
```

重启 htweb，右下角就会出现悬浮球。

### 先试这几句

```
今天有哪些任务                      只读，最安全，先确认链路通不通
查一下A101的状态                    验名称模糊匹配（库里叫「A101教室音箱」）
把A101教室音箱的音量调到 60          验写操作与权限
取消明天早读预备铃                   会先问「这次还是永久」，答「只这一次」
                                     → 去「启用管理」页面看，多了两条计划
停止播放                            没有在播的东西时会追问要停哪条
```

### 试完记得清

助手的测试数据不在 `audioserver-demo.sql` 里（那份快照是助手之前导的）：

```sql
DELETE FROM assistant_message;
DELETE FROM assistant_session;
DELETE FROM assistant_runtime_play;
DELETE FROM assistant_setting;
-- 一次性取消/挪动排下去的启用计划
DELETE FROM enabletask;
-- 立即播放建的临时任务
DELETE FROM mediaoftask   WHERE taskid IN (SELECT taskid FROM task WHERE taskname LIKE '助手即时播放%');
DELETE FROM terminaloftask WHERE taskid IN (SELECT taskid FROM task WHERE taskname LIKE '助手即时播放%');
DELETE FROM task WHERE taskname LIKE '助手即时播放%';
-- 一次性挪动建的影子任务
DELETE FROM mediaoftask   WHERE taskid IN (SELECT taskid FROM task WHERE taskname LIKE '%\_once\_%');
DELETE FROM terminaloftask WHERE taskid IN (SELECT taskid FROM task WHERE taskname LIKE '%\_once\_%');
DELETE FROM task WHERE taskname LIKE '%\_once\_%';
```

要是试过启用/停用方案或者挪动，`task` 的 `projectstate` / `playtime` /
`exemodel` 会被改掉，最省事的做法是直接按第 8 节整库重导。
