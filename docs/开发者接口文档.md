# 开发者接口文档

> 给**第三方系统**看的一份对外文档：教务系统、门禁、消防告警平台想让广播系统
> 播点什么、查点什么，照这份文档调就行。
>
> 内部实现在《开发文档》，那份是给维护这套代码的人看的。两份不要混。

---

## 0. 先打开「接口调用平台」

广播系统界面里有一页 **`开发者接口 → 接口调用平台`**，是这份文档的**可交互版本**：
左边列出全部接口，右边是参数说明，底下能**当场调一次**看真实返回，
还会同步生成等价的 curl 命令。

对接时建议这么用：

1. 在那一页把要用的接口点一遍，试通了再动手写代码 ——
   比读完文档再自己拼请求快得多，也把「是我写错了还是接口坏了」当场分开
2. 点右上角「下载 OpenAPI 文件」，导进 Postman / Apifox / 你们的代码生成器
3. 这份文档留着查细节（默认值、边界、为什么这么设计）

那一页上点「试一试」是**浏览器直接打接口**，不经过任何代理 ——
点出来的结果和你在自己机器上得到的完全一样。

## 0.1 一分钟上手

```bash
# 1. 管理员在界面上「用户管理 → 开发者密钥 → 新建密钥」，把生成的那串抄下来
KEY='hb_B33nnhYf_z4XqeRW63BikhgCAC6nLGPAtqhZLz6x5'

# 2. 查一下有哪些终端
curl -H "X-API-Key: $KEY" 'http://广播服务器:8080/openapi/v1/terminals'

# 3. 现在就把国歌播到操场
curl -X POST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/play' \
     -d '{"media":"中华人民共和国国歌.mp3","zones":["室外操场"],"volume":90}'
```

注意第 3 步：**直接写名字**，不必先查编号。这是这套接口的一个基本约定，见 §3。

## 1. 拿到密钥

密钥由**广播系统的管理员**在界面上发放，不能通过接口自助申请
（能拿密钥去发密钥的话，一次泄露就永远收不回来）。

界面路径：`用户管理 → 开发者密钥 → 新建密钥`。发放时要填三样：

| 填什么 | 说明 |
| --- | --- |
| 名称 | 给人看的备注，比如「教务系统」。出了事靠它认是哪一路调用 |
| 归属账号 | **这把密钥的权限完全等于这个账号的权限** |
| 到期时间 | 留空 = 不过期 |

> ⚠ **明文只出现一次**。服务器里存的是摘要，生成后的弹窗是唯一能看到完整密钥的
> 机会。抄丢了只能删掉重发一把。

### 权限怎么给

不要指望在接口这一侧配权限 —— **这里没有第二套权限系统**。密钥认证通过之后，
后端把它当成归属账号本人在操作：权限位、能看见哪些终端、备机只读，全部照旧生效。

所以「想让第三方能做什么」这个问题，答案永远是：在「用户」页给那个账号配。
建议给第三方**单独建一个账号**，只勾它真正需要的权限位，别直接挂在 admin 上。

各接口需要的权限位：

| 接口 | 需要 |
| --- | --- |
| 全部查询类（GET） | 有效密钥即可（能看见什么由归属账号的可见范围决定） |
| 任务的增删改启停、立即播放 | 任务管理（`taskpriv`） |
| 作息方案的增删启停 | 作息方案（`bellpriv`） |

### 停用与删除

- **停用**：立刻失效，但台账还在，之后仍能查到这把是谁的、谁发的、最后一次什么时候用的。出了事先停用。
- **删除**：连台账一起没。确认这把钥匙彻底不用了再删。

两者都是**即时**的：停用之后下一个请求就是 401，不需要等缓存过期。

## 2. 怎么调

### 机器可读的规格

```
GET /api/openapi/openapi.json      标准 OpenAPI 3.0（要登录，或带 ?token=）
```

界面上「下载 OpenAPI 文件」按钮下的就是它。可以直接导进 Postman / Apifox /
openapi-generator。它和这份文档、和「接口调用平台」那一页同一个来源
（`server/internal/openapi/spec.go`），不会互相对不上。

### 两组接口，先搞清楚用哪一组

| | 常用接口 | 全部功能接口 |
| --- | --- | --- |
| 路径 | `/openapi/v1/...` | `/api/...` |
| 覆盖 | 15 个最常用的动作 | **界面上的每一个页面功能**（213 个） |
| 寻址 | 写名字（也认编号） | 写编号 |
| 参数 | 为集成设计的「人话」 | 界面在用的那一套 |
| 稳定性 | **只增不改**，带版本号 | **跟着界面走**，页面改版时可能变 |
| 参数文档 | 这份文档逐条写了 | 没有逐条写 —— 见下 |

**能用常用接口解决的，优先用它。** 它是一份不会变的合同。

全部功能接口是为「常用接口覆盖不到」的场景准备的：改节假日、配报警映射、
管噪声设备、下发离线数据、看操作日志……这些界面上有、但不属于日常集成的功能。

它们的参数就是界面在用的那一套，这份文档**没有逐条抄** ——
抄了势必抄错、也势必跟不上改动，而一份看起来完整但有错的参数说明，
比明说「这里没有」更坏。要看确切参数，两个办法：

1. 在「接口调用平台」上选中那一条，直接改路径和请求体试
2. 用浏览器开发者工具，在界面上做一次同样的操作，看它发的请求 —— 这是最准的

### 返回里的 0/1 是什么意思

「全部功能接口」那一组返回的是**库里的原始值**。其中有四个字段的取值是
**反直觉的** —— 凭直觉猜必然猜错，而猜错了不会报错，只会让广播在错误的时间、
以错误的顺序、在错误的那一天响：

| 字段 | 取值 | ⚠ |
| --- | --- | --- |
| `projectstate` | **0 = 启用**，1 = 停用 | 0 才是启用 |
| `israndomplay` | **0 = 随机**，1 = 顺序 | 列名里的 random 会让人读反 |
| `priority` | 10~109，**数字小的优先级高** | 10 最高、109 最低 |
| `exemodel` | 7 位 0/1 串，**周日打头** | 第 1 位是周日；`"0000000"` = 手动，永不自动触发 |

其余常用的：

| 字段 | 取值 |
| --- | --- |
| `state`（任务执行状态） | 0 准备 / 1 执行中 / 2 已停止 / 3 立即执行 |
| `timelengthtype` | 1 = `timelength` 是秒数；2 = 是循环次数 |
| `tasktype` | 1 打铃条目 / 2 文件广播 / 7 文件广播(另一取值) / 9 功放子任务 / 15 作息内文件播放 / 30、24 LED 字幕 |
| `netstate` | 1 = 网络在线 |
| `devicestate` | 1 = 已启动、0 = 已停止。⚠ 是运行开关，**不是电源** |
| `taskstate` | 1 = 正在播、0 = 空闲 |
| `holidaytime.projectstate` | ⚠ **和 task 相反**：1 = 启用、0 = 停用 |
| `enabletask.enstate` | 0 = 到点启用、1 = 到点停用 |

「接口调用平台」右上角有「取值对照表」按钮，同样的内容在那里可以随时翻。

**常用接口（`/openapi/v1`）已经替你转好了**：`weekdays` 是 1=周一…7=周日、
`enabled` 是真正的布尔、`seconds` / `loopTimes` 分开给 —— 不必自己解这些编码。

### 哪些接口不开放给密钥

少数几个即使权限够也调不通，会回 `40301`：

| 不开放的 | 为什么 |
| --- | --- |
| 登录 / 登出 / 验证码 | 给人用的。程序有密钥，不需要换会话 |
| 发/停/删开发者密钥 | 拿密钥发密钥的话，一次泄露就永远收不回来 |
| 恢复出厂 / 恢复备份 / 上传备份包 | 会让数据不可逆地消失，必须有人在界面上确认 |
| 重启服务器 / 切换版本 | 会中断正在播的广播 |
| 清空全部离线数据 | 四条无 WHERE 的删除 |
| 服务器注册 / 领试用 | 装机环节，不是集成环节 |
| AI 助手对话 | 给人用的对话框。程序应当直接调接口，不必绕模型 |
| 首页三块配置 | 改的是所有人看到的界面 |

### 地址与认证

```
http://<广播服务器>:8080/openapi/v1/...
```

每个请求都要带这个头：

```
X-API-Key: hb_前缀_密钥正文
```

写请求的 body 是 JSON，记得带 `Content-Type: application/json`。

### 路径里的 `/v1`

这是**版本号**，代表一份不会变的合同：这份文档里描述的字段只增不减、
含义不改。真要做破坏性改动会开 `/v2`，`/v1` 继续能用。

> 顺带一提：这台服务器上还有一套 `/api/...` 的路径，那是**界面自己用的**，
> 字段跟着页面改。别去调它 —— 今天能通，下次升级就未必。

### 返回格式

所有响应都是这个信封，HTTP 状态码恒为 200，**看 `code` 而不是看状态码**：

```json
{ "code": 200, "msg": "ok", "data": { ... } }
```

| code | 含义 | 该怎么办 |
| --- | --- | --- |
| `200` | 成功 | — |
| `40001` | 请求填错了 | `msg` 里写了错在哪，照着改。**重试没用** |
| `401` | 密钥无效 | 密钥错了 / 被停用了 / 过期了 / 被删了。找管理员 |
| `40301` | 权限不够 | 密钥归属账号缺对应权限位，或服务器处于备机只读 |
| `40401` | 找不到对象 | — |
| `50001` | 服务器出错 | 可以重试。反复出现请联系管理员看服务端日志 |

`40001` 的 `msg` 是**写给人看的中文**，可以直接透传给你们自己的运维界面。
比如：

```json
{ "code": 40001, "msg": "找不到叫「教学」的分区。名字相近的有：教学楼", "data": null }
```

`401` 的 `msg` 恒为「密钥无效」，不会告诉你具体是停用了还是过期了 ——
真实原因在广播服务器的日志里，找管理员查。

## 3. 名字优先：一条贯穿全篇的约定

凡是要指认一个**媒体、终端、分区、任务**的地方，写名字或写编号都行：

```json
{ "terminals": ["A101教室音箱", 12] }
```

一个数组里混着两种写法也可以。字符串形式的纯数字（`"12"`）当编号处理 ——
有些语言的 JSON 序列化会把整数写成字符串，这里兼容了。

作息方案**只能写名字**，因为它根本没有编号（见 §6）。

### 三条硬规矩

1. **只精确匹配，绝不猜。** 「A101」对不上「A101教室音箱」，会报错并提示相近的名字。
   这是有意的：你们的程序写死了一个名字，猜错了没有人会看见，
   错误的广播会一直发下去。
2. **重名报错。** 有两个终端都叫「操场音箱」时不会随便挑一个，而是把它们的
   编号列出来让你指定。
3. **一个对不上，整个请求失败。** 「播到 A101、A102、A103」里 A102 拼错了，
   不会只播两个 —— 那样你们以为三个都播了，而漏掉的那个没有任何迹象。

所以：**广播系统里的名字改了，你们那边写死的名字要跟着改**，否则会收到 40001
而不是静悄悄地播错。这一点比「系统帮你猜」要好。

## 4. 查询类

四个接口都只要一把有效密钥。看得见什么由密钥归属账号的可见范围决定 ——
和那个人登录界面看到的完全一致。

### `GET /openapi/v1/terminals` 终端状态

| 参数 | 说明 |
| --- | --- |
| `zone` | 只看某个分区的，名字或编号 |
| `keyword` | 按终端名搜 |
| `pageNum` / `pageSize` | 分页。pageSize 默认 20，最大 200 |

```json
{
  "list": [{
    "id": 2, "name": "A102教室音箱", "type": "一体化音箱", "zone": "教学楼",
    "ip": "192.168.2.12",
    "online": true, "playing": true, "stateText": "播放中",
    "volume": 80, "running": true, "runStateText": "已启动"
  }],
  "total": 12, "pageNum": 1, "pageSize": 20
}
```

`online` 是网络在线，`playing` 是正在播任务 —— 两件事。离线的终端 `playing` 恒为假。
没归到任何分区的终端，`zone` 是 `"(未分区)"`。

⚠ `running` 是终端的**运行开关**（界面上的「启动终端 / 停止终端」），**不是电源**。
断电的终端表现为 `online: false`，不是 `running: false`。

### `GET /openapi/v1/media` 媒体列表

参数：`keyword`（按媒体名搜）、`folderId`、分页。

```json
{ "list": [{ "id": 125, "name": "10.起床号.mp3", "seconds": 89, "sizeKB": 1406, "folderId": 2, "type": "mp3" }],
  "total": 1, "pageNum": 1, "pageSize": 20 }
```

`seconds` 为 0 表示库里没记时长，**不是**「零秒」。

### `GET /openapi/v1/tasks` 任务列表

范围是**文件广播任务**（界面「任务管理」那一页列的东西）。作息方案里的打铃
不在这里，见 §6。

参数：`keyword`、`folderId`、分页。

```json
{
  "list": [{
    "id": 1008, "name": "升旗仪式-国歌", "note": "每周一",
    "enabled": true, "running": true, "stateText": "执行中",
    "startDate": "2026-01-01", "endDate": "2026-12-31",
    "playTime": "07:50:00", "endTime": "07:53:00",
    "weekdays": [7], "priority": 8, "volume": 90,
    "media": [{ "id": 138, "name": "中华人民共和国国歌.mp3" }],
    "terminals": [{ "id": 8, "name": "操场号角01" }]
  }],
  "total": 6, "pageNum": 1, "pageSize": 20
}
```

- `enabled` = 这条任务是启用还是停用（停用的永不触发）
- `running` = 此刻正在播
- `weekdays` = `1`=周一 … `7`=周日。**空数组表示手动任务**，后台永远不会自动触发它
- `note` 是只读的备注，改不了

### `GET /openapi/v1/schedules` 作息方案清单

无参数。

```json
[{ "name": "春季作息", "tasks": 7, "enabled": 7 }]
```

`tasks` 是方案里有几条打铃，`enabled` 是其中处于启用状态的条数。

### `GET /openapi/v1/schedules/{方案名}` 方案详情

方案名要 URL 编码。返回见 §6。

## 5. 任务

### `POST /openapi/v1/tasks` 新建任务

**一次调用带齐媒体、终端、任务信息** —— 对应界面「新建任务」那一屏。

```bash
curl -X POST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/tasks' -d '{
  "name": "课间音乐",
  "media": ["大课间.mp3", "10.起床号.mp3"],
  "terminals": ["A101教室音箱"],
  "zones": ["教学楼"],
  "playTime": "09:50",
  "weekdays": [1,2,3,4,5],
  "seconds": 600,
  "volume": 70
}'
```

```json
{ "id": 70230, "mediaCount": 2, "terminalCount": 5 }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 任务名，最多 45 字 |
| `media` | | 播放清单，**按数组顺序播** |
| `terminals` / `zones` | | 播到哪，取并集去重。分区会展开成终端 —— 见下面的 ⚠ |
| `playTime` | ✅ | 每天几点播。`09:50` 或 `09:50:00` |
| `endTime` | | 不给就按 `playTime + 时长` 自动算 |
| `weekdays` | | `1`=周一…`7`=周日。**留空 = 手动任务**，不是「每天」 |
| `startDate` / `endDate` | | 生效区间。都不给默认「今天起一年」 |
| `seconds` | | 播多久（秒）。与 `loopTimes` 二选一 |
| `loopTimes` | | 把清单循环几遍。与 `seconds` 二选一 |
| `volume` | | 0~100，默认 80 |
| `priority` | | 10~109，**数字小的优先级高**。不给取你能用的最低一档 |
| `prePower` | | 提前多少秒开功放电源 |
| `enabled` | | 建完是启用还是停用，默认启用 |
| `sequential` | | `true` 顺序播（默认）、`false` 随机播 |
| `folder` | | 任务分组，名字或编号。不给落到你看得见的第一个分组 |

几个**必须知道**的默认值：

- **`weekdays` 留空是「手动」**，这条任务永远不会自动响，只能靠 §5.3 的
  `start` 动作触发。想让它每天响就写 `[1,2,3,4,5,6,7]`。
  （默认成「每天」太危险 —— 少写一个字段就变成每天全校广播。）
- **不给 `priority` 时取最低一档**，会被别的广播压住。要它优先就自己填一个小数字。
- **`seconds` 和 `loopTimes` 都不给**时，按媒体自身总时长算；算不出来兜底 60 秒。

> ⚠ **分区是在写入那一刻展开成终端的。** 建完任务之后再往「教学楼」里加一台终端，
> **这条任务不会自动带上它**。加了终端要重新调一次 §5.2 更新任务。
> （广播系统底层存的就是终端清单，不是分区引用。）

### `PUT /openapi/v1/tasks/{名字或编号}` 修改任务

只写要改的字段，**没给的保持原样**：

```bash
curl -X PUT -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/tasks/课间音乐' -d '{"volume": 55}'
```

清单类字段（`media` / `terminals` / `zones`）给了就是**整体替换**：
传 `"media": ["A.mp3"]` 会把原来的清单换成只有 A.mp3，不是追加。
不传则保持原样。

路径里的名字要 URL 编码。

### `POST /openapi/v1/tasks/actions/{动作}` 启停

```bash
curl -X POST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/tasks/actions/stop' \
     -d '{"tasks": ["课间音乐", 1008]}'
```

四个动作，**分成两组，别搞混**：

| 动作 | 是什么 |
| --- | --- |
| `start` | **现在就播**这条任务 |
| `stop` | **现在停**。任务本身没变，明天到点照样会响 |
| `enable` | **启用**这条任务 |
| `disable` | **停用**。从此不再自动触发，直到重新 enable |

中文里 `stop` 和 `disable` 都能叫「停」。想让今天这一次别响是 `stop`，
想让这条任务以后都别响是 `disable`。

回执是**部分成功**的语义：

```json
{
  "succeeded": [{ "id": 1008, "name": "升旗仪式-国歌" }],
  "blocked":   [{ "id": 1010, "name": "课间轻音乐", "reason": "只能操作自己创建的任务" }]
}
```

一次给二十条，因为其中一条不归你就把另外十九条也拒掉是不合理的，
所以能做的做掉、做不了的逐条给原因。**要检查 `blocked` 是不是空的。**

### 删除任务

```bash
# 删一条
curl -X DELETE -H "X-API-Key: $KEY" 'http://广播服务器:8080/openapi/v1/tasks/课间音乐'

# 批量
curl -X DELETE -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/tasks' -d '{"tasks": [1008, "课间音乐"]}'
```

回执与启停同构（`succeeded` / `blocked`）。删除会连带清掉这条任务的媒体清单
与终端清单。

## 6. 作息方案

### 方案是什么

「春季作息」不是一条记录，而是**一批打铃任务共用的一个名字**。所以：

- 方案**没有编号**，名字就是它的身份，寻址只能用名字
- 建一个方案 = 一次性建出它下面的全部打铃条目
- 停用一个方案 = 把它下面所有打铃一起停掉

### `POST /openapi/v1/schedules` 新建方案

```bash
curl -X POST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/schedules' -d '{
  "name": "夏季作息",
  "zones": ["教学楼"],
  "weekdays": [1,2,3,4,5],
  "volume": 75,
  "items": [
    { "name": "早读预备",   "playTime": "07:20", "media": ["10.起床号.mp3"], "seconds": 30 },
    { "name": "第一节下课", "playTime": "09:50", "media": ["04.爱的纪念（下课）.mp3"] }
  ]
}'
```

```json
{ "name": "夏季作息", "itemCount": 2, "taskIds": [70232, 70233], "warnings": [] }
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | ✅ | 方案名 |
| `terminals` / `zones` | ✅ | 打到哪。方案里所有条目共用同一份终端清单 |
| `items` | ✅ | 至少一条 |
| `weekdays` | | **留空 = 周一到周五**（注意与 `/tasks` 不同，见下） |
| `startDate` / `endDate` | | 默认今天起一年 |
| `volume` / `priority` / `prePower` | | 方案级，全部条目共用 |

每个 `item`：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `playTime` | ✅ | 几点打 |
| `media` | ✅ | 播什么 |
| `name` | | 条目名。不给用「07:20 打铃」 |
| `seconds` / `loopTimes` | | 二选一。都不给按媒体自身时长 |

> ⚠ **`weekdays` 留空时，这里默认周一到周五，而 `/tasks` 那边默认「手动」。**
> 不是笔误：作息方案天然是「上课日打铃」，建一个永不触发的方案没有意义；
> 而文件广播任务建来手动触发是常见用法。两边都不要漏填这个字段。

`warnings` 是「建成了，但有件事你该知道」，比如同一时刻排了两条铃。不拦截，但要看。

### `PUT /openapi/v1/schedules/{方案名}/state` 启用 / 停用

```bash
curl -X PUT -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/schedules/夏季作息/state' -d '{"enabled": false}'
```

```json
{ "name": "夏季作息", "affectedTasks": 2 }
```

### `DELETE /openapi/v1/schedules/{方案名}` 删除方案

连同它下面的**全部**打铃条目一起删掉。没有二次确认参数 ——
挡误删的是权限位和「名字必须精确对上」，不是多传一个 `confirmed`。

### `GET /openapi/v1/schedules/{方案名}` 详情

```json
{
  "name": "春季作息", "volume": 66, "priority": 10,
  "terminals": [{ "id": 1, "name": "A101教室音箱" }],
  "items": [{
    "taskId": 1001, "name": "早读预备铃", "playTime": "07:20:00", "enabled": true,
    "seconds": 30, "loopTimes": 0, "weekdays": [1,2,3,4,5],
    "startDate": "2026-01-01", "endDate": "2026-12-31",
    "media": [{ "id": 125, "name": "10.起床号.mp3" }]
  }]
}
```

`seconds` 与 `loopTimes` 只有一个非零：按次数循环的条目没有确定的秒数，
所以 `seconds` 给 0、次数放在 `loopTimes` 上。

## 7. 立即播放

「现在就让操场出声」，不排期。

### `POST /openapi/v1/play`

```bash
curl -X POST -H "X-API-Key: $KEY" -H 'Content-Type: application/json' \
     'http://广播服务器:8080/openapi/v1/play' -d '{
  "media": "中华人民共和国国歌.mp3",
  "zones": ["室外操场"],
  "volume": 90
}'
```

```json
{
  "playId": 1, "taskId": 70231, "media": "中华人民共和国国歌.mp3",
  "terminals": [{ "id": 8, "name": "操场号角01" }, { "id": 9, "name": "操场号角02" }],
  "volume": 90, "seconds": 46, "state": "playing",
  "startTime": "2026-09-08 08:00:52", "endTime": ""
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `media` | ✅ | 播什么。**一个**媒体 |
| `terminals` / `zones` | ✅ | 播到哪，至少给一个 |
| `volume` | | 0~100，默认 80 |
| `seconds` | | 最多播多久。不给按媒体自身时长，还不行兜底 300 秒 |

**把返回的 `playId` 记下来**，停止时要用。

> 立即播放会以**最高优先级**（10）下发，会压住正在播的排期任务。这是有意的 ——
> 它是你此刻主动要求的。请谨慎使用，尤其是在上课时间。

### `POST /openapi/v1/play/{playId}/stop` 停止

```bash
curl -X POST -H "X-API-Key: $KEY" 'http://广播服务器:8080/openapi/v1/play/1/stop'
```

**幂等**：已经停了再调一次不会报错，直接回当前状态。

### `GET /openapi/v1/play` 还在播的

只列还在播的。**建议你们的系统定期调一下**，把自己发起过但没停掉的清理掉 ——
比如程序崩溃重启之后。

## 8. 常见问题

**问：我按名字调，广播系统那边改了名字怎么办？**
你们会收到 `40001` 加一句「找不到叫 X 的终端。名字相近的有：Y」，而不是静悄悄地
播错地方。改名字是个双方要沟通的事，接口这边只保证不猜。想彻底避开的话用编号 ——
但编号在系统重装后会变，各有各的代价。

**问：401 了，是密钥错了还是过期了？**
接口不会告诉你（对着接口试密钥的人不该从错误信息里学到任何东西）。
真实原因在广播服务器日志里，找管理员查。

**问：为什么我建的任务到点不响？**
按顺序查这三条：
1. `weekdays` 是不是空的？空 = 手动任务，永远不会自动响。
2. `enabled` 是不是 false？
3. 今天在不在 `startDate` ~ `endDate` 区间里？

**问：为什么我把终端加进分区了，任务却没播到它？**
分区是在建任务那一刻展开成终端存下来的。加了终端要重新调一次
`PUT /openapi/v1/tasks/{...}` 更新终端清单。见 §5.1 的 ⚠。

**问：一次能操作多少条？**
媒体清单最多 500 条，终端清单最多 3000 条，分页 `pageSize` 最大 200。

**问：接口有没有调用频率限制？**
目前没有。但立即播放会真的让喇叭响，别写循环。

**问：我的调用会被记录吗？**
会。所有写操作都进操作日志（谁、什么时候、做了什么），日志里标着
「开发者接口：」前缀，与人在界面上点的区分开。密钥的最后使用时间与来源 IP
也记在案，管理员在「开发者密钥」页看得到。
