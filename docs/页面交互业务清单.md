## 1. 系统整体框架

### 1.1 框架结构（A）

系统为**经典 frameset 三段式**：

```
index.html
 ├── topFrame   顶部（Logo / 当前用户 / 语言 / 注销）
 ├── menu       左侧导航菜单（可折叠分组）
 └── main       右侧主工作区（所有业务页面在此加载）
```

- 部分业务页面自身**再嵌一层 frameset**（左树 + 右列表），典型是"文件管理"。
- 登录成功后：`topFrame`、`menu` 强制 reload，`main` 跳转到"服务器基本参数"页。

**新版重构建议（仅交互层）**：用单页布局（顶栏 + 左侧菜单 + 右侧内容区）替换 frameset，保持"左树右表"的双栏结构不变，因为该结构是媒体库的核心操作范式。

### 1.2 登录页（A）

**页面**：`login.php`

| 元素 | 类型 | 说明 |
|---|---|---|
| 用户名 | 文本框 | 最大长度 20；超长直接判为非法 |
| 密码 | 密码框 | 最大长度 20 |
| 验证码 | 文本框 + 图片 | 最大长度 10；图片可点击刷新 |
| 登录 | 提交按钮 | — |
| 语言切换 | 下拉/链接 | 中文 / 繁体(big5) / English |

**点击"登录"后的业务行为链**：

1. 校验注册状态 → 未注册则整页跳转到**注册页**，不允许进入系统。
2. 校验验证码。存在一个**万能验证码 `htjy123`**，命中时跳过验证码与密码校验，直接登录（这是历史后门，见缺陷清单）。
3. 校验用户是否存在且**处于启用状态**；停用用户提示"用户不存在"。
4. 校验密码。
5. 登录成功后确定用户身份：
   - 用户组 = 1 → 身份标记为 **administrator（超级管理员）**
   - 用户组 ≠ 1 → 身份标记为 **user（普通用户）**
6. 加载该用户的**功能权限集合**（13 项开关，见 §5.1）与**用户等级 level**，写入会话。
7. 读取服务器运行模式（主/备），写入会话。

**失败反馈方式**：统一跳 `error.php` 页，展示提示语并提供返回链接。
**成功反馈方式**：跳 `success.php` 或直接刷新框架。

> 业务规则：登录失败会被计数（错误 IP/次数记录），历史版本有"连续错 5 次禁用"逻辑，**当前源码中该段被注释停用**。新版是否恢复需产品确认。

### 1.3 会话失效处理（A）

任何业务页加载时都会校验会话：

- 会话为空 → 清 Cookie、销毁会话、**直接中断输出**（页面呈现空白）。
- 会话中语言项为空 → 默认置为"中文"，并**强制 `top.location.reload()`**（整框架刷新）。

> 交互缺陷：会话失效时用户看到的是**空白页**而不是"请重新登录"提示。新版必须改为明确的登录过期提示 + 跳转登录页。

### 1.4 全局反馈组件（A）

| 组件 | 触发 | 表现 |
|---|---|---|
| `success.php` | 任意写操作成功 | 全屏提示"成功"，附返回目标页链接 |
| `error.php` | 任意写操作失败 | 全屏提示失败原因，附返回目标页链接 |
| 原生 `alert` + `history.back()` | 业务规则校验不通过 | 弹窗提示后退回上一页，**表单已填内容丢失** |
| `parent.location.reload(true)` | 文件夹增删改成功 | 直接刷新父框架 |

> 交互缺陷：大量校验失败走 `alert + history.back()`，用户填写的表单内容全部丢失。新版应改为**页内内联错误提示，不跳转、不丢数据**。

## 3. 【重点】文件管理 —— 文件夹树 + 媒体库

### 3.1 页面结构（A）

**入口**：菜单 → 资源管理 → 文件管理 → `filemanager.php`

该页本身只是一个**双栏 frameset**：

```
filemanager.php
 ├── 左栏 mediafolder ← media_folder_tree.php   文件夹树
 └── 右栏 mediafile   ← media_file.php          当前文件夹的媒体列表
```

左树点击任一文件夹节点 → 右栏加载该文件夹的媒体列表（`target="mediafile"`）。

### 3.2 左栏：文件夹树（A）

**渲染规则**：

- 根节点固定显示文本"**文件管理**"（多语言：file manager）。
- 根节点下渲染**顶层媒体库**（父级为根的文件夹）。
- 树**最多展示 3 层**（顶层库 → 二级 → 三级）。**第 4 层及以下文件夹在树上完全不可见**（源码中第 4 层递归被注释掉）。
- 系统预置的 6 个顶层媒体库（业务语义固定，不可删除）：

| 媒体库 | 业务用途 | 共享属性 |
|---|---|---|
| 共享媒体库 | 通用媒体 | 共享 |
| 铃声媒体库 | 打铃/作息方案取铃声 | 共享 |
| 点播媒体库 | 点播 | 共享 |
| 报警媒体库 | 报警联动播放 | 共享 |
| 录音媒体库 | 终端/设备录音归档 | 共享 |
| 语音合成媒体库 | TTS 生成音频 | 共享 |

- 预置子文件夹：`共享媒体库/提示音`、`录音媒体库/设备录音媒体`、`录音媒体库/录音媒体库`。
- **"录音媒体库"节点的可见性受注册状态控制**：未注册（或试用态之外）时，**整个"录音媒体库"分支在树上被跳过不显示**。
- 节点名在**繁体/英文语言环境下做固定词表翻译**（只翻译上述 6 个库名 + "文件管理"），自定义文件夹名不翻译。
- 当前选中节点在页面加载后自动展开高亮。

**交互点**：

| 交互 | 行为 |
|---|---|
| 点击文件夹名 | 右栏加载该文件夹媒体列表；同时把"当前文件夹"记入会话，刷新后仍保持选中 |
| 点击展开/收起图标 | 纯前端展开收起 |

> 树上**没有**右键菜单、没有拖拽移动、没有新建/改名/删除按钮 —— 文件夹的增删改全部在**右栏底部工具条**上（见 3.3）。

### 3.3 右栏：媒体列表（A）

#### 3.3.1 表格列

| 列 | 说明 |
|---|---|
| 选择 | 复选框 + 媒体 ID（有权限时）；无权限时显示行序号 |
| 名称 | 媒体显示名 |
| 大小 | ≥1024 显示为 `x.xx M`，否则显示 `x K` |
| 格式 | 媒体格式（mp3 等） |
| 比特率 | ≥1000000 → Mbps；≥1000 → kbps；否则 bps |
| 播放长度 | 秒数换算为"x 分 y 秒" |
| 试听 / 下载 | 两个操作链接 |

**排序**：列表默认按媒体 ID 倒序；筛选条件里可切换为按"大小"排序（降序）。表头**不可点击排序**。

#### 3.3.2 筛选条件（页面底部搜索条）

| 控件 | 选项 |
|---|---|
| 搜索条件 | 下拉：`媒体名称` / `媒体类型` |
| 关键字 | 文本框（模糊匹配） |
| 排序 | 下拉：`（不排序）` / `媒体大小` |
| 搜索 | 图片按钮（提交） |

**筛选行为规则**：
- 搜索是 **POST 提交，作用范围限定在"当前文件夹"内**，不跨文件夹、不递归子文件夹。
- 选了"排序=媒体大小" → 按大小降序；否则按 ID 降序。
- **搜索结果不保留翻页状态**，翻页链接不带搜索条件 → **翻到第 2 页搜索条件即丢失**（重大缺陷，见缺陷清单）。
- 搜索时会额外排除"TTS 占位记录"（文件名标记为 tts 的记录不在媒体列表中出现）。

> 数据可见范围规则见 §5.2。

#### 3.3.3 底部工具条按钮（共 8 个）

| 按钮 | 前置条件 | 点击后行为 |
|---|---|---|
| **全选** | — | 勾选当前页全部媒体 |
| **取消** | — | 取消当前页全部勾选 |
| **上传媒体** | 必须已选中文件夹（当前文件夹 ID ≠ 0）| ① 未选文件夹 → alert"请选择上传文件夹"<br>② **服务器为备机模式**时 → alert 拒绝，禁止上传<br>③ 通过 → 跳转上传页 `fileadd.php` |
| **删除**（媒体） | — | ① **未勾选任何媒体**：确认框"确认删除全部？"→ 确认后**删除当前文件夹下的所有媒体**（高危默认行为）<br>② 已勾选：确认框"确认删除？"→ 删除所选媒体 |
| **创建文件夹** | 当前文件夹须"允许建子级"（见下） | 允许 → 跳转新建文件夹页；不允许 → alert 提示层级受限 |
| **修改文件夹** | — | 跳转修改文件夹页（改的是**当前选中的文件夹**，不是勾选的媒体） |
| **删除文件夹** | — | 确认框 → 删除**当前选中的文件夹** |
| **设置终端** | **必须且只能勾选 1 条媒体** | 勾选数 ≠ 1 → alert"只能选择一个"；否则在鼠标位置弹出**浮层弹窗**（见 3.3.4） |

**"创建文件夹"的层级限制规则（重要业务规则）**：

页面会判断当前文件夹的父级：**只有当前文件夹的父级属于 {根, 共享, 铃声, 点播, 报警, 录音} 这几个顶层库时，才允许在其下再建子文件夹**；否则弹出提示禁止创建。
即：**业务上限制文件夹树最多 3 层**（顶层库 → 二级 → 三级）。这与左树只渲染 3 层是一致的。

#### 3.3.4 弹窗：设置终端（媒体复制）

- 触发：工具条"设置终端"，且恰好勾选 1 条媒体。
- 形态：跟随鼠标位置的**绝对定位浮层**（非模态，点击页面空白处不自动关闭，需点"取消"）。
- 字段：`媒体ID` 文本框（必填，必须是纯数字）。
- 按钮：**提交** / **取消**。
- 提交校验：
  - 为空 → alert"媒体错误"
  - 非数字 → alert"终端 ID 错误"
  - 通过 → 异步请求执行媒体复制，成功后 alert"成功"并**整页刷新**，弹层关闭。

#### 3.3.5 试听（弹窗页）

- 触发：媒体行"试听"链接。
- 形态：`window.open` 新开小窗（约 300×65），无工具栏/地址栏。
- 行为：
  - 媒体 ID **必须是数字**，否则 alert"格式错误"并中止。
  - 服务器上文件不存在 → 标题显示"媒体文件不存在(ERROR)"，播放器不给源。
  - 存在 → 展示媒体名 + 内嵌播放器直接播放。

#### 3.3.6 下载

- 触发：媒体行"下载"链接。
- 行为：以附件形式下载，**下载文件名 = 媒体显示名 + "." + 格式**（不是服务器上的物理文件名）。
- 文件不存在 → alert"FILE NOT EXISTS" 后 `history.back()`。

#### 3.3.7 "录音媒体库"下的功能锁定（重要业务规则）

当右栏是从**"录音媒体库"节点**进入时（左树传递的库标识 = 录音库），页面加载后会**批量禁用工具条链接**：

- 保留可用：**试听、下载、全选、取消、删除**
- 全部置灰不可点：**上传媒体、创建文件夹、修改文件夹、删除文件夹、设置终端**

> 业务语义：录音媒体是设备自动产生的归档数据，只允许听/下/删，不允许人工上传和改目录结构。**新版必须保留此规则。**

#### 3.3.8 无权限时的整页降级

若当前用户不具备"媒体权限"（且不是超级管理员）：

- 表格首列的复选框**替换为纯序号**（不能选中任何行）。
- 页面上**所有 `<a>` 链接被统一置灰、移除点击事件**（含试听、下载）。

> 即：无权限用户对文件管理页是**完全只读且不可操作**的。

### 3.4 上传媒体页（A）

**入口**：右栏工具条 → 上传媒体 → `fileadd.php?folder_id=<当前文件夹>`

| 元素 | 说明 |
|---|---|
| 选择文件 | 打开系统文件选择器，**支持多选** |
| 待上传列表 | 每个文件一行：文件名 + 大小 + 进度百分比 + `×` 移除按钮 |
| 开始上传 | 触发批量上传 |

**规则**：

- **允许格式：`mp3`、`wav`**（前端过滤器限制）。
- **单文件大小上限：300MB**。
- 上传目标文件夹由页面隐藏字段携带，**上传过程中不可更改**。
- 逐文件显示上传进度百分比。
- 上传后服务端做**统一转码**：
  - 一律转成 **mp3**；
  - 目标为"提示音"文件夹时按 **16000Hz** 转码，其余文件夹按 **44100Hz**；
  - **每个文件末尾自动追加 2 秒静音**（业务约定，防止播放截断）。
- **同名覆盖规则**：同一文件夹下已存在同名媒体 → **覆盖更新原记录**（替换文件、重置大小/时长/采样率/比特率），不新增记录，也不提示用户。
- 上传完成后向广播服务发送"该文件夹媒体已变更"通知。

> 交互缺陷：上传成功/失败**没有明确的结果页反馈**，用户只能看进度条到 100%。新版应给出成功/失败清单。

### 3.5 文件夹管理页（A，菜单已隐藏但页面存在）

**入口**：`filefoldermanager.php`（菜单项被注释，需直接访问）

这是一个**平铺列表**形式的文件夹管理页，与 §3.3 树上的文件夹操作是**两套并行入口**。

#### 3.5.1 表格列

| 列 | 说明 |
|---|---|
| 操作 | 复选框（有权限时）／序号（无权限时） |
| 文件夹名称 | **表头可点击排序**（前端排序） |
| 共享 | **表头可点击排序**；显示"共享"或"不共享" |
| 创建时间 | — |

#### 3.5.2 筛选条件

| 控件 | 选项 |
|---|---|
| 搜索条件 | 下拉：`文件夹名称` |
| 关键字 | 文本框（模糊） |
| 排序 | 下拉：`（不排序）` / `创建时间` |
| 搜索 | 图片按钮（GET 提交） |

> 缺陷：源码中排序分支被后续赋值语句整体覆盖，**"按创建时间排序"实际不生效**，永远按文件夹 ID 升序。见缺陷清单。

#### 3.5.3 底部按钮

| 按钮 | 校验 | 行为 |
|---|---|---|
| 全选 / 取消 | — | 勾选/取消当前页 |
| **创建文件夹** | 无强制校验 | 跳转新建页，**以当前勾选项作为父文件夹**；未勾选则父级为空 |
| **修改文件夹** | 必须**恰好勾选 1 个**：未选 → alert"请选择文件夹"；多选 → alert"只能选择一个" | 跳转修改页 |
| **删除文件夹** | 必须至少勾选 1 个 | 确认框 → 批量删除（支持多选，逗号分隔） |

#### 3.5.4 新建文件夹页

| 字段 | 校验 |
|---|---|
| 文件夹名称 * | 非空；**只允许中文、字母、数字**（正则 `^[0-9a-zA-Z一-龥]+$`，即不允许空格、下划线、连字符、括号等） |
| 是否共享 | **复选框在源码中被注释隐藏** —— 新建时用户无法选择共享属性 |

按钮：**创建** / **重置**。

**提交后规则**：
- 同一父文件夹下**不允许重名** → alert"名称已被使用" + 回退。
- 创建者记为当前登录用户。
- 由于共享复选框被隐藏，实际提交时该字段为空 → **新建文件夹一律为"共享"**（源码逻辑：字段不为空串则置 1，空串置 0，但表单不提交该项时判定分支落到"共享"）。这是一个语义走样点，见缺陷清单。

#### 3.5.5 修改文件夹页

| 字段 | 说明 |
|---|---|
| 文件夹名称 * | 同新建的校验规则；初始值为原名（繁体/英文环境下按词表翻译显示） |
| 是否共享 | **同样被注释隐藏**；隐藏逻辑中原本设计为：顶层文件夹的共享属性**不可修改**（禁用） |

按钮：**修改** / **重置**。

**提交后规则**：
- 重名校验范围：**同一父文件夹 + 同一创建者**下不得重名。
- 更新文件夹名与共享属性。
- 成功后刷新父框架。

> 缺陷：由于共享复选框隐藏，修改提交时共享属性取默认值 **1（共享）** → **任何一次改名都会把"不共享"的文件夹静默改成"共享"**。这是权限泄露级缺陷，见缺陷清单。

### 3.6 删除的业务规则（A · 最关键的一组规则）

#### 3.6.1 删除媒体（勾选删除）

按顺序校验，任一不通过即 alert + 回退：

1. 媒体被**终端快捷键**引用 → 拒绝："正在使用，不能删除"
2. 媒体被**任务**引用 → 拒绝，提示中带媒体名
3. 媒体被**报警映射**引用 → 拒绝，提示中带媒体名
4. 媒体所在文件夹是**系统预置库（1~9 号）**且当前用户**不是超级管理员** → 拒绝："权限不足"
5. 通过后：只删除**未被任何任务引用**的媒体，物理文件一并删除
6. 删除后向广播服务发送"文件夹媒体变更"通知

> **保护规则：ID 为 1 的媒体（系统内置提示音）物理文件永不删除。**

#### 3.6.2 删除媒体（未勾选 → 删全部）

- 直接按"当前文件夹"批量删除其下所有媒体。
- **注意：此路径不做"是否被任务/快捷键/报警引用"的校验**，也不校验系统库权限 —— 与勾选删除的规则**严重不一致**，是重大缺陷（见缺陷清单）。

#### 3.6.3 删除文件夹

1. **系统预置文件夹 1~9 一律禁止删除** → alert"不能删除系统文件"
2. 逐个检查所选文件夹：文件夹内是否存在**被任务引用的媒体**
   - 全部文件夹都含被引用媒体 → 提示"所选文件夹全部失败"，中止
   - 部分含 → 剔除这些文件夹，只删剩下的，并提示"包含正在使用的文件夹，已跳过"
3. 对可删文件夹：
   - 删除其下媒体（含物理文件）及媒体的快捷键/报警/摄像机报警关联
   - 删除文件夹本身
   - **删除其直接子文件夹及子文件夹下的媒体**
4. 通知广播服务

> **层级缺陷：删除只递归了 1 层子级。**三层树中，被删顶层文件夹的"孙级"文件夹及其媒体会**变成孤儿数据**永久残留。见缺陷清单。

## 5. 全局业务规则

### 5.1 功能权限（13 项开关 + 级别）

用户所属"用户组"上挂 13 个独立的功能权限开关，逐项控制页面的**可写能力**：

| 权限项 | 控制范围 |
|---|---|
| 文件广播权限 | 文件广播任务 |
| 终端权限 | 终端管理 |
| **媒体上传权限** | **文件管理页的所有写操作** |
| 用户权限 | 用户管理 |
| 服务器权限 | 服务器参数 |
| **目录权限** | **文件夹管理页的所有写操作** |
| 分区权限 | 终端分区 |
| 报警权限 | 报警映射/分区 |
| 方案权限 | 作息方案 |
| 采播权限 | 采播管理 |
| 电话采播权限 | 电话广播 |
| 电源权限 | 电源控制 |
| 文字语音权限 | TTS |

外加 **用户组级别 level**（最大 5，系统组为 10），用于任务优先级等场景。

**统一降级表现**：无权限 → 复选框变序号 + 所有链接置灰不可点（见 §3.3.8）。

**重要规则：服务器处于"备机模式"时，所有功能权限一律判定为无权限**（备机只读）。

### 5.2 数据可见范围规则（媒体与文件夹）

这是本系统**最容易出错、也最必须原样保留**的一组规则：

| 场景 | 可见范围规则 |
|---|---|
| 文件管理·媒体列表 | 用户名为 `admin` → 看到当前文件夹下**全部媒体**；其他用户 → **只看到自己上传的媒体** |
| 文件夹管理·列表 | 超级管理员组 → 看到**全部文件夹**；其他用户 → 只看到**自己创建的文件夹**（外加一条恒不成立的兜底条件） |
| 任务中的媒体选择树 | `admin` → 顶层库下全部子文件夹；其他用户 → 顶层库下**只显示自己创建的子文件夹**；顶层库本身按"**共享**或**自己创建**"两个条件取并集显示 |
| 媒体选择树的隐藏项 | **"语音合成媒体库"在任务媒体选择树中始终不显示**；TTS 类型的媒体记录在所有媒体列表中都被排除 |

**共享标记的业务语义**：
- 文件夹带"共享"标记 → **所有用户可见**
- 文件夹不带"共享"标记 → **仅创建者可见**
- 6 个系统预置顶层库全部是"共享"

> ⚠️ **重要不一致（必须在新版统一）**：文件夹管理页判断"是不是我的文件夹"时，比对的是**用户组编号**；而其它页面比对的是**用户编号**。两者语义不同，导致同一个用户在两个页面看到的文件夹集合不一致。新版应统一为"按用户编号判定归属"，并保留"共享则全员可见"的语义。

### 5.3 系统预置数据保护规则

| 对象 | 保护规则 |
|---|---|
| 文件夹 1~9（6 个顶层库 + 3 个预置子目录） | **禁止删除**（任何角色） |
| 文件夹 1~9 内的媒体 | **仅超级管理员可删除** |
| 媒体 ID = 1（内置提示音） | 物理文件**永不删除** |
| 用户 `admin` | 可改不可删 |
| 用户组 1（系统组） | 系统保留 |

### 5.4 媒体引用保护规则

媒体被以下任一对象引用时，**禁止删除**：

1. 任务媒体清单
2. 终端快捷键
3. 报警通道映射

（摄像机报警关联在删除时是**级联清理**，不阻断删除。）

### 5.5 分页规则

- 全站统一**每页 18 条**。
- 分页条形态：`上一页 / 页码（当前页左右各 3 页）/ ... / 末页 / 下一页`。
- **已知缺陷**：分页条头部的"共 N 页"是用**总条数 ÷ 18 硬编码**算出来的，与实际每页条数解耦；同时**翻页链接不携带搜索条件**，翻页即丢筛选。新版必须修正（见缺陷清单）。

### 5.6 多语言规则

- 支持 **中文 / 繁体(big5) / English** 三种。
- 界面文案走语言包。
- **数据内容（媒体库名称）走硬编码词表翻译**，只覆盖 6 个系统库名 + "文件管理"，自定义名称不翻译。
- 语言存于会话，切换后整框架刷新。

### 5.7 广播服务联动规则

以下操作完成后，Web 端会**主动通知后台广播服务**（让其重新加载媒体/任务）：

| 操作 | 通知内容 |
|---|---|
| 上传媒体 | 该文件夹媒体已新增 |
| 删除媒体 | 相关文件夹媒体已变更 |
| 删除文件夹 | 相关文件夹 + 点播库媒体已变更 |

> 新版必须保留此联动，否则后台服务的媒体缓存不会刷新，**播放的仍是旧清单**。

## 6. 交互缺陷汇总（供新版改进，均为交互层，不涉及库结构）

| # | 缺陷 | 影响 | 新版改进方向 |
|---|---|---|---|
| 1 | 删除媒体时**未勾选 = 删全部** | 误操作即清空整个文件夹 | 未勾选时按钮置灰；"清空文件夹"作为独立的二次确认操作，需输入文件夹名确认 |
| 2 | "删全部"路径**不校验引用与权限** | 正在被任务使用的媒体被删，任务播放失败 | 两条删除路径统一走同一套校验 |
| 3 | 翻页丢失搜索条件 | 搜索结果只能看第一页 | 分页链接携带全部筛选参数；筛选改为 GET |
| 4 | "共 N 页"计算硬编码 | 页数显示与实际不符 | 用实际每页条数计算 |
| 5 | 文件夹管理页排序下拉不生效 | 用户以为排序了其实没有 | 修正排序分支 |
| 6 | 共享复选框被注释隐藏 | 新建强制共享；**改名会把不共享改成共享** | 恢复共享开关；顶层库的共享属性保持只读 |
| 7 | 删除文件夹只递归 1 层 | 三层树删顶层会残留孤儿数据 | 改为完整递归删除整棵子树 |
| 8 | 树只渲染 3 层 | 第 4 层文件夹"存在但看不见" | 树改为按层懒加载，完整展示所有层级 |
| 9 | 校验失败 `alert + 后退` | 表单填写内容全丢 | 页内内联校验提示 |
| 10 | 会话失效返回空白页 | 用户不知发生了什么 | 明确的登录过期提示 + 跳登录 |
| 11 | 文件夹名只允许中文/字母/数字 | 空格、括号、连字符都被拒 | 放宽为"禁止特殊控制字符与路径分隔符"，长度受原字段容量约束 |
| 12 | 文件夹归属判定用"用户组"vs"用户"不一致 | 同一用户两页看到的文件夹不同 | 统一按用户编号判定 |
| 13 | 上传无结果反馈 | 不知哪些成功哪些失败 | 上传结果清单（成功/失败/覆盖） |
| 14 | 同名上传静默覆盖 | 误覆盖已有媒体 | 覆盖前二次确认，或提供"另存为副本" |
| 15 | 存在万能验证码 `htjy123` | 可绕过验证码与密码校验 | **新版必须移除** |
| 16 | 两套文件夹入口（树上 + 管理页）规则不一致 | 用户行为不可预期 | 合并为一套文件夹管理交互 |

## 7. 新版页面交互设计要点（结论）

1. **保留"左树右表"范式** —— 这是用户已形成的肌肉记忆，也是媒体库的最佳结构。
2. **文件夹树改为懒加载 + 完整层级**，节点上提供右键菜单（新建子文件夹 / 重命名 / 共享设置 / 删除），取消"底部工具条改的是当前文件夹"这种反直觉设计。
3. **删除操作全部改为显式**：不勾选不能删；清空文件夹作为独立高危操作。
4. **筛选与分页状态进 URL**，可分享、可后退、翻页不丢条件。
5. **权限降级从"置灰所有链接"改为"按钮级隐藏/禁用 + 明确的无权限提示"**，只读用户仍应能试听和下载。
6. **保留全部原有业务规则**：3 层文件夹限制（若产品确认放开需另行评审）、系统库保护、录音库功能锁定、媒体引用保护、共享可见性、备机只读、广播服务联动。
7. **上传保留原有转码约定**（统一 mp3、提示音 16k / 其余 44.1k、尾部补 2 秒静音），否则后台播放行为会变化。
