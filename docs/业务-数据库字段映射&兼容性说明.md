# 业务 ‑ 数据库字段映射 & 兼容性说明

> # ⛔ 硬性约束（本文件的第一原则）
>
> **数据库 `audioserver.sql` 的表、字段、字段类型、索引、注释完全锁定。**
> **禁止 `CREATE TABLE` / `ALTER TABLE` / `DROP TABLE` / `CREATE INDEX` / `ADD COLUMN` / 修改字段类型 / 建视图 / 建触发器 / 建外键。**
> 新版程序读写数据库必须与旧存储**完全兼容**，新旧系统可共用同一套库同时在线。
> 旧代码的业务缺陷**只能在应用代码层修复**（改 SQL 写法、改事务、改递归实现、改校验顺序），不得改动 schema。
>
> 本文档末尾附有**字段依赖自检表**（§6），确认所有业务实现只依赖 `audioserver.sql` 中真实存在的字段。

## 1. 数据库总览

| 项 | 值 |
|---|---|
| 库名 | `audioserver` |
| 建表语句数 | **90 条 `CREATE TABLE`**（其中 `terminaltypekey` 被定义两次，后者覆盖前者） |
| 实际表数 | **89 张** |
| 引擎 | 全部 InnoDB |
| 字符集 | 绝大多数 `utf8`；`TKdeviceinfo`、`TKstationinfo`、`enabletask` 为 `latin1`；`book_msg.title/content/ip`、`terminal.postion` 为 `gbk` |

### 1.1 字符集陷阱（必读）

| 对象 | 字符集 | 兼容要求 |
|---|---|---|
| `TKdeviceinfo`、`TKstationinfo`、`enabletask` | **latin1** | 新版写入这三张表时，中文必须按旧程序的**同一字节序列**写入，否则旧程序读出乱码。**本期建议不写这三张表**（属旧铁路/使能扩展模块，不在重构范围） |
| `book_msg.title` / `content` / `ip` | **gbk** | 留言板模块，不在重构范围 |
| `terminal.postion` | **gbk** | ⚠️ **在范围内**。终端"位置"字段是 gbk。新版读写该字段必须做 utf8 ↔ gbk 转换，否则旧客户端显示乱码 |
| 其余 | utf8 | 连接统一 `SET NAMES utf8`（与旧程序一致，**不要改成 utf8mb4**，否则四字节字符写入会因列为 utf8 而截断/报错） |

> **兼容红线**：连接字符集必须保持 `utf8`，与旧程序 `mysqli_query($con,"set names utf8")` 完全一致。

## 2. 核心业务域数据字典（逐字段标注）

### 2.1 `filefolder` —— 媒体文件夹（树形）★核心

| 字段 | 类型 | 默认 | 业务含义 | 新版读 | 新版写 |
|---|---|---|---|---|---|
| `id` | int(10) unsigned AI | — | 文件夹 ID，树节点唯一标识 | ✅ | 自增，不显式写 |
| `name` | varchar(255) NOT NULL | `''` | 文件夹名称。原注释写的是"文件名称"，实际语义是**文件夹名** | ✅ | ✅ 新建/改名 |
| `userid` | int(10) NOT NULL | — | **创建者的用户 ID**（对应 `book_admin.id`）。是"归属"判定依据 | ✅ | ✅ 新建时写入当前登录用户 ID |
| `priority` | int(10) NOT NULL | `0` | **共享标记**：`0`=不共享（仅创建者可见），`1`=共享（全员可见）。注意：此列名叫 priority 但**与优先级无关** | ✅ | ✅ 新建/修改共享属性 |
| `createtime` | timestamp NULL | `current_timestamp()` | 创建时间 | ✅ 列表展示 | ❌ 依赖默认值，**不显式写** |
| `parentid` | int(10) NOT NULL | `0` | **父目录 ID**；`0` 表示顶层。树的唯一结构依据 | ✅ | ✅ 新建时写入父 ID |

**主键**：`PRIMARY KEY (id, parentid)` —— 复合主键。
> ⚠️ **重要兼容点**：主键是 `(id, parentid)` 而非单列 `id`。这意味着**同一个 `id` 理论上可以配不同 `parentid` 存在多行**。旧程序在 `WHERE filefolder.id = X` 时假定唯一。
> **新版处理方式（不改 schema）**：所有按 id 的单条读取加 `LIMIT 1`；改名/改共享的 `UPDATE ... WHERE id = ?` 保持与旧程序一致的行为；不依赖"id 唯一"做任何缓存键假设。移动文件夹（改 `parentid`）**本期不提供**，因为它会改动主键组成部分，属高风险操作。

**系统预置数据（禁止删除，ID 固定）**：

| id | name | userid | priority | parentid | 业务角色 |
|---|---|---|---|---|---|
| 1 | 共享媒体库 | 1 | 1 | 0 | 顶层库 |
| 2 | 铃声媒体库 | 1 | 1 | 0 | 顶层库·作息方案取铃声 |
| 3 | 点播媒体库 | 1 | 1 | 0 | 顶层库 |
| 4 | 报警媒体库 | 1 | 1 | 0 | 顶层库·报警联动 |
| 5 | 录音媒体库 | 1 | 1 | 0 | 顶层库·受注册状态控制可见性 |
| 6 | 语音合成媒体库 | 1 | 1 | 0 | 顶层库·**在任务媒体选择树中始终隐藏** |
| 7 | 设备录音媒体 | 1 | 0 | 5 | 录音库子目录 |
| 8 | 录音媒体库 | 1 | 0 | 5 | 录音库子目录 |
| 9 | 提示音 | 1 | 0 | 1 | 共享库子目录·**上传时按 16000Hz 转码** |

| `userid` | int(4) | `0` | **上传者用户 ID**（对应 `book_admin.id`）。媒体可见范围判定依据 | ✅ | ✅ 上传时写当前登录用户 ID |

**主键**：`PRIMARY KEY (id)`。**无 `(name, folderid)` 唯一索引**（这是上传竞态问题的根因，只能用应用级锁解决，见 §4.4）。

**保护规则**：`media.id = 1` 是系统内置提示音，**物理文件永不删除**。

**与旧版的两处差异**（都在新 web 这一侧，代码里有注释）：

   节假日决定放假那天打不打铃，与作息方案是一件事的两面。
2. 服务器信息页在旧版没有任何权限校验（`servermanager.php` / `serversetting.php` 谁都能进），
   新 web 归到 `serverpriv` 之下。

> 所有列名均为 `audioserver.sql` 中真实存在的列。

### 4.2 文件夹树查询（★核心，含缺陷修复）

| 项 | 内容 |
|---|---|
| 读 | `filefolder`: `id, name, userid, priority, parentid, createtime` |
| WHERE（admin） | 无过滤，全量取回后内存构树 |
| WHERE（普通用户） | `priority = 1 OR userid = :currentUserId` |
| 附加规则 | `registerflag NOT IN (1,2)` 时，**在应用层裁剪掉 id=5（录音媒体库）整棵子树**；任务媒体选择树中**恒排除 id=6（TTS 库）** |

### 4.3 媒体列表（★核心）

| 项 | 内容 |
|---|---|
| 读 | `media`: `id, name, size, typeid, filename, bitrate, timelength, folderid, userid` |
| WHERE（基础） | `media.folderid = :folderId` |
| WHERE（TTS 过滤） | `AND media.typeid <> 'tts' AND media.filename <> 'tts'`（**统一口径，修复 D-24/D-25**） |
| WHERE（可见范围） | admin：不加条件；普通用户：`AND media.userid = :currentUserId`。✅ **已定稿：即使媒体位于共享目录内，普通用户也只显示自己上传的媒体**。共享目录（`filefolder.priority=1`）只影响**目录本身**可见，不影响目录内媒体的可见范围 |
| WHERE（筛选） | `searchkey='name'` → `AND media.name LIKE :kw`；`searchkey='typeid'` → `AND media.typeid LIKE :kw`（`%_\` 转义后绑定） |
| ORDER BY | 白名单：`orderby='size'` → `media.size DESC`；默认 `media.id DESC` |
| 分页 | `COUNT(*)` 同条件 + `LIMIT :size OFFSET :offset`（**修复 D-12 双查、D-14 边界**） |
| 目录容量 | `SELECT COALESCE(SUM(size),0) FROM media WHERE folderid = :folderId`（**修复 D-23**） |
| 建子目录判定 | `SELECT parentid FROM filefolder WHERE id = :folderId LIMIT 1`，`parentid ∈ {0,1,2,3,4,5}` 则允许 |
| 写 | 无 |
| **schema 影响** | **无。** |

### 4.4 上传媒体（★核心）

| 项 | 内容 |
|---|---|
| 读（查重） | `SELECT id FROM media WHERE name = :name AND folderid = :folderId LIMIT 1` |
| 写（新增） | `INSERT INTO media (name, size, typeid, priority, filename, folderid, timelength, channel, sample, bitrate, userid) VALUES (:name, :sizeKB, 'mp3', 0, :path, :folderId, 0, 0, 0, 0, :userId)` |
| 写（覆盖同名） | `UPDATE media SET size = :sizeKB, timelength = 0, sample = 0, bitrate = 0, filename = :path WHERE id = :id` |
| 关联 | `media.folderid → filefolder.id` |

### 5.2 写入契约（新版写入必须满足，否则旧程序或后台服务读不对）

| # | 契约 | 说明 |
|---|---|---|
| C-01 | 连接字符集固定 `SET NAMES utf8` | 不得改 utf8mb4 |
| C-02 | `book_admin.userpwd` 写入 **32 位小写 MD5** | 否则旧 Web 无法登录 |

| C-04 | `media.typeid` 上传后固定写 `'mp3'` | 后台按此判定解码器 |
| C-05 | `media.filename` 固定格式 `/backup/mediadata/<数字>.mp3` | 后台按此前缀定位物理文件 |
| C-06 | `media.timelength/channel/sample/bitrate` 上传时写 **0** | 由后台 C 服务扫描回填。**新版不要自行用 ffprobe 填值**——若填了与后台算法不同的值，旧程序的播放时长判定会与后台不一致 |

### 5.3 后台服务联动契约（必须实现，否则播放的是旧清单）

| 触发时机 | 发送内容 | 目标 |
|---|---|---|
| 上传媒体成功后 | `file?state=1&id=<folderid>` | `serverip`（默认主机名 `audioserver`） |
| 删除媒体成功后 | 对每个受影响 `folderid` 发 `file?state=0&id=<folderid>` | 同上 |
| 删除文件夹成功后 | `file?state=0&id=<folderids>` + `file?state=0&id=3` | 同上 |

> 端口配置来自 `inc/socket_conf.php`；新版必须沿用同一协议格式（纯文本 `type?state=X&id=Y`）。

### 5.4 并发共存风险与应对

| 风险 | 场景 | 应对（应用层） |
|---|---|---|
| **表锁冲突** | 旧 Web 执行 `LOCK TABLES media WRITE` 期间，新版所有 media 读写被阻塞 | 新版查询设置合理超时并重试；把长事务拆短；**新版自身绝不使用 `LOCK TABLES`** |
| **上传同名竞态** | 新旧 Web 同时上传同名文件到同一文件夹 → 产生两条同名记录 | `GET_LOCK('media_upload_<folderid>')`。**注意：旧程序不参与这把锁**，因此仍需在读取端容忍同名多条（按 `id` 取最新一条） |
| **删除竞态** | 新版正在删文件夹，旧 Web 同时往里上传 | 删除事务内对目标 `filefolder` 行 `SELECT ... FOR UPDATE`；删除后再次校验并清理残留 |
| **自增 ID 争用** | 两端同时 INSERT | 由 MySQL 自增保证，无需处理。**前提是新版不手工指定 id** |
| **孤儿数据** | 旧 Web 删文件夹只递归 1 层，留下孤儿目录/媒体 | 新版读取端必须容忍：文件夹树构建时**把 parentid 指向不存在节点的文件夹挂到"游离节点"分组下展示**，而不是丢弃 |
| **会话不互通** | 新旧 Web 各自维护 session | 两端可同时登录，属预期行为。`book_admin.usersessionid` 会被互相覆盖 —— **新版建议不依赖该列做互踢**，避免踢掉旧 Web 的会话 |
