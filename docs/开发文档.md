# 1. 系统是什么

## 1.1 定位

**IP 数字网络广播系统**的管理后台。一所学校 / 一个园区里挂着几十上百台
网络广播终端（音柱、功放、LED 屏、话筒），这套 web 负责**配置和调度**它们：
建任务、排作息、传媒体、分权限、看日志。

## 1.2 三层分工（必须先搞清楚）

```
   ┌────────────┐   HTTP/JSON    ┌─────────────┐   直接读写    ┌──────────┐
   │  新版 Web  │ ─────────────▶ │   htweb     │ ───────────▶ │ MariaDB  │
   │ (Vue3 SPA) │ ◀───────────── │  (Go 后端)  │ ◀─────────── │audioserver│
   └────────────┘                └──────┬──────┘              └────┬─────┘
                                        │ UDP 报文                 │ 轮询
                                        ▼                          │
                                 ┌─────────────┐ ◀────────────────┘
                                 │ 后台 C 服务  │
                                 └──────┬──────┘
                                        │ 私有协议
                                        ▼
                                 ┌─────────────┐
                                 │  硬件终端    │ 音柱 / 功放 / LED / 话筒
                                 └─────────────┘
```

- **htweb 只管数据库**。建一条任务 = 往 `task` 等表写几行，**不直接指挥终端**。
- **后台 C 服务**是真正的执行者：它读数据库、按时间表推流、跟终端讲私有协议。
- htweb 改完库之后，往 C 服务发一个 **UDP 报文**告诉它「有东西变了」（见第 9 章）。
  发失败只记日志，**不回滚业务** —— 库已经改完了，回滚更糟。
- 所以：**本地没有 C 服务和终端时，界面全都能点，但不会真的响。**

## 1.3 与旧系统 ok112 的关系

`ok112/` 是上一代 PHP 系统（Apache + PHP + 同一个 `audioserver` 库）。

- 它是**唯一的业务事实来源** —— 需求文档不存在，业务规则全在它的 PHP 和模板里。
- 新版**逐页对着它重写**，行为一比一对齐，缺陷则修掉（缺陷编号 D-xx 见缺陷清单）。
- **代码一行都不抄**，只作对照。
- 两套系统**共用同一个数据库**，同时在线。这就是下一章那条最重要的红线的由来。

# 2. 不可逾越的约束（红线）

违反其中任何一条，都会在现网出事，而且大概率是「几百个喇叭在不该响的时候响」这种事故。

## R1 · 不动旧表；新表可以建

> **2026-09-08 调整**：原来是「零 DDL，一张表都不许建」。为了给 AI 助手的状态
> 找地方放，用户放开了「建新表」。**改旧表仍然一律禁止。**

```
✅ 可以新建表（表名加前缀，与旧库那 89 张零冲突）
❌ 现有 89 张表一个字节都不动：不加列、不改类型、不加索引、不改字符集
```

不许改旧表的原因（三条里任何一条单独成立）：

1. 旧系统 ok112 还在跑，同一个库。加一列，旧版的 `SELECT *` + 按下标取值的老代码就会错位。
2. 后台 C 服务是编译好的二进制，按固定列序读数据。表结构一动，它的行为无法预测。
3. 数据库账号本身就**没有 DDL 权限**（只给 SELECT/INSERT/UPDATE/DELETE），这是最后一道锁。
   建新表要用另一个有 DDL 权限的账号手工跑一次建表脚本 —— **程序自己永远不建表**。

**推论一**：零碎的界面状态仍然不进数据库，照旧走本地 / 文件：

- 表格列设置 → 浏览器 `localStorage`（`web/src/utils/tablePrefs.ts`）
- 日志保留期 → 服务端 JSON 文件（`config.logs.settings_file`）
- 看板三块配置 → 服务端 `dashboard.json`

**推论二**：成规模、要查询、要并发安全的状态才值得建新表。
目前只有 AI 助手那 6 张（`assistant_*`，见 `db/assistant_tables.sql`
与《数据库文档》第 8 章）。

**推论三**：⚠ 每加一张新表，**有两处必须同步改**，否则会静默坏掉：

1. `internal/serverparam/factory.go` 的三张清单之一 ——
   恢复出厂遇到不认识的表会**拒绝执行**（这是有意的保险，不是 bug）。
2. 备份包的结构指纹会变。当前库比备份包**多**出来的表不再拦
   （只提示，恢复时不动它们）；备份包里有、而库里没有的，照旧拦死。

## R2 · 列名不等于列义

`usergroup` 那 13 个权限列，列名和真实含义**对不上**，是旧版留下的。
按字面意思理解会把现网所有用户组的权限悄悄挪位。完整对照见附录 B 和《数据库文档》。
最容易踩的四个：

| 列 | 字面像什么 | 实际是 |
|---|---|---|
| `serverpriv` | 服务器权限 | **遥控管理** |
| `admpriv` | 系统维护 | **采播管理** |
| `powerplay` | 强插播放 | **终端功放** |
| `telephonepriv` | 电话广播 | **led播放**（新版改挂的，见 7.4.6） |

## R3 · 反直觉的取值必须原样保留

| 地方 | 反直觉在哪 |
|---|---|
| `task.projectstate` | **0 = 启用，1 = 停用**（数据库列注释是反的） |
| `usergroup.level` | 是**两位复合值** 10~109：十位 = 组级别，个位 = 任务优先级基数。C 服务按此解析 |
| `task.tasktype` | 列注释「1-作息 2-文件 3-采播 4-电话 5-功放」不全，实际还有 15/17/19（文字语音）、24/30（LED）、9（功放子任务） |
| LED 任务的「独立 / 附属」 | **不看 tasktype**（都是 30），看 `sec_task_id` 是不是 0 |
| `ledsentence.mediaid` | 存的是 **`media.id`**，不是 `ledsentence` 自己的 id |
| 通知报文的 state | 手册说停止写 0，旧代码实际写 2；暂停/恢复的 22/23 手册根本没提 |

## R4 · ok112 目录只读

`ok112/` 保留在仓库里作对照，**不改、不删、不清理**。
（里面有明文口令和真实数据文件，这是已知的，按要求保持原样。）

## R5 · 通知报文格式照抄旧版调用点

不是照手册写，是照旧版 `do.php` 里**实际发出去的那一行**写。
差一个 `&type=2` 后台就解析不了。见第 9 章。

# 3. 技术选型与工程结构

## 3.1 选型

| 层 | 选型 | 为什么 |
|---|---|---|
| 后端 | **Go 1.24 + 标准库 `net/http`** | 单文件二进制，目标机器不需要装运行时；`go 1.22+` 的 ServeMux 已支持 `METHOD /path/{id}` 模式，不需要路由框架 |
| 数据库访问 | **`database/sql` + go-sql-driver/mysql，手写 SQL** | 零 DDL 前提下 ORM 的迁移能力是负担；旧库的列名列义还常常对不上，手写 SQL 反而看得清 |
| 配置 | YAML（gopkg.in/yaml.v3） | |
| 前端 | **Vue 3 + TypeScript + Vite 6 + Element Plus** | 基于 Geeker-Admin 模板起的 |
| 前端状态 | Pinia（+ persistedstate） | |
| 包管理 | pnpm | 锁文件是 pnpm 的 |

后端**直接依赖只有两个**（mysql 驱动 + yaml），这是有意的：这台机器要长期运行，
依赖越少越不容易在升级时炸。

## 3.3 后端分层规矩

```
handler (cmd/htweb/*_handlers.go)
    ├─ 解析请求参数 / JSON
    ├─ 取当前用户 auth.From(r.Context())
    ├─ 调 service
    └─ httpx.OK / httpx.Fail

    ├─ 校验业务规则
    ├─ 事务
    ├─ 写库
    └─ 发通知
```

**handler 里不写 SQL，service 里不碰 http.Request** —— 这条没有例外。

一个模块的典型文件切分（以 `internal/task` 为例）：

```

control.go   启动 / 停止 / 暂停 / 恢复 / 启停 / 音量
copy.go      复制
folder.go    任务分组
ledsub.go    LED 字幕子任务
picker.go    选择器（媒体树 / 终端树的数据源）
```

# 4. 后端通用约定

## 4.1 统一响应体

```json
{ "code": 200, "msg": "ok", "data": { } }
```

- **HTTP 状态码永远是 200**（除非是真的网络/服务器错误），业务结果看 `code`。
  这是 Geeker-Admin 前端拦截器的约定，改不得。
- 失败：`{"code": 40001, "msg": "请求参数格式错误: EOF", "data": null}`

错误码表（`internal/httpx`）：

| 码 | 含义 | 前端表现 |
|---|---|---|
| 200 | 成功 | |
| 40001 | 请求参数格式错误 | 弹错误提示 |
| 40002 | 名称已被占用 | |
| 40003 | 层级超限（目录树） | |
| **401** | 未登录 / 令牌失效 | ⚠ 必须是 401，拦截器认这个码跳登录 |
| 40102 | 用户名或密码错误 | |
| 40103 | 验证码错误 | |
| 40104 | 用户已停用 | |
| 40301 | 权限不足 | |
| 40302 | 备机（只读）模式，禁止写入 | |
| 40303 | 系统对象受保护（admin / 系统组） | |
| 40304 | 记录被锁定 | |
| 40401 | 对象不存在 | |
| 40402 | 文件缺失 | |
| 40901 | 被引用中，不能删 | |
| 40902 | 冲突 | |
| 41301 | 上传超限 | |
| 41501 | 文件类型不对 | |
| 50001 | 服务器内部错误 | |
| 50002 | 转码失败 | |

## 4.2 分页

请求：`?pageNum=1&pageSize=20`（`internal/store.NewPager`）
响应：

```json
{ "list": [], "pageNum": 1, "pageSize": 20, "total": 137 }
```

## 4.3 排序：白名单，不拼字符串

```go
var orderWhitelist = map[string]string{"id": "usergroup.id", "name": "usergroup.name"}
order := store.OrderBy(orderWhitelist, q.OrderBy, q.Order, "usergroup.id DESC")
```

旧版这里写的是 `ORDER BY '$searchsequence' desc` —— 加了引号变成按常量排序，
排序下拉永远不生效（D-40）。白名单同时解决注入和这个缺陷。

## 4.4 条件拼装与 LIKE 转义

```go
cond := &store.Cond{}
if q.Keyword != "" {
    cond.Add(`usergroup.name LIKE ? ESCAPE '\\'`, store.EscapeLike(q.Keyword))
}
rows, err := db.QueryContext(ctx, "SELECT … FROM usergroup"+cond.Where()+" ORDER BY "+order+" LIMIT ? OFFSET ?", …)
```

`EscapeLike` 把 `% _ \` 转义掉 —— 否则用户搜一个 `%` 就把整表捞出来。

## 4.5 删除一律先给「影响面预览」

凡是会级联删掉别的东西的删除，都配一个 `GET …/delete-preview`：
先告诉用户「这一删会连带删掉 3 个用户、12 条任务、5 个目录」，确认后才真删。

现有的预览接口：媒体目录、媒体、用户、用户组、终端、任务、报警分区、作息方案…

## 4.6 事务边界

「主记录 + 附属清单」一律在**同一个事务**里全清再写：

```go
tx, _ := db.BeginTx(ctx, nil)
defer tx.Rollback()
// 1. 改主记录
// 2. 删旧的附属行（媒体清单 / 终端清单 / 字幕 …）
// 3. 插新的
// 4. 同步子任务（功放 / LED）
tx.Commit()
```

旧版没有事务，中途失败任务就变成一个没有终端的空壳。

## 4.7 「整条拆掉重建」策略

任务的媒体清单、终端清单、LED 字幕、子任务，改的时候**不做逐行 diff**，
直接删光重插。数据量都是几行到几十行，重建代价可以忽略，而 diff 的代码
是缺陷高发区。

⚠ 唯一的例外见 7.4.6：LED 屏绑定（`ledoftask`）在表单不提交时要**保留原值**。

# 5. 认证、权限与数据可见范围

## 5.1 登录

```
POST /api/login   {"username":"admin","password":"123456","captchaId":"…","captcha":"…"}
→ {"code":200,"data":{"access_token":"…","server":{"readonly":false},"user":{…}}}
```

- 口令在库里是 **MD5**（`book_admin.userpwd`），旧版就是这样，沿用。
- 令牌放在请求头 **`x-access-token`**。
- 验证码由 `auth.captcha_enabled` 控制；开关的**唯一权威在服务端**，
  `GET /api/captcha` 返回 `{"enabled":false}` 时前端连输入框都不显示。
- 会话存在内存里（`auth.Manager`），重启即失效。TTL 由 `auth.ttl` 定（默认 8h）。

例外：**媒体试听 / 下载 / 备份包下载**这三个路由额外接受 `?token=`，
因为 `<audio src>` 和 `window.open` 带不上自定义请求头。其它接口一律不开这个口子。

## 5.2 权限模型

三层，从粗到细：

### ① 是不是超级管理员

`u.ID == 1`（就是 admin 本人）。只有他能：管理别人的账号、看/清操作日志、改日志保留期。

### ② IsAdmin（管理员组）

`book_admin.usergroupid == 1`。对应旧版的 `$_SESSION['admin_id']=='administrator'`。
**IsAdmin 直通所有权限位**，并且能看到所有人的数据。

### ③ 13 个权限位

`usergroup` 表的 13 个列，每个对应界面上一个勾选项。判定入口：

```go
u.HasRight(auth.PrivTask)                    // service 层
a.authMgr.RequireRight(auth.PrivTask, h)     // 路由层
```

**读接口一律只要登录**（`req`），写接口按位卡。完整对照见附录 B。

### 只读（备机）模式

`serverbaseparam.model` 表示主/备机。备机模式下所有写操作回 `40302`。
唯一的例外是 `srv` 这道门（`RequireRightAllowReadOnly`）：服务器信息页
在备机上也得能看能改自己的参数。

### 未注册状态

`regGate`：服务器未注册时，登录被拦（`LoginBlocked`），但注册相关的三个接口开放 ——
否则用户永远进不去也就永远注册不了。注册成功后这几个口子自动关上。

## 5.3 前端怎么知道自己有什么权限

不靠前端猜，两个接口下发：

- **`GET /api/menu/list`** —— 菜单树。没权限的页面**根本不在树里**，前端也就没有那个路由。
- **`GET /api/auth/buttons`** —— 页内按钮的可用性：

```json
{ "task": {"add":true,"edit":true,"delete":true,"control":true,"copy":true,"folder":true},
  "led":  {"edit":false},
  "time": {"config":true,"sync":true} }
```

页面上的按钮按它置灰。**但服务端不依赖它** —— 每个写接口自己再卡一次。

## 5.4 数据可见范围（★ 最容易写错）

规则一句话：**管理员看到全部，其他人只看到自己建的；文件管理是唯一例外。**

| 模块 | 归属列 | 非管理员看到什么 |
|---|---|---|
| 任务（文件广播 / 四类 typed / 作息方案） | `task.task_user_id` | 只有自己建的 |
| 任务分组 | `taskfree.userid` | 只有自己的 |
| 终端分区 | `terminalgroup.userid` | 只有自己的 |
| 报警分区 | `alarmarea.userid` | 只有自己的 |
| 遥控任务 | 经 `shortcutkeytask.mediaid → task.task_user_id` | 只有自己的 |
| 用户 | —— | 只有 admin 能管别人 |
| **文件管理（媒体 + 媒体目录）** | —— | ⚠ **所有登录用户都能看到全部** |

文件管理这个例外是有意的：媒体库是共用素材库，别人传的音频也要能拿来做任务。
**写操作没有放松** —— 删媒体、改名/删目录仍然只有创建者本人或管理员能做。

实现方式统一成一个方法，例如：

```go
// internal/remote/remote.go
func visibleCond(u *auth.User, alias string) (string, []interface{}) {
    if u.IsAdmin { return "1=1", nil }
    return alias+".task_user_id = ?", []interface{}{u.ID}
}
```

⚠ 写接口除了可见范围，**还要再查一次归属**才能改/删 —— 列表看不见不等于接口调不动。

# 6. 操作日志（审计）

## 6.1 落库方式：中间件，不是逐个 handler

```go
// cmd/htweb/audit_mw.go
auditMux.HandleFunc(pattern, handler)   // 注册路由时统一包一层
```

- 只记 **POST / PUT / DELETE**，且只在**成功**时记。
- 「成功」的判定：`httpx.Fail` 也回 HTTP 200，所以不能看状态码 ——
  包一层 `ResponseWriter`，嗅探响应体开头 32 字节里有没有 `"code":200`。
- 操作名来自 `auditLabels`，键是**注册路由时的模式原文**（`PUT /api/users/{id}`），
  不是实际 URL。否则一个接口会散成无数种 operate 值，日志没法按操作聚合。
- 当前用户由 `authMgr.Resolve(token)` 反查。
  ⚠ **不能用 `auth.From(r.Context())`** —— 上下文里的用户只活在鉴权中间件
  创建的那个请求副本里，中间件在外层拿不到。

**落到 `log` 表**：`(username, operate, ip, time)`。

## 6.2 两个自己记日志的接口

| 接口 | 为什么不能交给中间件 |
|---|---|
| `POST /api/login` | 成功那一刻请求上下文里还没有会话，中间件取不到用户名 |
| `POST /api/logout` | handler 已经把会话作废了，中间件事后反查 token 查不到人（实测落出来是 `user='-'`） |

两个都在 handler 里、在合适的时刻自己写一行。登出那一行必须写在
`authMgr.Logout(token)` **之前**。

## 6.3 覆盖面要求

**所有增删改都要有日志。** 当前状态：124 条写路由 —— 114 条有 label，
10 条自记，0 条遗漏。加新写接口时，`auditLabels` 里必须同时加一行。

## 6.4 保留期与按天滚动

- 可选 **1 个月（默认）/ 3 个月 / 半年 / 1 年**。
- 设置存**文件**不存库（R1：不能建表也不能加列），路径 `config.logs.settings_file`，
  默认 `<备份目录上级>/logsettings.json`。
- 触发时机有两个：
  1. 界面上选完保留期点「确定」—— **存设置和滚动是同一个动作**，立刻清一次；
  2. 服务内一个自调度 goroutine，起来 1 分钟后跑一次，之后每 24h 一次。
- 清什么：**只清 `log` 表**，按 `time` 删。后台 C 服务写在 `datelog/` 下的
  `logYYYY-MM-DD.html` 不归新版管 —— 任务日志那一页已撤（见 7.7.4），
  界面上看不见的东西不该在后台被悄悄删掉。
- 清理动作本身也记一行审计，且这行审计写在删除**之前**（用 `id < auditID` 把自己排除）。

## 7.0 界面语言（中 / 英）

右上角的语言下拉切中英文，选择记在 `localStorage` 的 `geeker-global.language` 里。

**开关本身**（`languages/index.ts` + `App.vue`）：初始值读上次选的，默认中文；
不按浏览器语言猜 —— 猜出来几乎总是错的。Element Plus 的 locale 跟着一起切，
只切自己的 `$t` 而不切它，会切出一个中英夹杂的界面。

**左侧菜单**由后端下发、标题是中文，但每一项都有稳定的 `name`。
前端按 `name` 查 `menu.*` 翻译（`stores/modules/auth.ts` 的 `localizeMenu`），
**后端一行都不用改**。翻译放在 store 的源头：`meta.title` 有 8 处在读，
逐处包 `$t` 漏一处就是那处永远中文。页签是例外 —— 它把标题存进了自己的
持久化状态，必须**渲染时**再翻一次，否则切了语言之后已经开着的页签停在旧语言上。

**工具**（都在 `web/scripts/`）：

| 脚本 | 干什么 |
| --- | --- |
| `check-i18n.mjs` | ① 比对 zh/en 键集合（缺键不报错，vue-i18n 会静默回落到中文）；② 数还剩多少界面文案没接入，这是「英文版做到哪儿了」的客观口径 |
| `i18n-extract.mjs` | 从一个文件里把会显示给人看的中文按「模板文本 / 模板属性 / 脚本字面量」分类列出来 |
| `i18n-apply.mjs` | 按一份 {中文: 键} 的映射做上下文相关的替换，只换完全相等的整串 |
| `i18n-ensure-t.mjs` | 给 `<script setup>` 注入 `const { t } = useI18n()` |
| `i18n-add.mjs` | 把一批 `{命名空间: {键: [中文, 英文]}}` 同时合进 zh.ts 与 en.ts，已存在的键跳过并列出来 |

在某一行写 `i18n-ignore`，`check-i18n` 与 `i18n-extract` 都会跳过那一行。
留给「**必须**是中文」的地方：AI 助手的例句是原样发给 NLU 的指令，
语言下拉里的「简体中文」是它自己那门语言的名字。没有这个标记的话，
每跑一次检查都要人重新判断一次这几条到底该不该翻。

⚠ **`defineProps` 的默认值里不能写 `t(...)`**。它会被提到 setup 外面，
`vue-tsc` 不报、`vite build` 才报。默认值留空串，在取值处兜底
（`TerminalTree/Select.vue` 的 placeholder / emptyLabel 就是这么处理的）。

⚠ **组件外的文件取不到 setup 里的 `t`**（`api/helper`、`utils`、`hooks`、
`routers`、`directives`）。那些地方用 `i18n.global.t`。
同理，**模块级常量不能存翻译好的文字** —— 它在 i18n 初始化之前就求值了。
`RIGHT_ITEMS`（权限项）、`KIND_TITLE`（四类任务标题）、首页快捷入口候选页
存的都是 **i18n 键**，翻译推到用的那一页去做。

⚠ **不要机器翻译夹着插值的句子**。`只能绑定<b>{{ 类型 }}</b>任务，最多 12 个`
拆开翻，中文拼得出来，英文语序对不上，只会拼出一句不通的话 ——
这类要整句一个键，用 `{placeholder}` 传参。

⚠ **代码注释不翻**。注释是写给维护者的，翻掉等于把信息丢了。
上面几个脚本都跳过注释区段。

### 后端也要跟着切：`internal/i18n`

页面里有一半内容是后端给的 —— 信封里的 `msg`、终端型号、紧急广播槽位名、
任务状态。只切前端不切后端，英文界面一报错就冒出一句中文。

**语言怎么传过去**：前端 axios 拦截器带 `Accept-Language: zh|en`（`web/src/api/index.ts`）；
后端最外层的 `i18n.Middleware` 解析它，塞进 context，同时把 `ResponseWriter` 包一层。

**msg 怎么翻**：`httpx.write` 在写响应前顺着 ResponseWriter 的包装链找那个
知道语言的（标准库 `http.ResponseController` 那套 `Unwrap()` 约定），翻一次 `msg`。

⚠ 这样做是为了**不改 170 个 `httpx.Fail` 调用点**。给它加一个 `r` 参数是一次
纯机械的大范围改动，把每个 handler 都搅一遍，收益只是把一个值传过去。
代价是包装器必须实现 `Unwrap()` —— 审计用的 `sniffWriter` 已经补上；
将来再包一层忘了实现，后果是那条链上的提示退回中文（看得见、能补），不会出错。

**data 里的展示文案**（型号、状态、槽位名）到不了响应边界，
在业务层用 `i18n.TC(ctx, "中文")` 现翻。

**字典为什么用中文原文当键**：后端三千多条提示散在各处，给每条编 ID 再改
三千个调用点是纯机械劳动，而且**改漏一处不会报错**，那条提示只是永远中文。
用原文当键，调用点一个字不动，补翻译 = 往字典加一行。

代价是原文改了字典会静默失配，所以 `dict_test.go` 会把 `codeDict` 里每一条
回源码里找一遍。库里 / 前端来的那些（终端型号、备机提示）源码里本来就没有，
单独放 `dataDict` —— 混在一起的话，要么测试天天红，要么就得关掉这条检查，
而它恰恰是防止翻译静默失效的唯一手段。

⚠ **切语言会整页重载**。页面里那一半后端内容是在请求发出那一刻定好语言的，
不重载会得到「菜单英文、表格中文」的半截界面。

⚠ **拼装型文案不能靠字典**。「周日、一、二」中文是「周」带一串，英文是
"Sun, Mon, Tue"，结构不同 —— 拿拼好的成品去查字典要为 2^7 种组合各配一条。
这类走 `i18n.CycleText(ctx, mask)`，拼装本身知道语言。
（dashboard / typedtask / offline 原来各抄了一份 `cycleText`，一并合成了这一个。）

⚠ **用户自己起的名字永远不翻**：终端名、媒体名、任务名、分区名、用户组名。
那是他们的数据，翻了就和他们嘴里说的对不上。
反过来，**终端型号、系统预置媒体库名、紧急广播槽位名、各种状态文字是产品词汇，
必须翻**。这条界线只能逐字段判，光看页面判不出来 —— 演示数据里型号那一列
混在终端名旁边，不逐字段比对根本分不出哪个是数据、哪个是没翻的词汇。
实际做法是**把接口快照按英文再录一遍，逐个字段找中文**，一次翻出了 19 处
漏掉的型号。

**终端型号的取值路径**：`terminal.typeid` → `terminaltype.id` → `terminaltype.name`，
全站 29 处 JOIN 都是这一条，前端一处都没写死型号名（都绑 `typeName`）。
翻译在读出来那一刻做（`i18n.TC(ctx, TypeName)`），库里存的始终是中文。

⚠ 型号名是**库里的数据**，不是代码里的字面量 —— 现网加一行新型号、或者改了某一行的名字，
字典就查不到了，而这件事**不会报错**，英文界面上只是冒出一句中文。
单元测试查不了（要连库），所以放在 `cmd/doctor` 里：

```
go run ./cmd/doctor -dsn "..."     # 末尾会报「终端型号(terminaltype.name)有译文: 35/35」
```

名字本来就不含中文的（现网那个 `MP3`）跳过，中英一样，没什么可翻的。

⚠ **系统预置目录才翻，用户建的目录不翻**。判据是 `id <= folder.SystemMaxID`，
规则导出成 `folder.LocalizedName(ctx, id, name)` —— 各种下拉/选择器不走
`folder.build()`，散着写 `id <= 9` 迟早写错一处。

### 接口调用平台的目录：走一遍结构，不逐条包

`internal/openapi/spec.go` 那六百多条文案不是逐个 `i18n.TC` 包起来的，
而是 `openapi.Localize(ctx, &spec)` 走一遍结构统一翻。理由是逐条包要给每个
构造函数都加 `ctx`，而且**新增接口时得记得也包一层** —— 漏一条不报错，
只在英文界面留一句中文。走结构只有一处，新增接口不用做任何事就跟着翻。

代价是漏补字典同样不报错，所以配了两个测试盯着：
`internal/openapi/localize_test.go`（常用接口）与
`cmd/htweb/openapi_expose_test.go`（全部功能接口）——
加接口时忘了补词条，测试当场红。

`Path` / `Method` / `Type` / `Body` / `CodeValue.Value` 这些是代码和字段名，不翻。
响应示例（`Sample`）只有含系统词汇的那几段进了字典（型号、状态文字、报错原文），
里面的演示名字是「用户数据长什么样」的示例，保持中文。


## 7.0.1 修改密码（右上角头像里）

对应旧版 `modifypassword.php` + `do.php` 的 `userpasswordmodify_msg`。

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/account/password-policy` | 登录 | 新密码要满足什么，只用来在弹窗里把要求写出来 |
| `PUT /api/account/password` | 登录 | 改**自己**的密码 |

两个都不需要任何权限位 —— 它动的是自己那一行。备机模式下也允许：
备机只读的是**广播业务**，不是「连自己密码都不许改」。
两个都在 `keyDenied` 里：密钥背后没有人，改谁的密码都不对。

**规则照搬旧版**：三个框、`maxlength=16`。`serverconfig.fuzamima` 非 0 时要求
「数字 + 大写 + 小写 + 符号，8 位以上」（旧版正则
`(?=.*[0-9])(?=.*[A-Z])(?=.*[a-z])(?=.*[^a-zA-Z0-9]).{8,30}`）；为 0 时旧版不做任何要求。
上限取表单的 `maxlength=16`，不取正则里的 30 —— 旧版界面根本输不进第 17 个字符。

**与旧版的三处差别，都是修 bug，不是改需求**：

1. **改的是自己的密码**。旧版把 `username` 从表单塞进 URL 一起提交
   （`usernames=…&oldpwds=…&newpwds=…` base64 后走 GET），服务端照着这个
   username 去改 —— 知道别人旧密码就能改别人的密码。新版用户名只从会话取，
   请求体里根本没有这个字段。顺带：密码不再走 query string（会进 access log）。
2. **确认密码真的比一遍**。旧版那个「再输一次」的框只参与复杂度校验，
   从头到尾没和新密码比过 —— 两个框填不一样也能改成功。
3. **校验在服务端做**。旧版三条规则全在浏览器里跑，服务端一条都不查，
   绕过页面直接发请求空密码也能设进去。

⚠ **改完不踢下线**，旧版也是留在原页面。但同一个账号在别处登录的会话也不会失效 ——
会话表按 token 存，没有「按用户批量作废」这条路。要做得给 session 带上 userID。

「个人信息」那个入口删掉了：它一直是脚手架留下的空弹窗（里面就一句
`This is userInfo`），既没有对应接口也没有对应需求。


## 7.1 看板 · 首页 `/home`

**页面**：设备概况环形图（总数/在线/离线）、服务器性能（CPU/内存/磁盘/网络流量）、
快捷入口、快捷任务、紧急广播四路按钮、浏览任务表格。

**接口**

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/dashboard/overview` | 登录 | 设备概况 |
| `GET /api/dashboard/perf` | 登录 | CPU / 内存 / 磁盘 / 网卡流量 |
| `GET /api/dashboard/tasks` | 登录 | 浏览任务（可按星期、类型筛） |
| `GET /api/dashboard/config` | 登录 | 两块自定义配置 + 紧急广播四路的名字 |
| `PUT /api/dashboard/shortcuts` | **超管** | 快捷入口 |
| `PUT /api/dashboard/quick-tasks` | **超管** | 快捷任务 |
| `POST /api/dashboard/emergency` | `taskpriv` | 下发一路紧急广播（play / stop） |

**⚠ 两块配置存在哪**：快捷入口 / 快捷任务都是**新增的界面状态**，
旧库里没有对应的表，R1 又禁止建表。看过所有空表后的结论是：
`shortcutkeytask`、`ctrltask` 这些虽然是 0 行，但**都是后台 C 服务可能扫描的业务表** ——
往里塞界面状态，万一被当成真任务执行，就会在一所正在上课的学校里放出一段
没人预期的广播。这个风险不值得冒。

所以这两样落**一个 JSON 文件**（默认 `<备份目录同级>/dashboard.json`）：
不动数据库、不可能被 C 服务误读、重启后仍在、所有用户共享同一份。
**代价是它不在数据库备份包里** —— 备份还原那一节也记了这一点。

**⚠ 绑定的任务被删掉之后**：`GET /api/dashboard/config` 每次读的时候会顺手把
快捷任务里指向已删除任务的绑定摘掉，并落盘。

为什么是「读的时候清」而不是挂在删除任务那一步上：任务能从很多地方被删 ——
任务页、开发者接口、AI 助手、删用户的级联、删终端的级联、快捷任务自己的清理。
挂钩子就得每一处都挂，而漏掉任何一处的表现是「首页上有个按钮，点了没反应」，
没有任何报错。

⚠ 判定只看 `task` 表里有没有这一行，**不带可见范围过滤**：这份状态全站共用，
按「当前这个人看不看得见」来删，普通用户一进首页就会把管理员配的绑定清掉。
另外只在查库**成功**之后才清 —— 数据库连不上时把绑定全清掉是最坏的失败方式。

### 快捷任务的执行状态：每 3 秒拉一次

`task.state` 归后台 C 服务所有 —— 界面只发命令、只读状态，一个字都不自己写。
这中间有时间差：点「执行」到 state 真的变成 1（执行中），隔着 C 服务下一次扫表。

所以卡片上的状态分两层：

- **每 3 秒轮询一次** `GET /api/dashboard/config`，只把返回里的 `quickTasks` 换掉
  （不动 `shortcuts` —— 那边可能正开着编辑模式）。轮询看的是任务本身，
  所以别人点的、作息方案到点自动跑的、AI 助手下发的，一样会在卡片上出现。
- **点完立刻本地标一个「启动中」**，等第一次轮询把真状态带回来再让位。
  没有这一步的话，点完的头三秒卡片纹丝不动，人会以为没点上。

  ⚠ 这个本地标记有兜底：**15 秒**内 C 服务还没把它变成执行中就撤掉，
  让卡片回到真实状态。停在一个「启动中」上不动，比直接显示「准备」更误导。
  另外命令被 `blocked` 挡下时根本不标 —— 它没有启动。

执行中的卡片上状态字变绿并带一个呼吸的圆点。**颜色不单独承载信息**：
字本身就写着「执行中」，圆点只是让人一眼扫到；`prefers-reduced-motion` 下不闪。

### 紧急广播那四个按钮

**四路固定**（地震 `quake` / 疏散 `evacuate` / 警戒 `alert` / 消防 `fire`），
**不绑任务** —— 按一下直接向后台广播服务发一条厂商 SDK 的二进制命令，
由后台去驱动终端。所以这四个按钮任何时候都能按，也不存任何东西。

早先这四个槽位是「绑一条文件广播任务、按了去启停那条任务」，
现在改成走 SDK（原系统本来就是这么做的）。`dashboard.json` 里那个
`emergency` 键已经不再读，下一次落盘时自动消失，不用手工清理。

**报文长什么样**（`server/internal/sdkudp`）：`cmdid = 194`，args 是
`SDKUrgentPlay_t{channelid, keyid, terminalid, isstop}` 四个 int32，
总长 `16(头) + 16(args) + 1(0x5a 结尾) = 33` 字节。

⚠ **字节序是本机序（小端），不是网络序** —— 厂商那边是把 C 结构体直接
`sendto` 出去的，`htons` 只用在端口上。写成大端的话后台服务解不出来，
而 UDP 不会报任何错，表现就是「点了没反应」。所以 `encode()` 有逐字节的单测。

四路的 `channelid` / `keyid` 是**设备固件里定死的**：0/1000、1/1001、2/1002、3/1003。
`terminalid` 固定填 **0 = 全部终端**（紧急广播按定义就是全场都要听见，
界面上也没有选终端这一步）。头部三个字段取 `state=0, serialid=0, sessionid=1`。

**端口在 `config.yaml` 的 `sdk` 一节**，默认 `127.0.0.1:8885`；
`enabled: false` 时只记日志不真发包（联调期用 —— 这条命令一发出去全场喇叭就响）。
它与 `notify` 是**两套协议、两个端口**：notify 发的是文本报文
（`task?state=3&id=7`）到 `serverbaseparam.webport`，不能混。

**⚠ 界面上的提示只能说「已下发」**：UDP 没有回执，接口返回成功只代表包发出去了，
后台服务收没收到、终端响没响，这一侧看不见。前端「执行」前还会问一遍
（停止不问 —— 真按错了要停下来的时候不该再挡一道）。

权限取 `taskpriv`，与它替换掉的那两个启停按钮一致；收到超管会让值班的人真出事时按不动。
同时它**不对开发者接口开放**：这种事必须是人在界面上按的，不能挂在一个能被脚本调用的密钥后面。

**性能数据**读 `/proc`（Linux 专有，Windows 上编译不过，见 10.1）。

### 7.2.2 时间设置 `/time`

**接口**：`GET /api/time`（当前时间/时区/运行时长/NTP/GPS/能力探测）、
`PUT /api/time/ntp`、`PUT /api/time/gps`（srv）、`PUT /api/time/clock`（srv）、
`POST /api/time/sync`（trm，给终端下发校时）、`GET /api/time/terminals`

**坑**
- **`serverbaseparam.adjusttime` 不是开关，是终端 ID**。0 = 不启用 GPS 校时。

  刷新页面按钮就亮，不用改代码也不用重启。
- 旧版那段 `date`/`time`/`setrtc` 是 DOS 语法 + 命令注入，**从来没生效过**（D-218）。

### 7.2.3 备份还原 `/backup` — **全部超管**

**接口**：`GET/POST/DELETE /api/backups`、`POST /api/backups/upload`、
`GET /api/backups/{name}/restore-precheck`、`POST /api/backups/restore`、
`GET /api/backups/{name}/download`（接受 `?token=`）

**★ 与旧版最根本的一处不同：备份包里不含任何 DDL。**
旧版备份是 `DROP TABLE` + `SHOW CREATE TABLE` 原文 + `INSERT`，
于是「恢复一个结构不一致的旧包」= **把线上表结构改成备份那一刻的样子** ——
这是 R1 红线上最大的实际风险。新版是**纯数据备份**：只有行数据，
恢复 = 现有表里 `DELETE` + `INSERT`，全程不碰表结构。

上传走 `MultipartReader` **流式**读，不用 `ParseMultipartForm`
（后者会把整个包先读进内存/临时文件，80MB 的包就是 80MB 内存峰值）。

恢复前先 `restore-precheck`：包里的表和现有表对不上就拒绝，并说清差在哪。

### 7.2.4 节假日管理 `/holiday` — 权限 `bellpriv`

**表**：`holidaytime`

**接口**：`GET /api/holidays`、`GET /api/holidays/{id}`、`POST/PUT/DELETE`、

**规则**

  （旧版这一页用的是 `ttspriv`，这是**有意的偏离**）。
- `holidaytime.projectstate`：**1 = 启用**，与 `task.projectstate` 相反。别混。
- 保存前查日期区间重叠（`overlaps`），重叠会让后台行为不确定。

### 7.4.0 `task` 表的四个共同约定

**① tasktype 决定它是什么**

| tasktype | 是什么 | 哪一页管 |
|---|---|---|
| 1、15（且 `info` 非空） | 作息方案的一次打铃 | 作息方案 |
| 2 | 文件广播 | 文件广播 |
| 3 | 采播 | 采播管理 |
| 5 | 终端功放 | 终端功放 |

| 24 / 30（`sec_task_id = 0`） | 独立 LED 任务 | led播放 |

**② projectstate：0 = 启用，1 = 停用**（列注释是反的）

**③ 归属与分组**：`task.task_user_id → book_admin.id`（可见范围靠它），
`task.parentid → filetaskfree.id`（任务分组）。

**④ 一条任务的完整数据 = 四张表**

```

mediaoftask       媒体清单（mediaid, taskid, sort）
terminaloftask    终端清单（taskid, terminalid, groupid, area）
+ 可能有子任务：   tasktype=9 功放子任务 / tasktype=30 LED 字幕子任务
```

保存时这几张全清再写（见 4.7），删除时一并删掉，`delete-preview` 里会说清连带删什么。

**⑤ `area` 是 8 位分区/通道掩码**，字符串 `"11111111"`，没勾过就用全通道默认值。

### 7.4.1 作息方案 `/bell` — 权限 `bellpriv`

**★ 作息方案不是一张表**：一个「方案」= `task` 表中**共享同一个 `task.info`** 的一组行，
每行是一次打铃（一节课）。方案本身没有独立主键行，属性由这组行聚合出来：

```
方案名   = task.info            （业务主键）
代表 ID  = MIN(taskid)          （只为兼容旧的按 taskid 传参）
条目数   = COUNT(*)
起止日期 = MIN(startdate) / MAX(enddate)
状态     = ROUND(AVG(projectstate))   ← 组内多数派
```

过滤条件**四项缺一不可**：`tasktype IN (1,15)`、`info` 非空串、`channel = 0`、`sec_task_id = 0`。
少一项就会把普通任务或功放子任务混进来。按「方案表 + 明细表」建模会与旧数据完全对不上（契约 C-38）。

**接口**：`GET /api/bell-plans`、`GET /api/bell-plans/detail`、
`POST/PUT/DELETE /api/bell-plans` + `delete-preview`、`POST /api/bell-plans/copy`、
`PUT /api/bell-plans/state`、`PUT /api/bell-plans/volume`、
条目：`POST /api/bell-plans/items`、`PUT /api/bell-plans/items/{id}`、
`PUT /api/bell-plans/items/schedule`、`DELETE /api/bell-plans/items`

**打铃条目也能挂 LED 字幕**，结构与文件广播那边完全一样（复用 `task.WriteLEDContent`）。

⚠ 旧版这一页有「备份方案 / 还原方案」两个按钮，点下去其实调 `backup_restore_form.php`，
**备份的是整个数据库加媒体文件**，跟「方案」没关系。新版**不放这两个按钮** ——
基础配置里已经有真正的备份还原页了。

| `POST /api/tasks`、`PUT /api/tasks/{id}` | 新建 / 修改 |
| `DELETE /api/tasks` + `delete-preview` | 删除（连带子任务） |
| `POST /api/tasks/{id}/copy` | 复制（**界面上已没有入口**，接口还在，见下） |
| `PUT /api/tasks/control/{action}` | 执行 / 停止 / 暂停 / 恢复 |
| `PUT /api/tasks/project-state` | 启用 / 停用 |
| `PUT /api/tasks/volume` | 任务音量（功放/LED 子任务一并同步） |
| `GET/PUT/DELETE /api/tasks/emergency` | 紧急设置 / 取消 |
| `POST /api/tasks/sync-terminals` | 批量同步终端 |
| `GET /api/task-folders/tree`、`POST/PUT/DELETE /api/task-folders` | 任务分组 |
| `GET /api/task-options/{media\|terminals\|priority-range}` | 选择器 |

**规则**
- `prepower > 0` 时自动建/维护一条 `tasktype = 9` 的功放子任务。
- 勾了 led播放 就自动建/维护一条 `tasktype = 30`、`sec_task_id = 主任务` 的字幕子任务；
  取消勾选再保存就删掉它。子任务除类型外**整行照抄主任务**，终端清单也一致。

  **子任务的名字就是主任务的名字**，服务端填（`LEDSub.normalize`），
  接口传什么都不算数，表单上也没有这一栏 —— 两个名字分开维护只会让人
  对着两处一样的东西发愣，主任务改了名还得记得回去改另一处。
  主任务改名时子任务跟着改（保存时整条重建）。

  ⚠ 因此**主任务名不能带 `? & =`**（这三个字符在 LED 那条链路上有特殊含义），
  长度也受 255 字节限制。报错说的是「任务名称」不是「LED 任务名称」——
  说后者的话，人在表单上根本找不到那一栏。
  另外把「不能包含」补进了 `isTaskValidationErr` 的关键词表：
  在此之前这条校验漏在网外，用户只看到「服务器内部错误」。
- 任务级别（priority）的可选区间由用户组 level 决定，新建时先问
  `GET /api/task-options/priority-range`，免得默认值落在区间外、点提交才被拒。
- 时长/循环次数合成到 `timelength` 一列，靠 `timelengthtype` 区分。

**列表两列的口径**（都照 ok112 的 `FileAd/FileTaskManager_from.html`）：

- **状态**：没在跑的时候（`state = 0`）显示启用/停用，跑起来就显示跑到哪一步
  （执行中 / 已停止 / 立即执行）。同一列两种含义 —— 「停用的任务」和
  「正在执行的任务」本来就是互斥的两种情形。
- **正在播放**：`task.playfileid` → `media.name`，也就是拿媒体号取到的媒体名。
  以前这一列显示的是任务状态，与列名对不上。

  ⚠ `task.playfileid` 存的**就是 `media.id`**（现场确认）。列名看不出这件事，
  库里也没有外键，所以两处都记了一笔（`task.Item` 的字段注释 + 这里）。

  ⚠ 这一列是**后台广播服务写的**，Web 这一侧只读不写 —— 旧版 PHP 从头到尾
  只在建任务时把表单值原样插进去（一般是 0），启停时一次都没碰。
  所以一条停下来的任务可能还挂着上一首的号，界面上就照样显示那个名字：
  **这一列如实反映库里的值，不替后台服务做判断**。取不到名字就显示「—」。

**操作列没有「复制」**：照 :80 只有「编辑 / 终端 / 媒体」，删除在工具栏上
（勾中行再点），不在行里重复一份。`POST /api/tasks/{id}/copy` 这个接口还在，
只是界面上不给入口了。

#### 终端列表里的「电源 / 分区」小框

勾中一台**前置或功放**时会弹一张小表，逐路勾电源与分区，勾选结果是
`terminaloftask.area` 那个 0/1 掩码（一路一位，第 1 位对第 1 路）。
照 ok112 —— 它在 `AddFileTask_form.html` 的 `toncheck()` 里 `state==1` 就把
`div#lead` 浮到鼠标边上；不弹的话那几路默认全接通，而人根本不知道有这回事。

**哪几路是电源、哪几路是分区，取决于终端是哪一类**（`internal/termswitch`）：

| 类别 | `terminaltype.id` | 排法 |
|---|---|---|
| 前置 | 4 / 34 / 36 / 39 / 47 | **前两路是电源**，其余 `switchcount - 2` 路是分区 |
| 功放 | 5 / 24 / 37 | **全部 `switchcount` 路都是电源** |
| 其它型号 | — | 没有这回事，不弹也不显示入口 |

⚠ 三件容易搞错的事：

1. **`switchcount` 只说有几路，不说每一路是干什么的。** 库里没有任何一列
   说得清这件事，而 R1 红线不许加列 —— 所以型号号码写在
   `internal/termswitch` 一处，后端算好，接口回一个
   `switches: {kind, power, zone}` 给界面。**前端不认型号号码。**
   现场换新型号只改那一处。
2. **旧版的名字是错的。** ok112 把十六个名字写死成
   `zone_1..zone_16`，其中第 7、8 位固定叫「电源一 / 电源二」——
   那是照某一种型号排的，换个型号就对不上。现在按型号算。
3. **`switchcount = 0` 的型号不弹**（现网 24 / 39 / 47 就是 0）：
   一路都没有的框弹出来是空的，比不弹更让人摸不着头脑。

点分组节点会连带勾上底下十几台，那种情况**不弹** —— 一台弹一个框没法用；
需要逐台设的话点节点上的入口。

三处界面共用同一个 `TerminalTree` 组件：文件广播、作息铃声、九类任务。

**修掉的旧缺陷**：排序双重失效（D-99）、分页被注释掉（D-100）、
**严重 N+1**（每个任务额外 2 条查询取媒体与终端，100 个任务 201 次查询，D-101）、
为渲染下拉把整张 media 读进内存（D-102）、媒体清单用内连接导致删过的媒体项直接消失（D-105）。

### 7.4.7 启用管理 `/enable` — 权限 `ttspriv`

**表**：`enabletask (id, enstate, startdate, starttime, taskid, flag)`
一条记录 = 「到了某年某月某日某时某分某秒，把这一批任务按各自的安排启用或停用」。

**接口**：`GET /api/enable-plans`、`GET /api/enable-plans/{id}`、`POST/PUT/DELETE`、
`GET /api/enable-plans/tasks`

**★★ `enstate` 和 `taskid` 是两串并列的逗号分隔值**，**逐项对应**：

```
taskid  = "70007,70012,70020"
enstate = "0,1,0"              ← 0=启用 1=停用，与 taskid 一一对应
```

不是整行一个值 —— 列类型 `varchar(1024)` / `varchar(2048)` 正是为此。

**表结构上的两个坑（不改表，读写时绕开）**
- `taskid` 是 `varchar(2048)`：超长会被**静默截断**，截断处很可能落在某个 id 中间，
  后台就解析出一个别的任务。**保存前按字节数挡住**。
- `id` 是 `int(4) unsigned zerofill` 且只有 UNIQUE KEY 没有 PRIMARY KEY：
  查出来是 `"0001"` 这种补零字符串，**一律 CAST 成整数用**。

⚠ 可见范围：`enabletask` 没有 userid 列，收敛不了，所有人看到同一份（旧版也没有过滤）。

## 7.6 噪声检测

三页：噪声设备 / 声场分区（`terminalgrouppriv`）、声场任务（`taskpriv`）。

**四张表**

```
sounddevice    (id, ip, devaddr, name, groupid, dbvalue, sendport)   噪声探头
soundgroupinfo (id, name, userid)                                     声场分区定义
soundgroup     (terminalid, groupid)                                  分区里的终端
```

### 7.6.1 噪声设备 `/noise/device`

之后一律只读 —— 界面上展示，不提供编辑。

### 7.6.2 声场分区 `/noise/zone`
`GET /api/sound/groups`、`GET /api/sound/groups/{id}`、`POST/PUT/DELETE`、
`GET /api/sound/groups/options`、`GET /api/sound/groups/terminals`

⚠ **终端归属又是记两份**（和终端分区、报警分区同一个老问题）：
`soundgroup` 是多对多关联表，`terminal.soundsgroupid` 是终端上的单值列。
旧版删分区时两处都清，**但新建和修改分区时只写 soundgroup、从不写
`terminal.soundsgroupid`**（D-220）—— 建完分区终端自己那列还是 0，后台按它取值就找不到分区。
**新版两处同时维护。**

⚠ `soundtask` 表不归这两页管，见下面的声场任务。

### 7.6.3 声场任务 `/noise/task` — 权限 `taskpriv`

旧版 `zhaoshentaskmanager.php` / `zhaoshengtaskadd.php`，`task.tasktype = 25`。
与终端功放 / 采播管理 / 文字语音 / led播放 **共用 `internal/typedtask` 与
`TypedTaskPage.vue`**（`kind = "sound"`）—— 任务属性、执行时间、播放模式、音量
那几段一模一样，只多出下面三样。

**① 终端从「声场分区」里挑，不是终端分区**

照旧版 `get_zhaoshenggrouped_terminal()`：一层 `soundgroupinfo`，底下**同时挂**
这个分区里的广播终端（`soundgroup`）和噪声探头（`sounddevice`），两种在同一棵树上勾。
节点 id 沿用旧版的 `stream_<分区>::<终端>` / `sounds_<分区>::<探头>`。
接口是 `GET /api/sound-tasks/tree`。

终端还要再按**可广播的型号**筛一道，与旧版 `get_terminal_type(3,…)` 同一句：

```sql
t.typeid IN (SELECT id FROM terminaltype
              WHERE isdecode = 1
                AND id NOT IN (0,2,7,8,9,10,12,15,16,17,21,22,25,26,28,29,30,31,32,36,37,40,41,42))
```

`isdecode = 1` 是「能解码音频」，也就是能出声；后面那串黑名单是旧版一个个排掉的
（服务器、报警主机、编码器、LED 设备、应急终端之类）。名单本身没有规律可循，照抄。

⚠ 写成子查询而不是把型号号码展开成常量：黑名单是「排除」不是「列举」，
现场装了新型号时只要它 `isdecode=1` 且不在黑名单里就该自动出现在树上。

⚠ 库里绑着、但型号不在这份清单里的终端**不会出现在树上**，也就勾不上。
编辑已有任务时界面会提示有几台被摘掉了，而不是悄悄丢。

**② 每个选中的探头带一张「音量 → 噪声值」对照表**

落进 `soundtask`，六档音量是**写死的 0 / 20 / 40 / 60 / 80 / 100**，一档一行。
意思是「这条任务在这个探头上，音量开到 N% 时环境噪声该是多少 dB」——
后台据此把音量调上去或调下来。旧版是浮在树旁边的一小块（`div#soundsset`），
新版做成对话框（浮层挡树，六格也放不下）。

**③ 媒体只能选一个**

旧版那棵媒体树的 `toncheck` 是「先把所有节点取消，再勾中这一个」。
`MediaTree` 因此加了 `multiple` 属性，声场任务传 `false`。
放开成多条的话，后台按什么顺序播、播完第一条还播不播，都是没人定义过的行为。

**`soundtask` 里 `taskid = 0` 那六行是模板，不是任务**

现网躺着 6 行 `taskid=0 devid=0 volume=0/20/…/100`，是界面上「设置默认噪声」存的
一份全站基准：新挑一个探头时先拿它填上，列表上的「应用默认噪声」再把它刷到选中
任务的所有探头上。**它永远不参与真实任务**，所以凡是读写任务数据的地方都带
`taskid <> 0`。

```
GET  /api/sound-tasks/db-template          读默认噪声值
PUT  /api/sound-tasks/db-template          设置默认噪声（旧版 set_task_volume_server.php 的 case 25）
PUT  /api/sound-tasks/apply-db-template    应用默认噪声（旧版 enable_zhaoshen_volume_msg）
```

**修掉的旧毛病**

- 旧版 `enable_zhaoshen_volume_msg` 的 UPDATE 没带 `taskid <> 0`，选中的任务号里
  混进个 0 就会把模板自己也改掉。新版显式排除。
- 旧版「设置默认噪声」是六条 UPDATE，行不在就什么也不发生 —— 少一行就永远改不了
  那一档，坏得无声无息。新版**有就改、没有就补**。
- 删任务时 `soundtask` 会留成孤儿：`typedtask.Delete` 原来不清这张表
  （它只服务过没有 soundtask 的四类）。已补上，同样带 `taskid <> 0` 保住模板。

## 7.7 用户管理

### 7.7.1 用户 `/user/list` — 权限 `userpriv`，且**只有 admin 本人能管别人**

**表**：`book_admin`、`userterminal`（用户能操作哪些终端）

**接口**：`GET /api/users`、`GET /api/users/{id}`、`POST/PUT`、
`POST /api/users/{id}/enable`、`DELETE /api/users` + `delete-preview`、
`GET /api/users/wind-capacity`、`GET /api/users/terminal-options`、
`GET /api/users/password-rule`

**★ 新建 / 修改表单的校验逐条照旧版 checkform()**（`useradd.html` / `usermodify.html`）

| 项 | 规则 |
|---|---|
| 用户名 | 非空；**只能是中文 / 字母 / 数字**（旧版 `isChinaOrNumbOrLett`：`^[0-9a-zA-Z一-龥]+$`）；≤ 50 |
| 用户描述 | ≤ **30** 个字符（旧版表单 `maxlength="30"`，提示语也是「最多30字符」） |
| 所属用户组 | 必选 |
| 密码 | 跟着 `serverconfig.fuzamima`：非 0 时「数字+大写+小写+符号，8~16 位」；为 0 时「6~16 位，且只能是中文/字母/数字」 |
| 确认密码 | 与密码一致 |
| 可控制的终端 | **至少一台**（旧版 checkform 末尾的 `add_user_terminals`） |

⚠ **密码规则与「自助修改密码」不是同一条**，虽然都读 `fuzamima`：
简单模式下自助改密码**不查长度**（旧版 `modifypassword.php` 一条都不判），
而新建用户判了 `length < 6` 并要求字符集。两处规则本来就不同，不要合并 ——
`auth.ReadPolicy` 给的是共同的那一半，`user.PasswordRule` 在它之上把下限换成 6。

⚠ 旧版这些规则**全在浏览器里跑**，服务端一条都不查：绕过页面直接发请求，
空用户名、一位数密码都能存进去。新版服务端各查一遍（`user/validate.go`）。

⚠ 这一组校验回的是 `user.ErrValidation` 包过的错，handler 按**类型**判 400，
不按中文关键词。带参数的提示（「密码长度必须在 %d~%d 之间」）必须先翻译格式串
再 Sprintf，英文界面下 `err.Error()` 是英文，中文关键词一条都匹配不上 ——
实测会变成「服务器内部错误」。

**修改用户与新建的唯一差别**：密码留空 = **不改密码**。
旧版这里有个会锁死账号的缺陷（D-58）：`if($newpwd == $confirmpwd)` 两个空串也相等，
于是把密码改成了 `md5("")` —— 管理员改个描述没填密码，该用户就再也登不进去了。

**规则**
- 口令 MD5。`admin`（id=1）可改不可删（BR-83 / BR-126）。
- 新建用户会连带建一个属于他的任务分组。
- 删用户 = 删掉他名下**所有数据**（任务、目录、媒体、分区…），所以 `delete-preview` 必须先看。
- 分控 ID（ctrlwind / subwind / camerawind）有容量上限，`wind-capacity` 给的就是余量；
  分配完会回 `ErrWindExhausted`。
- 服务器未注册时禁止新建/删除用户（`ErrNotRegistered`）。

### 7.7.2 用户组 `/user/group` — 权限 `userpriv`

**表**：`usergroup`

**接口**：`GET /api/usergroups`、`GET /api/usergroups/options`、`POST/PUT`、
`GET /api/usergroups/{id}/delete-preview`、`DELETE /api/usergroups/{id}`

**★ `level` 是两位复合值 10~109**

```
十位 = 组级别（1~9）        个位 = 组内任务优先级基数（0~9）
SplitLevel(level) → (level/10, level%10)      JoinLevel(g,p) → g*10+p
```

后台 C 服务按此解析任务优先级，**存储格式必须原样保持**（契约 C-28）。
界面上拆成两个控件录入，提交时合成。
**改了组级别要联动重算组内所有用户的任务优先级**（BR-97）——
旧版这里用的是 `if` 而不是循环，只处理了第一个用户（D-43）。

**★ 功能权限 13 项**，一一对应 `usergroup` 的 13 个列，界面按三组排列
（资源管理 / 任务管理 / 系统）。完整对照见附录 B。

**其它**
- 系统组（id=1）恒有全部权限：`UpdateGroup` 里卡死，列表与表单里也**恒按「全部勾上」显示**
  （库里某一位可能是 0，但组里的人走 IsAdmin 直通，照库显示反而像少了一项）。
- 删组 = 删掉组内全部用户及其名下所有数据，先看 `delete-preview`。
- 只改描述时**不校验组级别** —— 否则 level 为 1/3/5 的旧数据行连描述都改不了。

### 7.7.3 注册服务 `/user/register` — 权限 `serverpriv`

**接口**：`GET /api/register/status`（**公开**，登录页据此判断要不要跳过去）、
`GET /api/register`、`POST /api/register`、`POST /api/register/trial`

**规则**

# 8. 前端约定

## 8.1 路由与菜单：**后端下发，前端不写死**

登录后拿 `GET /api/menu/list`，动态注册路由。没权限的页面**根本不在树里**，
地址栏手敲也进不去（前端没有那条路由）。
页内按钮的可用性另由 `GET /api/auth/buttons` 下发（见 5.3）。

菜单项的 `component` 字段就是 `src/views/` 下的路径，例如
`/typed/tts/index` → `src/views/typed/tts/index.vue`。

## 8.2 http 封装（`src/api/index.ts`）

- `baseURL` **留空**。接口路径里的 `/api` 前缀已经写在各 `api/modules/*.ts` 里
  （如 `/api/login`），baseURL 再补一次会变成 `/api/api/login`，
  只能靠代理剥掉一层来抵消 —— 前缀在三个地方各写一遍，极易改错。
- 请求拦截器加 `x-access-token`；响应拦截器见到 `code === 401` 跳登录。

**⚠ 全站最容易踩的一个坑：`http.delete` 的第二个参数是 query，不是 body。**

```ts
http.delete(url, { ids })                  // ❌ 变成 ?ids=1&ids=2，后端读 body 得到 EOF
http.delete(url, {}, { data: { ids } })    // ✅ 放进请求体
```

后端删除接口一律从 JSON body 读 `ids`。写错的表现是
`40001 请求参数格式错误: EOF` —— 上一轮一口气查出 8 个这样的接口。

## 8.3 ProTable

全站表格都用 `components/ProTable`，`columns` 配置驱动。要点：

- `requestApi` 传接口函数，分页/排序/搜索参数由它自己拼。
- **`tableKey`**：列设置存 localStorage 时用的表标识，默认取当前路由 path。
  **一个页面里有两张以上表格时必须显式传**，否则它们共用同一份列设置。

## 8.4 界面配置存本地

- **列设置**（显示/排序两个开关）→ `localStorage`，键 `htweb:cols:<tableKey>`，
  只存**用户改过的值**，不存列定义 —— 后端加列/改列名都不会被旧记录带偏
  （记录里没有的列走代码默认值，代码里删掉的列套用时忽略）。
  实现见 `utils/tablePrefs.ts`，所有读写都包了 try/catch（隐私模式下 localStorage 会直接抛）。
- **布局/主题/侧边栏**走 pinia 的 `geeker-global`，本来就落 localStorage，退出登录也不清。

## 8.6 顶栏的服务器时钟

顶栏右侧、图标组左边那个走秒的钟显示的是**服务器**的时间
（`src/layouts/components/Header/components/ServerClock.vue`）。

广播系统里所有任务都按服务器的钟走。运维的笔记本慢两分钟，看着「10:00 的早读没响」，
其实是服务器上才 9:58 —— 这个钟就是为了当场排除这种误会。

- **走秒靠本地，对时靠服务器**：每 **3 分钟**拉一次 `GET /api/time/now`，
  记下 `skew = 服务器毫秒 - 本地毫秒` 和服务器时区偏移，中间每秒重算一次显示值。
  3 分钟里只有一次请求；标签页被挂到后台、`setInterval` 被节流也只是刷得慢，
  再次可见时显示的仍是对的 —— 值是**算出来**的，不是累加出来的。
- **单开一条轻接口**，不复用 `GET /api/time`：后者要探系统时钟能力（可能 fork sudo）、
  查两次库，每 3 分钟付一次那个代价没有道理。
- **⚠ 排版用 `getUTC*` 加服务器时区偏移，不用 `getHours()`**：
  `new Date(服务器毫秒)` 只定死「哪一个瞬间」，`getHours()` 取出来的是**浏览器所在时区**
  的那个小时。服务器在东八区、笔记本在 UTC 时，服务器墙上 15:00 这里会显示 07:00 ——
  同一个瞬间，但不是服务器的钟面，而钟面才是任务时间表对齐的东西。
  已按 UTC / 纽约 / 东京三个浏览器时区验过，显示的都是服务器钟面。
- **首次同步成功之前什么都不显示**：那时唯一能拿到的是浏览器时间，
  把它当服务器时间摆出来，正好制造了这个组件要消除的误会。
  同步失败就接着用上一次的 skew 走，超过 **7 分钟**（错过两轮）把颜色改成警示色。
- 这里**不显示服务器和浏览器差了多少秒** —— 那是「时间设置」那一页的事
  （它连数据库的钟一起比），顶栏塞进去只会让人以为哪边出了故障。

## 8.7 Element Plus 的两个已知坑

- **删除预览弹窗关掉后 DOM 还在**：写自动化断言时统计 `.el-table__row` 会把
  隐藏弹窗里的行也算进去，要限定到可见容器（`.table-box .el-table__row:visible`）。

# 9. 与后台 C 服务的通知协议

**UDP**，发往 `notify.host` : `serverbaseparam.webport`（`notify.port = 0` 时运行时读库）。
发失败**只记日志不回滚**（库已经改完了，回滚更糟）。

**★ 报文格式照抄旧版 `do.php` 的实际调用点，不是照手册。** 三种形态混用会让后台解析失败：

```
task?state=3&id=X                启动（无 type）
task?state=2&id=X&type=2         停止 / 暂停 / 恢复 / 删除（带 type）
task?state=4&id=X&volume=V       新增 / 修改（带 volume）
```

**任务类 state**

| 值 | 含义 | 值 | 含义 |
|---|---|---|---|
| 2 | 停止（`&type=2`） | 6 | 删除（`&type=2`） |
| 3 | 启动（无 type） | 15 | 离线数据有变更（`id` 恒为 0） |
| 4 | 新增（`&volume=`） | 22 | 暂停（`&type=2`） |
| 5 | 修改（`&volume=`） | 23 | 恢复（`&type=2`） |

⚠ 手册说停止写 `state=0`，**旧代码实际写的是 2**；暂停/恢复的 22/23 手册根本没提；
新增/修改要带 `&volume=` 手册也没提。这些差异都会让后台收不到或误解通知。

**终端类 state**

| 值 | 含义 | 值 | 含义 |
|---|---|---|---|
| 0 | 停止终端 | 7 | 下发密码（id 用 `{}` 包裹，带 `&pwd=`） |
| 1 | 启动终端 | 13 / 14 | 开始 / 停止录音 |
| 2 | 终端已删除 | 27 | 线路检测（id 用 `{}` 包裹） |
| 3 / 4 | 对讲开 / 关（带 `&speech=`） | 30 | 同步时间 |
| 5 | 音量（带 `&volume=`） | 32 | 删除任务终端 |

⚠ 粒度必须原样保留：手册说「逐个终端发」，但录音、线路检测、密码这几条
**旧代码是把整串 ID 一次发出去的**。

**其它报文**

```
project?state=<1启用|0停用>&name=<方案名>      作息方案启停
file?state=<n>&id=<folderId>                  媒体目录变更
server?state=1                                服务器重启
```

# 10.5 AI 助手（业务域十四）

一个浮在所有页面之上的对话框：用中文说一句「把春季作息明天8点的早读挪到9点」，
它把这句话变成对广播系统的实际操作。收起时是右下角一个球。

## 从哪来的

一比一复刻 `ai_speaker_project`（2ada1e9 / T124）那套 Python 实现，
但**执行层全部换成直连数据库**：原来是 HTTP SDK 打到广播服务器上，
现在 htweb 自己就坐在 audioserver 上，走 tao 已有的 service 层。

## 分工：模型只做推理，别的全在 Go

```
NLU（Python 旁挂，同机 127.0.0.1:5013）   文本 → intent + slots，只做推理
                                          不碰数据库、不知道广播系统的存在
本包（Go，internal/assistant）            消歧、鉴权、执行、审计、回话
```

这么切有两个直接好处：

- **写操作全在 Go 这一侧**，因此全都走 tao 的权限体系与审计，
  不存在"模型那边偷偷改了库"这种事。
- **会话状态落在数据库**（原实现挂在模型进程里），进程重启不丢，
  多个 htweb 实例也能共享。

代价是模型那边的 `session_manager.py` 整层要在 Go 重写一遍，见
`internal/assistant/session_resolve.go`。

## ⚠ 助手只认中文，英文界面下也是

面板的界面文字（标题、按钮、提示、指令历史）走 i18n，切英文跟着变。
**例句与回话不翻**，这是判断不是漏：

- 例句是「点一下就原样发出去」的指令，而 NLU 只认中文 ——
  翻成英文点一下发出去的是一句它听不懂的话，比不给例句更糟。
- 回话是按 SHA1 从中文变体池里**稳定挑**出来的（`internal/assistant/reply.go`），
  连标点和「搞定啦」这类前缀都参与组句，`reply_test.go` 拿原 Python 实现的
  输出当基准。换语言等于重做一套回话引擎，不是翻译。

所以中英两版都明说一句「助手只认中文指令，回话也是中文」（`ai.chineseOnly`），
免得英文用户以为是坏了。真要做英文助手，要动的是 NLU 的训练数据和
`reply.go` 那套变体池，跟界面翻译是两件事。

## 写操作一律走页面用的那个 service

助手不自己写 `UPDATE`。启停任务走 `task.Control`、方案启停走 `bell.SetState`、
终端启停走 `terminal.SetRunning`、分区走 `zone.*`。理由是这些 service 里
已经把守卫和通知报文做全了：

| 动作 | 走谁 | 白拿的守卫 |
|---|---|---|
| 启停任务 | `task.Control` | 归属、方案停用不许启动、没媒体/没终端不许启动、功放子任务同步、通知报文 |
| 方案启停 | `bell.SetState` | 子任务范围、`project?state=` 报文 |
| 方案删除 | `bell.Delete` | 连带清 `terminalkeymaptask` / `offlinetaskofterminal`（旧版漏清，D-184） |
| 终端启停 | `terminal.SetRunning` | 要求在线、停止时连 `taskstate` 一起清 0（BR-144） |
| 分区 | `zone.*` | 重名用命名锁串起查重与写入（表上没有唯一索引） |

绕过它们自己写 UPDATE 等于把这些守卫**悄悄**丢掉：用对话启动一条没有终端的
任务不会报错，只会让后台空转。

## 「1:1 复刻」是怎么保证的

回话措辞、时间解析、名称匹配这几块的验收标准只有一条：**同样的话，
算出同样的结果**。做法是黄金用例 —— 期望值由 `nlu/golden/` 下的脚本
**跑原实现生成**（能 import 的直接 import，不能的用 `ast` 按源码位置把函数体
原样切出来 exec），不是照着代码推的。

```
gen_reply_golden.py           27 条  写操作三类回话（成功/追问/失败）
gen_terminal_reply_golden.py  33 条  终端与分区意图的回话
gen_schedule_reply_golden.py  16 条  作息方案相关回话
gen_cancel_reply_golden.py    11 条  取消相关回话
gen_time_golden.py            20 条  中文时间范围解析
gen_match_golden.py           12 条  任务与查询窗口的比对
gen_anchor_golden.py          45 条  时间锚点与星期/时刻位移
gen_schedule_templates.py      —     作息模板蒸馏（不是用例，是数据）
```

这套用例抓到过真问题：Go 与 Python 选出了不同的回话模板，根因是
Python 组种子时写的是 `str(part or "")`，而 **0 在 Python 里是 falsy**，
所以计数为 0 的那一位在种子里是空串不是 `"0"`。看着像 bug，
但它已经决定了现网每一句回话选的是哪个模板，所以照搬（见 `reply.go` 的 `seedNum`）。

## 几处**有意与原实现不同**的地方

都写在对应文件的头注释里，这里汇总：

1. **永久取消 = 停用，不是删除**（`exec_cancel.go`）。原实现是把任务删掉。
   这套库里删任务会连带删掉媒体清单、终端清单、功放/LED 子任务，且没有撤销。
   「取消」在中文里不等于「删除」——用户说"以后都别放了"是别响，
   不是"从系统里抹掉"。这套库里恰好有精确表达"别响"的 `projectstate`。

2. **删方案要先问一句**（`exec_schedule.go`）。原实现不问。删方案会连同底下
   所有任务一起没，没有撤销；页面上要勾选、点按钮、再确认一次，
   对话里一句话说错就没了。而且**先把要删的东西说清楚再问** ——
   只问"确定吗"，用户是在对一个自己没看见的东西点头。

3. **影子任务的星期掩码**（`exec_move.go`）。原实现写 `execmode = 0`。
   这套库里 `exemodel = "0000000"` 的意思是「手动」，后台不会自动执行它 ——
   影子建了却永远不响，而用户已经被告知"改到那天执行"了。
   改成把目标那天的星期位打开，起止日期都钉成那一天。

4. **时长不按 `timelengthtype == 2` 判分钟**（`exec_task.go`）。
   这套库里 2 是「按循环次数」，1 才是按秒。照抄会把"放 3 遍"算成"放 3 分钟"。
   改用这套库里权威的来源：`endtime - playtime`。

5. **待确认的重问有上限**（`pending.go`）。待确认在 NLU 之前截住这一轮，
   只要它挂着，用户说什么都会被当成在答那个问题 —— 实测确认了这个坑。
   问过一遍还没答上来就放手，让这一轮正常走 NLU。
   原实现在周几消歧那一支里就有同一个模式的解法。

6. **模板媒体按名字找，不按 id**（`exec_create_schedule.go`）。
   模板里的 `mediaid` 是原库的 id，在这套库里指向完全不同的东西。

## 一次性操作落在 enabletask 上

「取消明天早读，就这一次」不是把任务改掉，而是排两条**启用计划**：
到时刻前 30 秒把它置停用，到结束时刻再置回启用。这不是我们挑的做法，
原实现的注释就写着「一次性取消：通过 enabletask 定时禁用/恢复」，
而 `enabletask` 正是这套库里「启用管理」那张表。

好处是运维在「启用管理」页面上看得见、改得动、删得掉 ——
助手排下去的东西不该是只有助手自己知道的黑箱。

⚠ `enstate` **0 = 启用、1 = 停用**（与 `task.projectstate` 一致，
与 `holidaytime.projectstate` 相反）。搞反的后果是"取消"变成"到点开始播"。

停用计划排下去了、恢复计划没排上，这些任务会**一直停着** —— 这是最坏的失败，
所以第二条失败时会把第一条删掉，回到什么都没发生的状态。

`web/src/components/AiAssistant/`，挂在 `layouts/index.vue`。

# 10.6 开发者接口（业务域十五）

对外的 HTTP 接口，给第三方系统（教务、门禁、消防告警）直接调。
**对外那份文档在《开发者接口文档》**，这里只写内部实现要点，别把两份写重。

## 与 `/api` 的三点不同

| | `/api`（界面用） | `/openapi/v1`（对外） |
| --- | --- | --- |
| 凭据 | `x-access-token`，内存会话、8 小时、重启即失 | `X-API-Key`，落库、长期、可单独吊销 |
| 寻址 | 编号 | **编号优先**（只有编号唯一），名字也认 |
| 路径 | 随页面改 | 带版本号，只增不改 |

第一条是这套接口存在的**根本理由**：界面的令牌存在 `auth.Manager.sessions` 里，
htweb 一重启全部失效。人重新登录一下就好，程序不行 —— 服务半夜重启，
第二天早上第三方的定时广播全哑，而且没人知道。

## 权限不是第二套

认证通过后注入的是**同一个 `auth.User`**（`auth.WithUser`），
之后权限位、可见范围收敛、备机只读全部照旧生效。
一把密钥能干什么，完全等于它归属的那个 `book_admin` 账号能干什么。

发密钥必须**登录界面**动手（管理接口挂在 `/api/openapi-keys`，要 `userpriv`）——
允许拿密钥发密钥的话，一次泄露就永远收不回来：吊销 A 的时候 A 发的 B 还活着。

## 新建了两张表

| 表 | 用途 |
| --- | --- |
| `api_key` | 密钥。存 sha256，明文只在新建那一次的响应里出现 |
| `api_play` | 立即播放的临时任务登记（`task` 表不能加列做标记，R1 红线） |

两张都在 `db/openapi_tables.sql`，都已加进恢复出厂的清空清单
（`serverparam/factory.go`）—— 恢复出厂 = 这台机器要重新交付，
之前发出去的密钥必须全部作废。**不动任何旧表。**

`api_play` 不复用助手的 `assistant_runtime_play`：那张表前端「助手时间线」
直接读，混进来的话用户会看到自己从没说过的播放记录，而且他说一句「停止播放」
会把第三方系统正在放的东西停掉。

## 寻址层与助手的关键区别：**不做模糊匹配**

助手面对的是人说的话（「A101」要对到「A101教室音箱」），猜错了人当场能纠正；
开发者接口面对的是机器，猜错了没有人会看见，错误的广播会一直发下去。
所以只精确匹配：对不上就报错并列出相近的名字，**绝不替调用方挑一个**。
一组引用里有一个解析不了就整体失败，不做「能播几个算几个」。

## 业务逻辑一行都没重写

动作全部委托给页面用的那几个 service（`task` / `bell` / `terminal` / `zone` /
`media` / `enable`）。这一层只做三件事：认证、把名字变成 id、把「人话」参数
翻成 service 的入参。

`internal/openapi` 里自己写 SQL 的地方只有几处，每处都在注释里写了理由，
最主要的一处是媒体列表：`media.List` 是**按目录**列的（界面上永远是先进目录
再看里面），而第三方是按名字找歌，不知道也不该知道它在哪个目录。

## 几个「猜错的代价」定下来的默认值

| 场景 | 默认 | 为什么 |
| --- | --- | --- |
| `/tasks` 的 `weekdays` 留空 | 手动（`0000000`） | 默认成「每天」的话，少写一个字段就变成每天全校广播 |
| `/schedules` 的 `weekdays` 留空 | 周一到周五 | 作息方案天然是上课日打铃，建一个永不触发的方案没有意义 |
| 排期任务没给优先级 | 该账号能用的**最低**一档 | 优先级数字小的赢。默认成最高会压过消防疏散广播 |
| 立即播放的优先级 | **最高**（10） | 它是调用方此刻要求的，给低了会被排期任务压住 —— 收到 200 却没声音 |
| 时长算不出来 | 60 / 300 秒兜底 | **绝不落 0**：`timelength=0` 是「不限时长」，会一直播下去 |
| 分页 `pageSize` | 20，夹取 `[1,200]` | 不能用界面那套「不认识的尺寸回落到 18」—— 传 30 变 18，翻页会漏数据且毫无察觉 |

## 操作日志

写操作的标签都带「开发者接口：」前缀（`auditLabels`）。同样是新建任务，
界面上点的和第三方系统调的，追责时是两回事；混成一个名字就分不出这一下是谁干的。

密钥的最后使用时间与来源 IP 记在 `api_key` 上（写入带一分钟节流）。
⚠ 来源 IP 取 `X-Forwarded-For` 第一段，**只用于台账展示，绝不用于权限判断** ——
那个头是调用方可伪造的。

## 认证失败说得少

密钥不存在 / 已停用 / 已过期，对外一律是同一句「密钥无效」。
真实原因只进服务端日志 —— 「这个前缀存在但停用了」就是在告诉试密钥的人
前缀猜对了。同理，「这把密钥不是你的」也回「不存在」，
否则调用方能枚举出别人有几把密钥。

## 全部功能接口：让密钥走同一条鉴权中间件

**「用密钥能做什么」必须等于「这个账号在界面上能做什么」。**
所以密钥不另建一套路由 —— `auth.Manager.require` 里在会话解析失败后
再看 `X-API-Key`，认过之后注入的是**同一个 `*auth.User`**。
一条中间件、一个身份，权限位与可见范围自然一致。

另建一套的话就是另一套鉴权代码，两套迟早分叉，而分叉的表现是
**接口上比界面多一条口子**，没有人会注意到。

### 暴露面归暴露面：keyGate 白名单

「谁是谁」和「哪些接口对外开放」是两件事。后者由 `cmd/htweb/openapi_expose.go`
的 `exposedGroups` 白名单管，`keyGate` 在路由最外层执行。

为什么是白名单：漏写一条白名单 → 「这个接口暂时用不了」，有人会来问；
漏写一条黑名单 → 「恢复出厂能被第三方调」，没有人会来问。代价差着数量级。

⚠ **`keyGate` 必须用 `auth.WillUseAPIKey(r)` 判断，不能用 `auth.ViaAPIKey(ctx)`。**
它跑在鉴权中间件**之前**，那时上下文里还没有身份 —— 第一版就栽在这儿：
挡板装了，但装在了它要挡的东西前面，恢复出厂、发密钥、备份恢复、助手对话
全都能用密钥调通，而且不报错、不留痕。`openapi_gate_test.go` 专门盯着这条。

### 三个防漂移的测试（`openapi_expose_test.go`）

| 测试 | 盯住什么 |
| --- | --- |
| `TestEveryAPIRouteIsExposedOrDenied` | 每条 /api 路由都得表态：要么开放、要么在 `keyDenied` 里写明理由 |
| `TestNoStaleEntriesInExposureLists` | 清单里不能有指向已删路由的记录（会出现在平台上，调了 404） |
| `TestDenyReasonsAreWritten` | 不开放的理由不能敷衍 —— 写不出理由的多半该开放 |

它们直接读 `main.go` 的源码取路由表：routes() 就是这个系统的路由注册处，
想拿到这张表要么把它跑起来（要数据库、配置、一整个 app），要么读源码。
正则失效时会因为「一条都没扫到」而失败，不会假通过。

## 接口调用平台（「像 Swagger 那样」的那一页）

`开发者接口 → 接口调用平台`。左边接口目录、右边参数说明 + **能当场调一次**。

平台上分两段列：

- **常用接口**（15 条，`internal/openapi/spec.go` 的 `Catalog()`）——
  名字寻址、参数是人话、路径带版本号，逐条写了参数说明
- **全部功能接口**（213 条，`cmd/htweb/openapi_expose.go` 的 `APICatalog()`）——
  界面用的那套，覆盖每个页面功能，`Freeform: true`，平台上给可编辑路径 +
  自由 JSON 请求体

分两段而不是混着列：它们的定位不同（一个是不会变的合同，一个跟着界面走），
混着列会让人把集成建在一条会随改版变化的路径上。

全功能那 213 条**刻意不写逐参数说明** —— 逐条抄一遍势必抄错、也跟不上改动，
而一份看起来完整但有错的参数说明，比明说「这里没有」更坏。

### 示例里的每个值都要解释

`Endpoint.Returns` 逐字段解释响应示例。光贴一段 JSON 是不够的：
`"priority": 8` 里的 8 是什么？数字大就优先吗（不是，反过来）？
`"weekdays": [7]` 的 7 是周日还是周六？**猜错了不会报错，只会在错的那天广播。**

`Spec.Codes` 是全站通用的取值对照表（平台右上角「取值对照表」按钮）。
它主要为全功能那一组服务 —— 那些接口返回的是库里的原始值，其中四个是反直觉的：

	projectstate  0 才是启用
	israndomplay  0 是随机、1 是顺序
	priority      数字**小**的优先级高
	exemodel      7 位掩码，**周日打头**

⚠ 表里每一条都对着源码核过（常量、stateText、SetRunning、ok112 那条判
「今天该不该响」的 SQL），不是照记忆写的。改之前先去看对应的定义。

两个测试盯着它们（`internal/openapi/query_test.go`）：
`TestEverySampleIsExplained`（给了示例就必须逐字段解释 —— 漏写没有任何症状，
平台上少一块而已）、`TestCodeTablesAreComplete`（四个反直觉字段必须在表里
且必须标红）。

### 任务接口的字段覆盖

`POST /openapi/v1/tasks` 必须覆盖 `task.Input` 的**每一个**业务字段。
早先只开放了 17 个概念、漏了 6 个（间隔播放、当天停用、发送模式、
本地优先、LED 字幕、终端区域掩码）——用户看示例时发现的。

漏一个字段**没有任何症状**：接口照常回 200，任务也建出来了，只是那一项
永远是默认值。集成方发现不了，我们也发现不了。所以
`TestCreateTaskCoversEveryBackendField` 拿一张「后端字段 → 接口字段名」的表
比对**字段说明**（不是 Go 结构体 —— 结构体里有了但没写进说明，
对集成方而言仍然等于不存在），并要求示例里出现主要字段。
`TestTaskDetailMirrorsCreateFields` 保证详情能把这些读回来。

新增 `GET /openapi/v1/tasks/{ref}`：没有它，集成方建完任务只拿到一个 id，
没法确认自己填的写进去没有，只能去界面上人眼看 —— 而那正是集成要避免的事。

⚠ **局部更新的语义要一致到底。** LED 字幕原先跟界面一样「没传就当取消」，
于是「只改个音量」的请求会把字幕删掉 —— 界面每次提交整张表单，
而这个接口是局部更新的。调用方没提过 LED，也就不会想到去看它。
实测撞出来的，已改成「不传保持原样，要取消得明确传空正文」。

### 一处改名：powerOn → running

早先终端 DTO 里把 `devicestate` 叫成 `powerOn`（「已开机 / 已关机」）——
是错的。那一列由 `PUT /api/terminals/start|stop` 控制，是**运行开关**，不是电源；
断电的终端表现为 `netstate` 离线。叫 powerOn 会让集成方以为能靠它判断通没通电。
**名字错的字段比没有这个字段更坏**，所以趁没有真实集成方之前改掉，
措辞也与界面终端列表对齐（已启动 / 已停止）。

**目录来自后端**（前端只负责渲染）。
前端写死一份清单的话，后端改了参数它不会跟着变 —— 而它看起来还是对的，
调用方照着一份过期的文档调，得到的错误跟文档对不上。

⚠ **加接口时 `Catalog()` 里也要加一条。** 漏了不会报错，只是这个接口对外
等于不存在 —— 没人知道它能用。

**同一个目录还渲染出标准 OpenAPI 3.0 文档**（`OpenAPIJSON()`，界面上「下载
OpenAPI 文件」按钮）。我们自己那个界面是给人看的（中文、带「为什么」、能试），
这一份是给工具看的（Postman / Apifox / 代码生成器）。两份同源，不会分叉。

**「试一试」是浏览器直接打 `/openapi/v1`，不经后端代理。** 这样点出来的结果和
集成方在他自己机器上得到的完全一样 —— 同一条认证路径、同一套权限、同一份错误。
走代理的话「代理用登录身份还是用密钥」就成了说不清的问题，而「在平台上能跑、
在你那儿跑不通」是最难查的一类问题。代价是这一页要用户粘一把密钥，
这不是缺陷而是必然：服务器只存摘要，谁也拿不回明文。
（刚发完密钥的那一次会经 sessionStorage 自动带过来，关掉标签页就没 ——
不落 localStorage，密钥长期躺在硬盘上比让人多粘一次糟得多。）

⚠ 那一页用**原生 fetch**，不走项目的 axios 实例：后者会自动带登录令牌、
401 时还会跳登录页。这一页要的恰恰是「只用密钥」，密钥无效时就该原样看见 401。

**两页的权限不一样，是有意的**：接口调用平台只要登录（它是说明书 + 试一试，
本身改不了任何东西，而对接常常是没有用户管理权限的开发同事在做）；
开发者密钥要 `userpriv`（发一把密钥等于把某个账号的权限借出去）。

# 11. 怎么验收

上一轮全量验收的做法（见《模块测试与ok112对照-验收记录》），照这个来：

1. **全站扫描**：逐页 `goto`，收集 `pageerror` / `console.error` / 非 200 的 `/api` 响应。
   27 个页面应当全部干净。
2. **界面上的增删改往返**：每个模块在真界面上建一条 → 查库核对 → 改一次 → 再核对 →
   删掉 → 确认连带数据也没了、没有孤儿行。
3. **权限矩阵**：至少三个身份（admin / 有部分权限的操作员 / 只读查看），
   核对菜单可见性、按钮置灰、写接口是不是回 40301、可见范围对不对。
4. **接口层往返**：树/掩码这类界面上不好点的，直接打接口，重点核对级联写入
   （`task` / `mediaoftask` / `terminaloftask` / 子任务）。
5. **收尾**：测试数据全删干净，核对没有孤儿行。

# 附录 B · 权限位速查

`usergroup` 的 13 列。**列名与含义对不上，别按字面猜**（R2）。

| 界面上的名字 | 列 | 管住什么 |
|---|---|---|
| **资源管理** | | |
| 终端管理 | `terminalpriv` | 终端管理页全部写操作（参数/音量/启停/密码/开关/快捷键/寻呼组/快捷任务/终端替换/删除）；云广播→音乐传输；时间设置→下发校时 |
| 分区管理 | `terminalgrouppriv` | 终端分区；噪声检测→噪声设备、声场分区 |
| 报警管理 | `alarmgrouppriv` | 报警分区、报警映射 |
| 文件管理 | `mediapriv` | 上传媒体、删除媒体、清空目录内媒体 |
| 文件夹管理 | `folderpriv` | 新建 / 改名 / 删除媒体文件夹 |
| **任务管理** | | |
| 文件广播 | `taskpriv` | 文件广播的增删改与启停、任务分组 |
| 作息方案 | `bellpriv` | 作息方案与打铃条目；节假日管理 |
| 终端功放 | `powerplay` | 终端功放任务 |
| 采播管理 | `admpriv` | 采播任务 |
| 文字语音 | `ttspriv` | 文字语音任务；启用管理 |
| **led播放** | **`telephonepriv`** | led播放 任务；LED 任务目录；LED 屏设备。⚠ 旧版这列是「电话广播」，新版改挂 LED |
| **系统** | | |
| 遥控管理 | `serverpriv` | 遥控任务；云广播→任务传送；基础配置→服务器信息、时间设置里的 NTP/GPS；用户管理→注册服务 |
| 用户管理 | `userpriv` | 用户与用户组 |

**超出 13 位之外的两道门**
- **超级管理员**（`book_admin.id == 1`）：日志、日志保留期、备份还原、重启、恢复出厂、
  看板三块配置、离线全部清除。
- **IsAdmin**（`usergroupid == 1`）：直通所有权限位 + 看得到所有人的数据。
