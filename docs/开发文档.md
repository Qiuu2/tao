# 1. 系统是什么

## 1.1 定位

**IP 数字网络广播系统**的管理后台。一所学校 / 一个园区里挂着几十上百台
网络广播终端（音柱、功放、LED 屏、话筒），这套 web 负责**配置和调度**它们：
建任务、排作息、传媒体、分权限、看日志。

## 1.2 三层分工（必须先搞清楚）

```
   ┌────────────┐   HTTP/JSON    ┌─────────────┐   直接读写    ┌──────────┐
   │  新版 Web  │ ─────────────▶ │   htweb     │ ───────────▶ │ MariaDB  │
   │ (Vue3 SPA) │ ◀───────────── │  (Go 后端)  │ ◀─────────── │audioserver│
   └────────────┘                └──────┬──────┘              └────┬─────┘
                                        │ UDP 报文                 │ 轮询
                                        ▼                          │
                                 ┌─────────────┐ ◀────────────────┘
                                 │ 后台 C 服务  │
                                 └──────┬──────┘
                                        │ 私有协议
                                        ▼
                                 ┌─────────────┐
                                 │  硬件终端    │ 音柱 / 功放 / LED / 话筒
                                 └─────────────┘
```

- **htweb 只管数据库**。建一条任务 = 往 `task` 等表写几行，**不直接指挥终端**。
- **后台 C 服务**是真正的执行者：它读数据库、按时间表推流、跟终端讲私有协议。
- htweb 改完库之后，往 C 服务发一个 **UDP 报文**告诉它「有东西变了」（见第 9 章）。
  发失败只记日志，**不回滚业务** —— 库已经改完了，回滚更糟。
- 所以：**本地没有 C 服务和终端时，界面全都能点，但不会真的响。**

## 1.3 与旧系统 ok112 的关系

`ok112/` 是上一代 PHP 系统（Apache + PHP + 同一个 `audioserver` 库）。

- 它是**唯一的业务事实来源** —— 需求文档不存在，业务规则全在它的 PHP 和模板里。
- 新版**逐页对着它重写**，行为一比一对齐，缺陷则修掉（缺陷编号 D-xx 见缺陷清单）。
- **代码一行都不抄**，只作对照。
- 两套系统**共用同一个数据库**，同时在线。这就是下一章那条最重要的红线的由来。

# 2. 不可逾越的约束（红线）

违反其中任何一条，都会在现网出事，而且大概率是「几百个喇叭在不该响的时候响」这种事故。

## R1 · 不动旧表；新表可以建

> **2026-09-08 调整**：原来是「零 DDL，一张表都不许建」。为了给 AI 助手的状态
> 找地方放，用户放开了「建新表」。**改旧表仍然一律禁止。**

```
✅ 可以新建表（表名加前缀，与旧库那 89 张零冲突）
❌ 现有 89 张表一个字节都不动：不加列、不改类型、不加索引、不改字符集
```

不许改旧表的原因（三条里任何一条单独成立）：

1. 旧系统 ok112 还在跑，同一个库。加一列，旧版的 `SELECT *` + 按下标取值的老代码就会错位。
2. 后台 C 服务是编译好的二进制，按固定列序读数据。表结构一动，它的行为无法预测。
3. 数据库账号本身就**没有 DDL 权限**（只给 SELECT/INSERT/UPDATE/DELETE），这是最后一道锁。
   建新表要用另一个有 DDL 权限的账号手工跑一次建表脚本 —— **程序自己永远不建表**。

**推论一**：零碎的界面状态仍然不进数据库，照旧走本地 / 文件：

- 表格列设置 → 浏览器 `localStorage`（`web/src/utils/tablePrefs.ts`）
- 日志保留期 → 服务端 JSON 文件（`config.logs.settings_file`）
- 看板三块配置 → 服务端 `dashboard.json`

**推论二**：成规模、要查询、要并发安全的状态才值得建新表。
目前只有 AI 助手那 6 张（`assistant_*`，见 `db/assistant_tables.sql`
与《数据库文档》第 8 章）。

**推论三**：⚠ 每加一张新表，**有两处必须同步改**，否则会静默坏掉：

1. `internal/serverparam/factory.go` 的三张清单之一 ——
   恢复出厂遇到不认识的表会**拒绝执行**（这是有意的保险，不是 bug）。
2. 备份包的结构指纹会变。当前库比备份包**多**出来的表不再拦
   （只提示，恢复时不动它们）；备份包里有、而库里没有的，照旧拦死。

## R2 · 列名不等于列义

`usergroup` 那 13 个权限列，列名和真实含义**对不上**，是旧版留下的。
按字面意思理解会把现网所有用户组的权限悄悄挪位。完整对照见附录 B 和《数据库文档》。
最容易踩的四个：

| 列 | 字面像什么 | 实际是 |
|---|---|---|
| `serverpriv` | 服务器权限 | **遥控管理** |
| `admpriv` | 系统维护 | **采播管理** |
| `powerplay` | 强插播放 | **终端功放** |
| `telephonepriv` | 电话广播 | **led播放**（新版改挂的，见 7.4.6） |

## R3 · 反直觉的取值必须原样保留

| 地方 | 反直觉在哪 |
|---|---|
| `task.projectstate` | **0 = 启用，1 = 停用**（数据库列注释是反的） |
| `usergroup.level` | 是**两位复合值** 10~109：十位 = 组级别，个位 = 任务优先级基数。C 服务按此解析 |
| `task.tasktype` | 列注释「1-作息 2-文件 3-采播 4-电话 5-功放」不全，实际还有 15/17/19（文字语音）、24/30（LED）、9（功放子任务） |
| LED 任务的「独立 / 附属」 | **不看 tasktype**（都是 30），看 `sec_task_id` 是不是 0 |
| `ledsentence.mediaid` | 存的是 **`media.id`**，不是 `ledsentence` 自己的 id |
| 通知报文的 state | 手册说停止写 0，旧代码实际写 2；暂停/恢复的 22/23 手册根本没提 |

## R4 · ok112 目录只读

`ok112/` 保留在仓库里作对照，**不改、不删、不清理**。
（里面有明文口令和真实数据文件，这是已知的，按要求保持原样。）

## R5 · 通知报文格式照抄旧版调用点

不是照手册写，是照旧版 `do.php` 里**实际发出去的那一行**写。
差一个 `&type=2` 后台就解析不了。见第 9 章。

# 3. 技术选型与工程结构

## 3.1 选型

| 层 | 选型 | 为什么 |
|---|---|---|
| 后端 | **Go 1.24 + 标准库 `net/http`** | 单文件二进制，目标机器不需要装运行时；`go 1.22+` 的 ServeMux 已支持 `METHOD /path/{id}` 模式，不需要路由框架 |
| 数据库访问 | **`database/sql` + go-sql-driver/mysql，手写 SQL** | 零 DDL 前提下 ORM 的迁移能力是负担；旧库的列名列义还常常对不上，手写 SQL 反而看得清 |
| 配置 | YAML（gopkg.in/yaml.v3） | |
| 前端 | **Vue 3 + TypeScript + Vite 6 + Element Plus** | 基于 Geeker-Admin 模板起的 |
| 前端状态 | Pinia（+ persistedstate） | |
| 包管理 | pnpm | 锁文件是 pnpm 的 |

后端**直接依赖只有两个**（mysql 驱动 + yaml），这是有意的：这台机器要长期运行，
依赖越少越不容易在升级时炸。

## 3.3 后端分层规矩

```
handler (cmd/htweb/*_handlers.go)
    ├─ 解析请求参数 / JSON
    ├─ 取当前用户 auth.From(r.Context())
    ├─ 调 service
    └─ httpx.OK / httpx.Fail

    ├─ 校验业务规则
    ├─ 事务
    ├─ 写库
    └─ 发通知
```

**handler 里不写 SQL，service 里不碰 http.Request** —— 这条没有例外。

一个模块的典型文件切分（以 `internal/task` 为例）：

```

control.go   启动 / 停止 / 暂停 / 恢复 / 启停 / 音量
copy.go      复制
folder.go    任务分组
ledsub.go    LED 字幕子任务
picker.go    选择器（媒体树 / 终端树的数据源）
```

# 4. 后端通用约定

## 4.1 统一响应体

```json
{ "code": 200, "msg": "ok", "data": { } }
```

- **HTTP 状态码永远是 200**（除非是真的网络/服务器错误），业务结果看 `code`。
  这是 Geeker-Admin 前端拦截器的约定，改不得。
- 失败：`{"code": 40001, "msg": "请求参数格式错误: EOF", "data": null}`

错误码表（`internal/httpx`）：

| 码 | 含义 | 前端表现 |
|---|---|---|
| 200 | 成功 | |
| 40001 | 请求参数格式错误 | 弹错误提示 |
| 40002 | 名称已被占用 | |
| 40003 | 层级超限（目录树） | |
| **401** | 未登录 / 令牌失效 | ⚠ 必须是 401，拦截器认这个码跳登录 |
| 40102 | 用户名或密码错误 | |
| 40103 | 验证码错误 | |
| 40104 | 用户已停用 | |
| 40301 | 权限不足 | |
| 40302 | 备机（只读）模式，禁止写入 | |
| 40303 | 系统对象受保护（admin / 系统组） | |
| 40304 | 记录被锁定 | |
| 40401 | 对象不存在 | |
| 40402 | 文件缺失 | |
| 40901 | 被引用中，不能删 | |
| 40902 | 冲突 | |
| 41301 | 上传超限 | |
| 41501 | 文件类型不对 | |
| 50001 | 服务器内部错误 | |
| 50002 | 转码失败 | |

## 4.2 分页

请求：`?pageNum=1&pageSize=20`（`internal/store.NewPager`）
响应：

```json
{ "list": [], "pageNum": 1, "pageSize": 20, "total": 137 }
```

## 4.3 排序：白名单，不拼字符串

```go
var orderWhitelist = map[string]string{"id": "usergroup.id", "name": "usergroup.name"}
order := store.OrderBy(orderWhitelist, q.OrderBy, q.Order, "usergroup.id DESC")
```

旧版这里写的是 `ORDER BY '$searchsequence' desc` —— 加了引号变成按常量排序，
排序下拉永远不生效（D-40）。白名单同时解决注入和这个缺陷。

## 4.4 条件拼装与 LIKE 转义

```go
cond := &store.Cond{}
if q.Keyword != "" {
    cond.Add(`usergroup.name LIKE ? ESCAPE '\\'`, store.EscapeLike(q.Keyword))
}
rows, err := db.QueryContext(ctx, "SELECT … FROM usergroup"+cond.Where()+" ORDER BY "+order+" LIMIT ? OFFSET ?", …)
```

`EscapeLike` 把 `% _ \` 转义掉 —— 否则用户搜一个 `%` 就把整表捞出来。

## 4.5 删除一律先给「影响面预览」

凡是会级联删掉别的东西的删除，都配一个 `GET …/delete-preview`：
先告诉用户「这一删会连带删掉 3 个用户、12 条任务、5 个目录」，确认后才真删。

现有的预览接口：媒体目录、媒体、用户、用户组、终端、任务、报警分区、作息方案…

## 4.6 事务边界

「主记录 + 附属清单」一律在**同一个事务**里全清再写：

```go
tx, _ := db.BeginTx(ctx, nil)
defer tx.Rollback()
// 1. 改主记录
// 2. 删旧的附属行（媒体清单 / 终端清单 / 字幕 …）
// 3. 插新的
// 4. 同步子任务（功放 / LED）
tx.Commit()
```

旧版没有事务，中途失败任务就变成一个没有终端的空壳。

## 4.7 「整条拆掉重建」策略

任务的媒体清单、终端清单、LED 字幕、子任务，改的时候**不做逐行 diff**，
直接删光重插。数据量都是几行到几十行，重建代价可以忽略，而 diff 的代码
是缺陷高发区。

⚠ 唯一的例外见 7.4.6：LED 屏绑定（`ledoftask`）在表单不提交时要**保留原值**。

# 5. 认证、权限与数据可见范围

## 5.1 登录

```
POST /api/login   {"username":"admin","password":"123456","captchaId":"…","captcha":"…"}
→ {"code":200,"data":{"access_token":"…","server":{"readonly":false},"user":{…}}}
```

- 口令在库里是 **MD5**（`book_admin.userpwd`），旧版就是这样，沿用。
- 令牌放在请求头 **`x-access-token`**。
- 验证码由 `auth.captcha_enabled` 控制；开关的**唯一权威在服务端**，
  `GET /api/captcha` 返回 `{"enabled":false}` 时前端连输入框都不显示。
- 会话存在内存里（`auth.Manager`），重启即失效。TTL 由 `auth.ttl` 定（默认 8h）。

例外：**媒体试听 / 下载 / 备份包下载**这三个路由额外接受 `?token=`，
因为 `<audio src>` 和 `window.open` 带不上自定义请求头。其它接口一律不开这个口子。

## 5.2 权限模型

三层，从粗到细：

### ① 是不是超级管理员

`u.ID == 1`（就是 admin 本人）。只有他能：管理别人的账号、看/清操作日志、改日志保留期。

### ② IsAdmin（管理员组）

`book_admin.usergroupid == 1`。对应旧版的 `$_SESSION['admin_id']=='administrator'`。
**IsAdmin 直通所有权限位**，并且能看到所有人的数据。

### ③ 13 个权限位

`usergroup` 表的 13 个列，每个对应界面上一个勾选项。判定入口：

```go
u.HasRight(auth.PrivTask)                    // service 层
a.authMgr.RequireRight(auth.PrivTask, h)     // 路由层
```

**读接口一律只要登录**（`req`），写接口按位卡。完整对照见附录 B。

### 只读（备机）模式

`serverbaseparam.model` 表示主/备机。备机模式下所有写操作回 `40302`。
唯一的例外是 `srv` 这道门（`RequireRightAllowReadOnly`）：服务器信息页
在备机上也得能看能改自己的参数。

### 未注册状态

`regGate`：服务器未注册时，登录被拦（`LoginBlocked`），但注册相关的三个接口开放 ——
否则用户永远进不去也就永远注册不了。注册成功后这几个口子自动关上。

## 5.3 前端怎么知道自己有什么权限

不靠前端猜，两个接口下发：

- **`GET /api/menu/list`** —— 菜单树。没权限的页面**根本不在树里**，前端也就没有那个路由。
- **`GET /api/auth/buttons`** —— 页内按钮的可用性：

```json
{ "task": {"add":true,"edit":true,"delete":true,"control":true,"copy":true,"folder":true},
  "led":  {"edit":false},
  "time": {"config":true,"sync":true} }
```

页面上的按钮按它置灰。**但服务端不依赖它** —— 每个写接口自己再卡一次。

## 5.4 数据可见范围（★ 最容易写错）

规则一句话：**管理员看到全部，其他人只看到自己建的；文件管理是唯一例外。**

| 模块 | 归属列 | 非管理员看到什么 |
|---|---|---|
| 任务（文件广播 / 四类 typed / 作息方案） | `task.task_user_id` | 只有自己建的 |
| 任务分组 | `taskfree.userid` | 只有自己的 |
| 终端分区 | `terminalgroup.userid` | 只有自己的 |
| 报警分区 | `alarmarea.userid` | 只有自己的 |
| 遥控任务 | 经 `shortcutkeytask.mediaid → task.task_user_id` | 只有自己的 |
| 用户 | —— | 只有 admin 能管别人 |
| **文件管理（媒体 + 媒体目录）** | —— | ⚠ **所有登录用户都能看到全部** |

文件管理这个例外是有意的：媒体库是共用素材库，别人传的音频也要能拿来做任务。
**写操作没有放松** —— 删媒体、改名/删目录仍然只有创建者本人或管理员能做。

实现方式统一成一个方法，例如：

```go
// internal/remote/remote.go
func visibleCond(u *auth.User, alias string) (string, []interface{}) {
    if u.IsAdmin { return "1=1", nil }
    return alias+".task_user_id = ?", []interface{}{u.ID}
}
```

⚠ 写接口除了可见范围，**还要再查一次归属**才能改/删 —— 列表看不见不等于接口调不动。

# 6. 操作日志（审计）

## 6.1 落库方式：中间件，不是逐个 handler

```go
// cmd/htweb/audit_mw.go
auditMux.HandleFunc(pattern, handler)   // 注册路由时统一包一层
```

- 只记 **POST / PUT / DELETE**，且只在**成功**时记。
- 「成功」的判定：`httpx.Fail` 也回 HTTP 200，所以不能看状态码 ——
  包一层 `ResponseWriter`，嗅探响应体开头 32 字节里有没有 `"code":200`。
- 操作名来自 `auditLabels`，键是**注册路由时的模式原文**（`PUT /api/users/{id}`），
  不是实际 URL。否则一个接口会散成无数种 operate 值，日志没法按操作聚合。
- 当前用户由 `authMgr.Resolve(token)` 反查。
  ⚠ **不能用 `auth.From(r.Context())`** —— 上下文里的用户只活在鉴权中间件
  创建的那个请求副本里，中间件在外层拿不到。

**落到 `log` 表**：`(username, operate, ip, time)`。

## 6.2 两个自己记日志的接口

| 接口 | 为什么不能交给中间件 |
|---|---|
| `POST /api/login` | 成功那一刻请求上下文里还没有会话，中间件取不到用户名 |
| `POST /api/logout` | handler 已经把会话作废了，中间件事后反查 token 查不到人（实测落出来是 `user='-'`） |

两个都在 handler 里、在合适的时刻自己写一行。登出那一行必须写在
`authMgr.Logout(token)` **之前**。

## 6.3 覆盖面要求

**所有增删改都要有日志。** 当前状态：124 条写路由 —— 114 条有 label，
10 条自记，0 条遗漏。加新写接口时，`auditLabels` 里必须同时加一行。

## 6.4 保留期与按天滚动

- 可选 **1 个月（默认）/ 3 个月 / 半年 / 1 年**。
- 设置存**文件**不存库（R1：不能建表也不能加列），路径 `config.logs.settings_file`，
  默认 `<备份目录上级>/logsettings.json`。
- 触发时机有两个：
  1. 界面上选完保留期点「确定」—— **存设置和滚动是同一个动作**，立刻清一次；
  2. 服务内一个自调度 goroutine，起来 1 分钟后跑一次，之后每 24h 一次。
- 清什么：`log` 表按 `time` 删；任务日志按文件名里的日期删 `logYYYY-MM-DD.html`。
  **今天的任务日志文件永不删**（BR-252）。
- 清理动作本身也记一行审计，且这行审计写在删除**之前**（用 `id < auditID` 把自己排除）。

**接口**

| 接口 | 权限 | 说明 |
|---|---|---|

旧库里没有对应的表，R1 又禁止建表。看过所有空表后的结论是：
`shortcutkeytask`、`ctrltask` 这些虽然是 0 行，但**都是后台 C 服务可能扫描的业务表** ——
往里塞界面状态，万一被当成真任务执行，就会在一所正在上课的学校里放出一段
没人预期的广播。这个风险不值得冒。

所以这三样落**一个 JSON 文件**（默认 `<备份目录同级>/dashboard.json`）：
不动数据库、不可能被 C 服务误读、重启后仍在、所有用户共享同一份。
**代价是它不在数据库备份包里** —— 备份还原那一节也记了这一点。

**紧急广播是四个固定槽位**（地震 `quake` / 疏散 `evacuate` / 警戒 `alert` / 消防 `fire`），
只能改「每个槽位绑哪条文件广播任务」，不能增删槽位。

**性能数据**读 `/proc`（Linux 专有，Windows 上编译不过，见 10.1）。

### 7.2.1 服务器信息 `/server` — 权限 `serverpriv`（备机也可用）

**表**：`serverbaseparam`（单行）、`serverconfig`

**接口**

| 接口 | 权限 | |
|---|---|---|
| `GET/PUT /api/server/params` | srv | 数据端口 / IP / 网关 / 端口 / UDP 端口 / 最大带宽 / 最大 HTTP 连接数 / 离线端口 / 主备模式 |

  探不通就把按钮置灰，`GET /api/server/version` 的 `reason` 说明缺什么。
  **动手之前先挡住**，不会出现「包解开了、容器没重建」这种半途状态。

### 7.2.2 时间设置 `/time`

**接口**：`GET /api/time`（当前时间/时区/运行时长/NTP/GPS/能力探测）、
`PUT /api/time/ntp`、`PUT /api/time/gps`（srv）、`PUT /api/time/clock`（srv）、
`POST /api/time/sync`（trm，给终端下发校时）、`GET /api/time/terminals`

**坑**
- **`serverbaseparam.adjusttime` 不是开关，是终端 ID**。0 = 不启用 GPS 校时。

  能力**每次请求现探**（`canSetClock` / `clockBlockReason`），装好 sudoers 后
  刷新页面按钮就亮，不用改代码也不用重启。
- 旧版那段 `date`/`time`/`setrtc` 是 DOS 语法 + 命令注入，**从来没生效过**（D-218）。

### 7.2.3 备份还原 `/backup` — **全部超管**

**接口**：`GET/POST/DELETE /api/backups`、`POST /api/backups/upload`、
`GET /api/backups/{name}/restore-precheck`、`POST /api/backups/restore`、
`GET /api/backups/{name}/download`（接受 `?token=`）

**★ 与旧版最根本的一处不同：备份包里不含任何 DDL。**
旧版备份是 `DROP TABLE` + `SHOW CREATE TABLE` 原文 + `INSERT`，
于是「恢复一个结构不一致的旧包」= **把线上表结构改成备份那一刻的样子** ——
这是 R1 红线上最大的实际风险。新版是**纯数据备份**：只有行数据，
恢复 = 现有表里 `DELETE` + `INSERT`，全程不碰表结构。

上传走 `MultipartReader` **流式**读，不用 `ParseMultipartForm`
（后者会把整个包先读进内存/临时文件，80MB 的包就是 80MB 内存峰值）。

恢复前先 `restore-precheck`：包里的表和现有表对不上就拒绝，并说清差在哪。

**③ 归属与分组**：`task.task_user_id → book_admin.id`（可见范围靠它），
`task.parentid → filetaskfree.id`（任务分组）。
任务分组树 `filetaskfree` 与媒体文件夹树 `filefolder` **毫无关系**（BR-161）。

**④ 一条任务的完整数据 = 四张表**

```
task              主行
mediaoftask       媒体清单（mediaid, taskid, sort）
terminaloftask    终端清单（taskid, terminalid, groupid, area）
+ 可能有子任务：   tasktype=9 功放子任务 / tasktype=30 LED 字幕子任务
```

保存时这几张全清再写（见 4.7），删除时一并删掉，`delete-preview` 里会说清连带删什么。

**⑤ `area` 是 8 位分区/通道掩码**，字符串 `"11111111"`，没勾过就用全通道默认值。

### 7.4.1 作息方案 `/bell` — 权限 `bellpriv`

**★ 作息方案不是一张表**：一个「方案」= `task` 表中**共享同一个 `task.info`** 的一组行，
每行是一次打铃（一节课）。方案本身没有独立主键行，属性由这组行聚合出来：

```
方案名   = task.info            （业务主键）
代表 ID  = MIN(taskid)          （只为兼容旧的按 taskid 传参）
条目数   = COUNT(*)
起止日期 = MIN(startdate) / MAX(enddate)
状态     = ROUND(AVG(projectstate))   ← 组内多数派
```

过滤条件**四项缺一不可**：`tasktype IN (1,15)`、`info` 非空串、`channel = 0`、`sec_task_id = 0`。
少一项就会把普通任务或功放子任务混进来。按「方案表 + 明细表」建模会与旧数据完全对不上（契约 C-38）。

**接口**：`GET /api/bell-plans`、`GET /api/bell-plans/detail`、
`POST/PUT/DELETE /api/bell-plans` + `delete-preview`、`POST /api/bell-plans/copy`、
`PUT /api/bell-plans/state`、`PUT /api/bell-plans/volume`、
条目：`POST /api/bell-plans/items`、`PUT /api/bell-plans/items/{id}`、
`PUT /api/bell-plans/items/schedule`、`DELETE /api/bell-plans/items`

**打铃条目也能挂 LED 字幕**，结构与文件广播那边完全一样（复用 `task.WriteLEDContent`）。

⚠ 旧版这一页有「备份方案 / 还原方案」两个按钮，点下去其实调 `backup_restore_form.php`，
**备份的是整个数据库加媒体文件**，跟「方案」没关系。新版**不放这两个按钮** ——
基础配置里已经有真正的备份还原页了。

### 7.4.6 led播放 `/led` — 权限 `telephonepriv`（= LED 权限）

**比其它三类多的东西**：一层任务目录（工具栏上有创建/修改/删除/复制目录）、

```
GET/POST /api/led/devices          PUT/DELETE /api/led/devices/{id}
```

**★ 字幕怎么存**（三处一致：文件广播的字幕子任务、文字语音的字幕子任务、独立 LED 任务）


但 `ledoftask` 是后台服务真正读的表，而子任务保存时是整条拆掉重建的，于是定了这个约定：

```
提交里 devices 缺省（JSON 里没这个键）= 保持库里原样   ← 界面走这条
提交里 devices 是空数组 []                = 真的清空
```

实现在 `task/ledsub.go` 与 `typedtask/led.go` 的 `keepLEDBinds()`，在拆之前把已有绑定读回入参。
**这是 4.7「整条拆掉重建」的唯一例外。**

### 7.4.7 启用管理 `/enable` — 权限 `ttspriv`

**表**：`enabletask (id, enstate, startdate, starttime, taskid, flag)`
一条记录 = 「到了某年某月某日某时某分某秒，把这一批任务按各自的安排启用或停用」。

**接口**：`GET /api/enable-plans`、`GET /api/enable-plans/{id}`、`POST/PUT/DELETE`、
`GET /api/enable-plans/tasks`

**★★ `enstate` 和 `taskid` 是两串并列的逗号分隔值**，**逐项对应**：

```
taskid  = "70007,70012,70020"
enstate = "0,1,0"              ← 0=启用 1=停用，与 taskid 一一对应
```

不是整行一个值 —— 列类型 `varchar(1024)` / `varchar(2048)` 正是为此。

**表结构上的两个坑（不改表，读写时绕开）**
- `taskid` 是 `varchar(2048)`：超长会被**静默截断**，截断处很可能落在某个 id 中间，
  后台就解析出一个别的任务。**保存前按字节数挡住**。
- `id` 是 `int(4) unsigned zerofill` 且只有 UNIQUE KEY 没有 PRIMARY KEY：
  查出来是 `"0001"` 这种补零字符串，**一律 CAST 成整数用**。

⚠ 可见范围：`enabletask` 没有 userid 列，收敛不了，所有人看到同一份（旧版也没有过滤）。

## 7.7 用户管理

### 7.7.1 用户 `/user/list` — 权限 `userpriv`，且**只有 admin 本人能管别人**

**表**：`book_admin`、`userterminal`（用户能操作哪些终端）

**接口**：`GET /api/users`、`GET /api/users/{id}`、`POST/PUT`、
`POST /api/users/{id}/enable`、`DELETE /api/users` + `delete-preview`、
`GET /api/users/wind-capacity`、`GET /api/users/terminal-options`

**规则**
- 口令 MD5。`admin`（id=1）可改不可删（BR-83 / BR-126）。
- 新建用户会连带建一个属于他的任务分组。
- 删用户 = 删掉他名下**所有数据**（任务、目录、媒体、分区…），所以 `delete-preview` 必须先看。
- 分控 ID（ctrlwind / subwind / camerawind）有容量上限，`wind-capacity` 给的就是余量；
  分配完会回 `ErrWindExhausted`。
- 服务器未注册时禁止新建/删除用户（`ErrNotRegistered`）。

### 7.7.2 用户组 `/user/group` — 权限 `userpriv`

**表**：`usergroup`

**接口**：`GET /api/usergroups`、`GET /api/usergroups/options`、`POST/PUT`、
`GET /api/usergroups/{id}/delete-preview`、`DELETE /api/usergroups/{id}`

**★ `level` 是两位复合值 10~109**

```
十位 = 组级别（1~9）        个位 = 组内任务优先级基数（0~9）
SplitLevel(level) → (level/10, level%10)      JoinLevel(g,p) → g*10+p
```

后台 C 服务按此解析任务优先级，**存储格式必须原样保持**（契约 C-28）。
界面上拆成两个控件录入，提交时合成。
**改了组级别要联动重算组内所有用户的任务优先级**（BR-97）——
旧版这里用的是 `if` 而不是循环，只处理了第一个用户（D-43）。

**★ 功能权限 13 项**，一一对应 `usergroup` 的 13 个列，界面按三组排列
（资源管理 / 任务管理 / 系统）。完整对照见附录 B。

**其它**
- 系统组（id=1）恒有全部权限：`UpdateGroup` 里卡死，列表与表单里也**恒按「全部勾上」显示**
  （库里某一位可能是 0，但组里的人走 IsAdmin 直通，照库显示反而像少了一项）。
- 删组 = 删掉组内全部用户及其名下所有数据，先看 `delete-preview`。
- 只改描述时**不校验组级别** —— 否则 level 为 1/3/5 的旧数据行连描述都改不了。

### 7.7.3 注册服务 `/user/register` — 权限 `serverpriv`

**接口**：`GET /api/register/status`（**公开**，登录页据此判断要不要跳过去）、
`GET /api/register`、`POST /api/register`、`POST /api/register/trial`

**规则**
- 三样外部依赖都从配置来，不写死：注册命令 `register.command`（默认 `registerserver`）、

- 注册命令取**标准输出第一行**判定 `success` / `failed` / `expired`。
- ⚠ **试用剩余天数是从 serial 文件算的，不是从库里的 `trystartdate`** ——
  旧版页面里读 `trystartdate` 的那段被整段注释掉了。文件形如：

  ```

  startdate=2016-08-31
  ```

  配置留空则页面算不出剩余天数，**如实说明，不猜一个日期**。
- 未注册时 `regGate` 放开这三个接口（否则用户永远进不去也就注册不了），注册成功后自动关上。
- 旧版这一页没有菜单入口，只能从登录页进，且页面与两个动作**完全不校验会话**。

**页面**：两个标签 —— 操作日志（库里的 `log` 表）、任务日志（磁盘上的 html 文件）。
工具栏：`清理日志 | 日志保留 [下拉] [确定]`。

`GET/PUT /api/logs/retention`、
`GET /api/task-logs/files`、`GET /api/task-logs/files/{name}`、

# 8. 前端约定

## 8.1 路由与菜单：**后端下发，前端不写死**

登录后拿 `GET /api/menu/list`，动态注册路由。没权限的页面**根本不在树里**，
地址栏手敲也进不去（前端没有那条路由）。
页内按钮的可用性另由 `GET /api/auth/buttons` 下发（见 5.3）。

菜单项的 `component` 字段就是 `src/views/` 下的路径，例如
`/typed/tts/index` → `src/views/typed/tts/index.vue`。

## 8.2 http 封装（`src/api/index.ts`）

- `baseURL` **留空**。接口路径里的 `/api` 前缀已经写在各 `api/modules/*.ts` 里
  （如 `/api/login`），baseURL 再补一次会变成 `/api/api/login`，
  只能靠代理剥掉一层来抵消 —— 前缀在三个地方各写一遍，极易改错。
- 请求拦截器加 `x-access-token`；响应拦截器见到 `code === 401` 跳登录。

**⚠ 全站最容易踩的一个坑：`http.delete` 的第二个参数是 query，不是 body。**

```ts
http.delete(url, { ids })                  // ❌ 变成 ?ids=1&ids=2，后端读 body 得到 EOF
http.delete(url, {}, { data: { ids } })    // ✅ 放进请求体
```

后端删除接口一律从 JSON body 读 `ids`。写错的表现是
`40001 请求参数格式错误: EOF` —— 上一轮一口气查出 8 个这样的接口。

## 8.3 ProTable

全站表格都用 `components/ProTable`，`columns` 配置驱动。要点：

- `requestApi` 传接口函数，分页/排序/搜索参数由它自己拼。
- **`tableKey`**：列设置存 localStorage 时用的表标识，默认取当前路由 path。
  **一个页面里有两张以上表格时必须显式传**，否则它们共用同一份列设置。

## 8.4 界面配置存本地

- **列设置**（显示/排序两个开关）→ `localStorage`，键 `htweb:cols:<tableKey>`，
  只存**用户改过的值**，不存列定义 —— 后端加列/改列名都不会被旧记录带偏
  （记录里没有的列走代码默认值，代码里删掉的列套用时忽略）。
  实现见 `utils/tablePrefs.ts`，所有读写都包了 try/catch（隐私模式下 localStorage 会直接抛）。
- **布局/主题/侧边栏**走 pinia 的 `geeker-global`，本来就落 localStorage，退出登录也不清。

## 8.5 公共组件

| 组件 | 用途 |
|---|---|
| `ProTable` | 全站表格 |
| `TerminalTree` | 终端树，带分区分组、逐台勾通道掩码（`area`） |
| `MediaTree` | 媒体库→音频文件两级树，**懒加载**；回填时要把已选媒体的名字一并给它，否则只显示 id |
| `HmsInput` | 时:分:秒输入 |
| `SearchForm` / `SelectFilter` / `TreeFilter` | 搜索区 |

## 8.6 Element Plus 的两个已知坑

- **删除预览弹窗关掉后 DOM 还在**：写自动化断言时统计 `.el-table__row` 会把
  隐藏弹窗里的行也算进去，要限定到可见容器（`.table-box .el-table__row:visible`）。
- `el-select` 的内层 input 用 `inputValue()` 取不到值。

# 9. 与后台 C 服务的通知协议

**UDP**，发往 `notify.host` : `serverbaseparam.webport`（`notify.port = 0` 时运行时读库）。
发失败**只记日志不回滚**（库已经改完了，回滚更糟）。

**★ 报文格式照抄旧版 `do.php` 的实际调用点，不是照手册。** 三种形态混用会让后台解析失败：

```
task?state=3&id=X                启动（无 type）
task?state=2&id=X&type=2         停止 / 暂停 / 恢复 / 删除（带 type）
task?state=4&id=X&volume=V       新增 / 修改（带 volume）
```

**任务类 state**

| 值 | 含义 | 值 | 含义 |
|---|---|---|---|
| 2 | 停止（`&type=2`） | 6 | 删除（`&type=2`） |
| 3 | 启动（无 type） | 15 | 离线数据有变更（`id` 恒为 0） |
| 4 | 新增（`&volume=`） | 22 | 暂停（`&type=2`） |
| 5 | 修改（`&volume=`） | 23 | 恢复（`&type=2`） |

⚠ 手册说停止写 `state=0`，**旧代码实际写的是 2**；暂停/恢复的 22/23 手册根本没提；
新增/修改要带 `&volume=` 手册也没提。这些差异都会让后台收不到或误解通知。

**终端类 state**

| 值 | 含义 | 值 | 含义 |
|---|---|---|---|
| 0 | 停止终端 | 7 | 下发密码（id 用 `{}` 包裹，带 `&pwd=`） |
| 1 | 启动终端 | 13 / 14 | 开始 / 停止录音 |
| 2 | 终端已删除 | 27 | 线路检测（id 用 `{}` 包裹） |
| 3 / 4 | 对讲开 / 关（带 `&speech=`） | 30 | 同步时间 |
| 5 | 音量（带 `&volume=`） | 32 | 删除任务终端 |

⚠ 粒度必须原样保留：手册说「逐个终端发」，但录音、线路检测、密码这几条
**旧代码是把整串 ID 一次发出去的**。

**其它报文**

```
project?state=<1启用|0停用>&name=<方案名>      作息方案启停
file?state=<n>&id=<folderId>                  媒体目录变更
server?state=1                                服务器重启
```

# 10. 构建、部署与本地测试

## 10.1 构建

```bash
# 后端（交叉编译，目标机器不需要装 Go）
cd server
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -trimpath -ldflags='-s -w' -o /tmp/htweb ./cmd/htweb

# 前端
cd web && pnpm install && pnpm build:pro     # 产物 web/dist
```

⚠ **Windows 上编译不过**：`internal/dashboard/perf.go` 用了 Unix 专有的
`syscall.Statfs`（取磁盘占用）。实测 `linux ✓ / darwin ✓ / windows ✗`。Windows 用 WSL2。

## 10.2 部署到真服务器

`deploy/install.sh` 一把装完（systemd 单元、受限的免密 sudo 规则、前端目录、
上一版前端留在 `html/htweb.prev` 可回滚）。详见 `deploy/README.md`。

两条容易漏的：
- 数据库账号**只给 DML，不给任何 DDL**。
- systemd 单元里**不能有 `NoNewPrivileges=true`** —— 它会禁掉整个 setuid 提权路径，
  而 sudo 正是 setuid 程序。加了之后 sudoers 写得再对，`sudo -n` 也一律失败，
  「设置服务器时间」「版本切换」会静静地变灰。真正的安全边界在 sudoers 那一侧。

## 10.3 本地跑

见《本地测试运行.md》。一句话：导 `audioserver-demo.sql`、写个 config.yaml、
`go build` + `pnpm build:pro`、跑起来，`admin / 123456`。

# 11. 怎么验收

上一轮全量验收的做法（见《模块测试与ok112对照-验收记录》），照这个来：

1. **全站扫描**：逐页 `goto`，收集 `pageerror` / `console.error` / 非 200 的 `/api` 响应。
   27 个页面应当全部干净。
2. **界面上的增删改往返**：每个模块在真界面上建一条 → 查库核对 → 改一次 → 再核对 →
   删掉 → 确认连带数据也没了、没有孤儿行。
3. **权限矩阵**：至少三个身份（admin / 有部分权限的操作员 / 只读查看），
   核对菜单可见性、按钮置灰、写接口是不是回 40301、可见范围对不对。
4. **接口层往返**：树/掩码这类界面上不好点的，直接打接口，重点核对级联写入
   （`task` / `mediaoftask` / `terminaloftask` / 子任务）。
5. **收尾**：测试数据全删干净，核对没有孤儿行。

自动化用 Playwright + Chromium 起浏览器跑，断言注意 8.6 那两个坑。

# 附录 B · 权限位速查

`usergroup` 的 13 列。**列名与含义对不上，别按字面猜**（R2）。

| 界面上的名字 | 列 | 管住什么 |
|---|---|---|
| **资源管理** | | |
| 终端管理 | `terminalpriv` | 终端管理页全部写操作（参数/音量/启停/密码/开关/快捷键/寻呼组/快捷任务/终端替换/删除）；云广播→音乐传输；时间设置→下发校时 |
| 分区管理 | `terminalgrouppriv` | 终端分区；噪声检测→噪声设备、声场分区 |
| 报警管理 | `alarmgrouppriv` | 报警分区、报警映射 |
| 文件管理 | `mediapriv` | 上传媒体、删除媒体、清空目录内媒体 |
| 文件夹管理 | `folderpriv` | 新建 / 改名 / 删除媒体文件夹 |
| **任务管理** | | |
| 文件广播 | `taskpriv` | 文件广播的增删改与启停、任务分组 |
| 作息方案 | `bellpriv` | 作息方案与打铃条目；节假日管理 |
| 终端功放 | `powerplay` | 终端功放任务 |
| 采播管理 | `admpriv` | 采播任务 |
| 文字语音 | `ttspriv` | 文字语音任务；启用管理 |
| **led播放** | **`telephonepriv`** | led播放 任务；LED 任务目录；LED 屏设备。⚠ 旧版这列是「电话广播」，新版改挂 LED |
| **系统** | | |
| 遥控管理 | `serverpriv` | 遥控任务；云广播→任务传送；基础配置→服务器信息、时间设置里的 NTP/GPS；用户管理→注册服务 |
| 用户管理 | `userpriv` | 用户与用户组 |

**超出 13 位之外的两道门**
- **超级管理员**（`book_admin.id == 1`）：日志、日志保留期、备份还原、重启、恢复出厂、
  看板三块配置、离线全部清除。
- **IsAdmin**（`usergroupid == 1`）：直通所有权限位 + 看得到所有人的数据。
